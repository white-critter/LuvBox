# XlikeSaver 1.10.0

내 X(트위터) 계정에서 Like한 게시물의 사진·동영상·움직이는 GIF를 저장하는 Windows 프로그램입니다.

## 실행하기

`release/XlikeSaver-1.10.0/XlikeSaver-1.10.0.exe`를 더블클릭하세요. 같은 폴더의 `_internal`(내장 Python·ExifTool·FFmpeg·글꼴)과 함께 실행되므로 **폴더째** 보관하거나 옮기세요. 예전처럼 실행할 때마다 내부 도구를 임시 폴더에 풀지 않아, 앱 시작과 저장 시작(작업 프로세스 실행)이 매번 약 4초 빨라졌습니다. 폴더 이름에 버전이 붙어 있어 이전 버전을 실행 중이어도 새 버전을 만들거나 받을 수 있습니다. Python이나 IDE 설치는 필요 없습니다.

배포용 `release/XlikeSaver-1.10.0.zip`에는 앱 폴더, 짧은 사용 안내, 소스와 라이선스가 들어 있습니다. 압축을 풀고 폴더 안의 exe를 실행하세요.

## 사용하기

1. **내 X 아이디**와 **저장 폴더**를 입력합니다.
2. **로그인 연결**을 눌러 열린 창의 안내대로 인증 토큰을 붙여 넣습니다(처음 한 번). `cookies.txt` 파일로도 연결할 수 있습니다.
3. 필요하면 **옵션 변경**에서 폴더 정리·동영상·확인 범위를 바꾸고 **저장 시작**을 누릅니다.
4. 지금까지 저장한 파일과 실행 기록은 **기록 · 통계**에서 봅니다. 파일을 고르고 **파일 열기**·**트윗 열기**를 누르면 됩니다.

메인 화면에는 진행 상태와 '새로 저장 / 이미 저장돼 있음 / 용량 초과' 숫자가 크게 나오고, 자세한 진행 정보는 **자세히**를 켜면 보입니다. 진행 막대는 현재 파일의 진행률을 부드럽게 표시하며, 전체 목록 조회·GIF 변환처럼 완료율을 알 수 없는 작업에는 움직이는 표시를 사용합니다. 작업 기록에는 저장·이미 저장·용량 초과 파일마다 파일명과 작성자·트윗 게시일이 한 줄씩 표시됩니다. 처음 쓰는 사람을 위한 설명은 **사용 방법**에 있습니다.

토큰과 쿠키는 로그인 인증정보입니다. 다른 사람에게 보내지 마세요. 인증 토큰은 현재 Windows 사용자만 읽을 수 있도록 암호화해 보관하며, 쿠키 파일은 직접 안전하게 보관해야 합니다.

상단의 **다크 테마 / 라이트 테마** 버튼으로 언제든 화면을 바꿀 수 있고 선택은 다음 실행에도 유지됩니다. 창 제목 표시줄과 확인·안내 창도 같은 테마를 따릅니다(Windows 10 20H1 이상). 폴더·파일 선택 창은 Windows 기본 창이라 Windows 설정의 앱 모드를 따릅니다. 화면은 둥근 카드·버튼과 스위치로 통일하고, Pretendard 글꼴을 포함해 별도 설치 없이 적용합니다. 작은 화면에서는 메인·기록 창을 스크롤해 아래 기능까지 볼 수 있고, 설명은 창 너비에 맞춰 줄바꿈합니다. 로그인 상태의 **연결 정보 저장됨**은 토큰 보관 상태이며, 실제 유효성은 저장을 시작할 때 확인합니다. 옵션의 시험 저장은 한 번 실행한 뒤 자동으로 꺼집니다.

## 저장 옵션 (옵션 변경)

기본값은 **구분 없이 저장**, **계정별 폴더 끔**, **새 Like만 빠르게 확인**입니다. 파일을 선택한 저장 경로에 바로 넣습니다.

| 설정 | 예시 |
| --- | --- |
| 구분 없이 저장 | `D:/X사진/게시물ID_1.jpg` |
| 작성자별 폴더 | `D:/X사진/작성자/게시물ID_1.jpg` |
| 저장일별 폴더 | `D:/X사진/2026-10-04/게시물ID_1.jpg` |
| 계정별 폴더 켬 | 위 경로 앞에 `내아이디/` 추가 |

저장일은 파일 저장이 끝난 날의 한국 날짜입니다. 계정별 폴더 옵션을 바꿔도 기존 파일은 제자리에 두고 건너뛰며, 새 파일부터 바뀐 위치에 저장합니다. 작성자별·저장일별·구분 없이 정리 방식을 바꾸면 방식별 기록을 사용하므로 별도 복사본이 생길 수 있습니다.

사진은 항상 저장 대상이며 한 게시물의 여러 사진도 모두 저장합니다. 동영상은 제공된 직접 MP4 중 최고 비트레이트로 저장합니다. 움직이는 GIF 트윗은 옵션의 **움직이는 GIF 저장 형식**에 따라 저장합니다. 기본값 **GIF로 바꿔 저장**은 제공된 MP4를 PC에서 GIF로 변환하고, **원본 MP4 그대로 저장**은 변환 없이 MP4로 둡니다. GIF는 색상이 256개로 줄고 보통 MP4보다 몇 배 큽니다. 용량이 걱정되면 **GIF 크기**를 **최대 720px · 초당 15장** 또는 **최대 480px · 초당 12장**으로 고르세요. 가로·세로 중 긴 쪽을 그 크기 안에 맞추고(작은 영상은 키우지 않음) 초당 장면 수를 줄이며, 재생 길이는 원본과 같습니다. GIF 변환에는 추가 X 요청이 없습니다. GIF 변환 중 중단하면 완료된 MP4 임시 파일을 남겨 다음 실행에서 로컬 변환부터 재시도합니다. 변환에 실패하거나 변환한 GIF가 용량 제한을 넘으면 그 파일은 원본 MP4로 저장하고 다음 파일로 넘어갑니다. 받은 MP4 자체가 용량 제한을 넘으면 건너뜁니다. 동영상·GIF는 개별 파일 용량을 제한할 수 있으며 기본 200MiB, 0은 제한 없음입니다. 직접 MP4가 없는 HLS 영상은 지원하지 않습니다.

새로 받은 파일 안에 원본 트윗 주소와 작성자 **@아이디·프로필 주소**를 기록합니다. 숫자 사용자 ID가 제공되면 함께 저장합니다. 이미 저장된 파일은 저장 실행 중에 작성자만 추가하려고 다시 쓰지 않습니다. 작성자 정보는 기록 DB에만 반영하고, 실행이 끝나면 처리할 파일 수를 알려 줍니다. 파일에 넣으려면 **기록 · 통계 → 출처·작성자 기록**을 실행하세요. 이 작업은 파일을 다시 쓰므로 OneDrive 같은 동기화 폴더에서는 파일이 다시 업로드될 수 있습니다. 출처 기록에 실패했던 기존 파일은 저장 실행 중에도 다시 시도합니다. 작성자 정보가 없거나 X 아이디 형식이 아닌 값(예: 예전 폴더 이름)은 작성자 없이 출처만 기록합니다. 작성자가 아이디를 바꾸면 이 앱이 예전에 기록한 작성자 항목을 새 값으로 바꾸고, 다른 프로그램이 넣은 작성자 정보는 그대로 둡니다. 이 작업은 X에 요청을 보내거나 미디어를 재인코딩하지 않으며, 작업 동안 ExifTool 하나를 띄워 두고 재사용합니다. 기록 화면의 파일 상세에서 작성자와 기록 상태를 확인할 수 있습니다.

작성자 아이디는 대소문자만 바뀌어도 기존 파일 처리에 반영합니다. 앱이 직접 추가한 작성자 항목만 교체하며, 이전 버전 파일처럼 누가 넣은 값인지 구분할 수 없으면 기존 값을 보존합니다.

## 확인 범위: 새 Like만 빠르게 / 전체

X의 Like 목록은 최근에 누른 Like부터 나옵니다. **새 Like만 빠르게 확인**은 이미 저장한 파일이 100개 연속으로 나오면 이전 확인 지점에 도달한 것으로 보고 멈춥니다. Like가 수천 개여도 새 항목만 확인하므로 목록 요청이 크게 줄어듭니다.

이 방식은 직전 실행이 목록 끝까지 정상 종료됐을 때만 안전합니다. 그래서 다음 경우에는 자동으로 **전체 목록**을 확인하고, 그다음 실행부터 다시 빠르게 확인합니다.

- 첫 실행, 또는 이 정리 방식(작성자별·저장일별·구분 없이)의 첫 실행
- 직전 실행이 중단·오류·시험 저장(20개)으로 끝났거나 비정상 종료된 경우
- 동영상·GIF 포함 여부나 영상 용량 제한을 바꾼 경우

예전 Like를 다시 훑고 싶으면 **전체 목록 다시 확인**을 고르세요.

## 정기적으로 자동 저장하기

메인 화면의 **자동 저장 → 예약 설정**에서 실행 시각을 고르고 **예약 켜기**를 누르면, Windows 작업 스케줄러에 ‘XlikeSaver 자동 저장’이 등록되어 매일 그 시각에 새 Like만 저장합니다. 메인 화면에는 켜짐/꺼짐과 다음 실행 시각, 마지막 자동 저장 결과가 표시됩니다. **예약 끄기**로 해제합니다.

- 예약 실행은 마지막으로 저장을 시작할 때의 설정(아이디·저장 경로·정리 방식·미디어 옵션)을 사용하며 창 없이 실행됩니다. 예약을 켤 때 지금 화면의 설정도 저장합니다.
- PC가 꺼져 있거나 잠자기 상태라 시각을 놓치면 다음에 켰을 때 바로 실행합니다. 배터리로 쓰는 중에도 실행합니다. Windows에 로그인해 있을 때만 실행됩니다.
- 자동 저장이 실패하면(로그인 만료·요청 제한 등) 바로 알림 창이 뜨고, 다음에 앱을 열 때도 상단에 알려 줍니다. 앱에서 저장 중이라 겹쳐 실행하지 않은 경우는 실패로 알리지 않습니다.
- 결과는 `%LOCALAPPDATA%/XlikeSaver/logs/`에 남고 최근 30개만 보관합니다. **예약 설정 → 실행 기록**으로 열 수 있습니다.
- 새 버전을 처음 열면, 예약이 이전 버전 exe로 등록돼 있을 때 이 버전으로 바꿀지 한 번 묻습니다. 예전 방식(명령 프롬프트)으로 등록한 예약도 **예약 갱신**을 누르면 위 설정으로 바뀝니다.
- cookies.txt 연결은 파일 경로를 저장하지 않으므로 예약 실행을 지원하지 않습니다.
- 너무 자주 예약하지 마세요. 요청 간격을 지켜도 계정 제한 위험은 남습니다.

## 기록과 다시 시작

기록 DB는 `저장 경로/.xlikesaver/계정명/`에 모아 보관합니다. 사진과 영상은 이 폴더 밖에 저장됩니다. **기록 위치**에서 확인할 수 있습니다. 인증 연결과 설정은 `%LOCALAPPDATA%/XlikeSaver/`에 별도로 보관합니다.

기존 `저장 경로/계정명/`의 기록은 처음 사용할 때 복사해 이어서 사용합니다. 이전 사진과 DB는 그대로 보존하며, 예전에 받은 파일도 계속 건너뜁니다. 기록을 유지하려면 저장 경로와 `.xlikesaver` 폴더를 함께 보관하세요. 앱에서 저장 경로를 바꾸면 해당 계정의 기록을 새 `.xlikesaver/계정명/` 폴더로 자동 복사해 이어서 사용합니다. 새 위치에 기록이 있어도 합쳐서 유지합니다. 기존 사진·영상과 원본 DB는 그대로 두며, 새 파일만 새 위치에 저장합니다. 직접 입력한 경로는 **Enter 또는 저장 시작·기록 보기**를 누를 때 적용됩니다. 이전에 실패하면 원래 저장 경로를 유지합니다.

이전 폴더가 연결되지 않았으면 새 폴더에서 시작할지 확인합니다. 새로 시작하면 이전 기록을 가져오지 못해 중복 저장될 수 있습니다. 이전 폴더를 다시 연결해 앱에서 선택하면 양쪽 기록을 합칩니다. 이후 원하는 새 폴더를 선택하면 합친 기록을 가져옵니다.

중단·오류 이후에도 완료 기록은 유지합니다. 다음 실행은 목록 앞에서 다시 확인하며 정확한 페이지 위치에서 이어지는 방식은 아닙니다. 삭제되거나 접근할 수 없는 게시물과 X가 제공하지 않는 오래된 목록은 받을 수 없습니다.

X는 Like한 시각을 알려 주지 않습니다. 대신 저장 실행이 Like 목록(최근 Like부터)을 훑을 때 **Like 순서**와 **처음 발견한 시각**을 기록합니다. 기록 화면의 **정렬 → Like한 순**으로 Like한 순서대로 보고, 파일 상세의 **Like한 시기**에서 "2026-10-05 09:00 ~ 2026-10-06 09:00 사이"처럼 확인합니다. 새로 누른 Like는 직전에 끝까지 확인한 실행과 이번 실행 사이로 표시되고, 그보다 오래된 Like는 "~ 이전"으로만 표시됩니다. 매일 자동 저장을 켜 두면 새 Like의 시기가 하루 단위로 기록됩니다. 1.8.0 이전에 저장한 기록은 다음 실행에서 다시 훑은 부분부터 순서가 붙으므로, 모두에 붙이려면 **전체 목록 다시 확인**을 한 번 실행하세요.

**정렬**은 저장한 순·Like한 순·게시일 최신순·게시일 오래된 순 중에서 고르고, **기간**에서 게시일 또는 저장일의 시작·끝 날짜(예: 2026-10-01)를 입력해 거를 수 있습니다. 한쪽만 입력해도 되며 **기간 지우기**로 해제합니다. CSV에는 Like한 시기(liked_after·liked_before)와 트윗 본문·해시태그도 함께 내보냅니다.

저장 실행은 Like한 트윗의 **본문과 해시태그**도 기록합니다(X가 이미 보내 주는 내용이라 요청이 늘지 않습니다). 검색칸에 단어나 `#해시태그`를 넣으면 작성자·파일명·트윗 번호와 함께 본문에서도 찾고, 파일 상세의 **내용**에서 본문을 봅니다. 1.9.0 이전에 저장한 기록의 본문은 다음 실행에서 다시 훑은 부분부터 채워지므로, 모두 채우려면 **전체 목록 다시 확인**을 한 번 실행하세요.

파일을 고르고 **이 작성자만 보기**를 누르면 그 작성자의 파일만 보입니다(대소문자 무시, 정확히 같은 아이디만). 검색칸 옆의 **@아이디 만 보는 중 ✕**를 누르면 다시 전체를 봅니다. 검색칸 오른쪽의 **표 / 모아보기**로 현재 페이지를 섬네일 격자로 볼 수 있습니다. 섬네일은 PC의 파일로 만들며 X에 요청하지 않습니다. 섬네일을 누르면 상세와 미리보기가 바뀌고, 두 번 누르면 파일을 엽니다. 모아보기에서는 Page Up/Down으로 바로 페이지를 넘깁니다.

**통계** 탭에는 많이 저장한 작성자 순위(상위 20명)와 달마다 몇 개인지 보여 주는 막대그래프가 있습니다. 그래프는 **저장한 달 / 게시된 달 / Like한 달** 중에서 고르고, 막대에 마우스를 올리면 정확한 개수가 보입니다. 3년이 넘는 기간은 해마다 묶습니다. **Like한 달**은 기간을 아는 새 Like(자동 저장을 켜 둔 뒤 새로 누른 Like)만 셉니다. 순위에서 작성자를 두 번 누르거나 **이 작성자 파일 보기**를 누르면 그 작성자의 파일 목록으로 이동합니다. 통계의 가장 오래된 게시일은 저장 기록 중 최솟값이며, 그 날짜까지 모든 Like를 빠짐없이 저장했다는 뜻은 아닙니다. **자세히**의 퍼센트는 현재 파일의 진행률입니다. **기록 · 통계**는 지금까지의 기록을 바로 보여 주고, 저장 폴더의 파일은 뒤에서 다시 확인해 반영합니다. 저장 작업 중에는 폴더 재확인을 건너뛰며, 작업이 끝난 뒤 **새로고침**을 누르면 다시 확인합니다.

파일 목록과 실행 기록은 페이지로 나눠 봅니다. **페이지 번호 버튼**을 누르거나 **처음·이전·다음·마지막**으로 이동합니다. 멀리 이동하려면 페이지 번호를 입력하고 **이동**을 누릅니다. 목록에서 **Ctrl+Page Up/Down**으로 이전·다음, **Ctrl+Home/End**로 처음·마지막 페이지로 이동합니다. Ctrl 없이 누르면 목록 안에서 스크롤합니다. **50·100·200개씩** 표시할 수 있고, 검색 결과에도 총수와 전체 페이지가 표시됩니다. 검색하거나 표시 개수를 바꾸면 첫 페이지로 돌아갑니다. CSV는 페이지와 관계없이 전체 기록을 내보냅니다.

기록이 갱신돼도 선택한 파일·실행을 유지하며, 검색 결과에서 사라지면 선택을 해제합니다. 불러오는 동안 페이지 이동은 잠시 막습니다. 작성자 검색은 `아이디`와 `@아이디` 모두 가능하며, 긴 출처·경로는 상세 영역에서 스크롤하고 복사할 수 있습니다. 파일을 클릭하면 로컬 사진·GIF·동영상의 첫 장면을 썸네일로 확인합니다. 미리보기를 위해 X에 요청하지 않습니다. 창이 좁으면 파일명이 잘리지 않도록 **저장한 때** 열을 숨기고, 이 값은 아래 상세에 표시합니다.

예전에 MP4로 받은 움직이는 GIF는 **기록 · 통계 → MP4 GIF를 GIF로**로 한꺼번에 바꿀 수 있습니다. 현재 **GIF 크기** 옵션과 영상 용량 제한을 따르고, 파일 안에 출처·작성자를 다시 기록하며, 파일 수정 시각은 원본과 같게 둡니다. 바꾼 파일의 원본 MP4는 Windows 휴지통으로 옮기므로 되돌릴 수 있습니다. 휴지통이 없는 위치(네트워크 드라이브 등)의 파일, 같은 이름의 GIF가 이미 있는 파일, 변환 결과가 용량 제한을 넘는 파일은 MP4로 둡니다. 중간에 멈출 수 있고 X에 요청하지 않습니다. 동기화 폴더라면 새 GIF가 다시 올라갑니다.

## 기록 DB 손상과 복구

기록·통계 DB(`저장 경로/.xlikesaver/계정명/.xlikesaver-history.sqlite3`)가 손상되면 기록 화면에 **기록 DB 파일이 손상되어 읽을 수 없습니다**가 표시되고, 위쪽의 **기록 복구**를 누르면 고칩니다. 손상된 원본은 먼저 `%LOCALAPPDATA%/XlikeSaver/backups/계정명-날짜-damaged/`에 그대로 보관하고, 파일 기록을 손상된 페이지에서 직접 읽어 살린 뒤(최근 백업에만 있는 기록도 더함) 검사를 통과한 새 DB로 바꿉니다. 이어서 저장 폴더의 파일을 다시 확인해 빠진 기록을 채웁니다. 사진·영상 파일과 중복 방지 기록(archive)은 건드리지 않습니다. 손상된 상태에서 저장을 시작하면 같은 안내와 함께 멈춥니다.

저장 실행이 끝날 때마다 검사를 통과한 기록 DB를 이 PC의 `%LOCALAPPDATA%/XlikeSaver/backups/catalog/계정명/`에 하루 하나씩, 최근 7일 치 보관합니다. 손상된 DB는 백업으로 덮어쓰지 않습니다.

Google Drive·OneDrive 같은 동기화 폴더는 DB 파일과 보조 파일(-wal, -shm)을 서로 다른 시점에 올리거나 내려받을 수 있어, 앱이 쓰는 중인 SQLite DB가 손상될 수 있습니다. 같은 저장 폴더를 다른 PC에서 동시에 쓰지 말고, 가능하면 저장 폴더를 동기화하지 않는 위치로 두거나 동기화를 잠시 멈춘 상태에서 저장하세요.

## 제한이나 오류가 나면

요청 제한·인증 오류·서버 오류가 나면 자동 재시도하지 않고 멈춥니다. 완료한 파일은 보존합니다. 화면의 안내를 확인한 뒤 수동으로 다시 시작하세요. `429`는 안내한 시각까지 기다리고, 계정 잠금은 X에서 직접 확인합니다. 디스크 부족이나 쓰기 권한 오류는 해당 문제를 해결한 뒤 재시작합니다. 국가 제한·연령 제한·볼 수 없는 미디어처럼 게시물마다 생기는 상황은 안내만 남기고 건너뜁니다.

이 앱은 X 웹사이트의 비공식 API를 사용합니다. 요청 간격과 제한 시 중단 기능은 계정 제한을 예방한다고 보장하지 않습니다. 자세한 처리 방식은 [개발·문제 해결 안내](docs/development.md)를 참고하세요.

## 코드 수정·빌드

VS Code에서 이 폴더 또는 `XlikeSaver.code-workspace`를 열고 `.venv/Scripts/python.exe`를 선택합니다. **XlikeSaver 앱** 실행 구성으로 F5를 누르거나 `run.bat`를 실행하세요.

```powershell
.\setup.ps1
.\run.bat
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\build.ps1
```

빌드는 `release/XlikeSaver-<버전>/` 앱 폴더(exe와 `_internal`)와 소스·라이선스를 포함한 `release/XlikeSaver-<버전>.zip`, 체크섬 `release/SHA256-<버전>.txt`를 만듭니다. 버전은 `xlikesaver/__init__.py`에서 읽습니다. 같은 버전의 exe가 실행 중이면 덮어쓰지 않고 안내 후 멈춥니다. `build/`는 중간 작업 폴더이며 배포하지 않습니다. 사용자 토큰·쿠키·사진·DB는 배포본에 포함하지 않습니다. 재배포할 때는 ZIP의 소스와 라이선스도 함께 제공하세요.
