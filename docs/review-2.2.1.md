# 2.2.1 전체 검토와 안정화

검토·수정일: 2026-10-07. 기준은 커밋되지 않은 2.1.1·2.2.0 작업분입니다. 2.2.0 삭제 기능을 검토한 뒤 앱 코드 전체(약 12,700줄)를 모듈별로 다시 읽고, 의심 지점은 임시 자료로 재현한 것만 고쳤습니다.

## 보완

| 문제 | 재현 | 수정 후 동작 |
| --- | --- | --- |
| 저장 중 진행 표시가 그 실행이 끝날 때까지 멈춤 | 작업 프로세스가 한글 글자 중간까지 쓴 순간 화면이 이벤트 파일을 읽으면 `UnicodeDecodeError`. 이후 이벤트를 모두 잃고 “작업 프로세스를 실행하지 못했습니다”만 표시 | 이벤트 파일을 바이트로 읽고 완성된 줄만 해석 |
| 저장·삭제가 기록을 쓰는 동안 라이브러리 파일 열기·미리보기가 멈춤 | DB를 열 때마다 맞는 행이 없어도 UPDATE가 쓰기 잠금을 기다림. 다른 연결이 2초 쓰는 동안 2.08초 대기, 5초 넘게 쓰면 열기 실패 | 옛 행이 있을 때만 UPDATE. 평소 열기는 읽기만 하며 기다리지 않음 |
| 기록 복구 중 앱을 닫으면 복구가 중간에 끊김 | 종료 대기 대상에 복구가 빠져 있음. 원본은 백업되지만 기록 폴더에 임시 파일이 남으면 이후 저장 폴더 변경이 막힐 수 있음 | 복구를 마친 뒤 창·앱을 닫고, 그동안 저장·기록 이전을 시작하지 않음 |
| 삭제 기록이 쌓이면 라이브러리 페이지가 느려짐 | 기록 12만·삭제 1만 개에서 페이지마다 12.9초 | 삭제 기록 색인으로 0.3초 |
| 대량 삭제가 느림 | 기록 12만 개에서 파일당 0.6초(1,000개면 약 10분) | 같은 트윗의 기록만 조회해 파일당 약 0.01ms |
| OneDrive·Dropbox 파일을 링크로 오인해 삭제 거부 가능 | 클라우드 자리표시자는 링크가 아니어도 reparse 속성을 가짐 | 다른 위치를 가리키는 링크·정션·마운트 지점만 거부. 실제 정션 안의 파일은 계속 거부 |
| Windows ‘삭제 확인’ 설정을 켜면 파일마다 확인창이 뜨고 앱 뒤에 숨을 수 있음 | 휴지통 이동 옵션에 일반 확인 생략이 없음 | 일반 확인은 생략하고 영구 삭제 경고는 유지. PreDelete 검사도 그대로 영구 삭제를 막음 |
| 휴지통에서 복원해도 ‘다시 받지 않기’가 보이지 않게 남음 | 복원·새로고침 후에도 다시 받지 않는 목록에 남음 | 원래 위치로 돌아온 파일이면 그 삭제가 기록한 선택만 해제. 다른 사본의 이후 삭제나 이후 선택은 유지 |

새 회귀 검사는 수정 전 코드에서 실패하고 수정 후 통과하는 것을 확인했습니다. OneDrive는 이 PC에서 실행 중이 아니어서, Python이 클라우드 파일에 보고하는 속성을 재현한 검사와 실제 정션 검사로 확인했습니다.

## 확인한 정상 부분

- 저장 작업: 중단·요청 제한·인증 오류·디스크 오류 처리, 계정·저장 경로 잠금, GIF 변환 실패 시 원본 MP4 보존.
- 기록: 폴더 사본 합병, 기록 이전의 저널·복구, 손상 DB 복구와 일일 백업.
- 휴지통 삭제: COM 호출 순서·영수증 검증·의도 기록·중단 복구.
- 화면: 미리보기·썸네일·기록 불러오기가 화면 스레드 밖에서 실행되고, 라이브러리 작업 중 저장·폴더 변경·종료가 겹치지 않음.
- 최소화나 다른 창 뒤에서 오류 확인창이 떠도 앱을 다시 앞으로 가져오면 확인창이 위에 올라오는 것을 재현으로 확인.

## 검증

- 전체 회귀 **671개 중 668개 통과, 3개 생략**(462.7초). 생략은 Windows 심볼릭 링크 생성 권한이 필요한 검사 2개와, 명시적으로 켰을 때만 실제 휴지통을 쓰는 검사 1개입니다. 실제 휴지통 검사는 따로 켜서 새 임시 파일 하나로 통과했습니다. 로그: `.test-output/fix221-full-tests.log`.
- 새 회귀 검사 11개: 진행 이벤트 해독, DB 열기 대기, 기록 복구 중 종료(창·앱), 삭제 기록 색인, 삭제 완료 시 전체 조회 없음, 복원 후 선택 해제와 유지 조건 3개, 클라우드 파일·실제 정션. 기존 링크·확인창 옵션 검사는 새 기준으로 바꿨습니다.
- `build.ps1`로 `release/XlikeSaver-2.2.1` 폴더 빌드와 ZIP을 만들었습니다(PyInstaller 6.22.3). 로그: `.test-output/fix221-build.log`.
- 배포본 감사: ZIP CRC·SHA256, 소스 93개·앱 2,921개 파일 일치, 개인 설정·DB·쿠키 항목 0개. ZIP을 한글 경로(`.test-output/2.2.1 단독폴더`)에 풀어 exe 자체 점검을 통과했습니다. 작업 프로세스, ExifTool 직접 작성과 재확인, 삭제 기록·재다운로드 설정, 기록 이전·복구, 테마를 확인합니다. 감사: `.test-output/fix221-release-audit.json`, 자체 점검: `.test-output/fix221-frozen-selftest.json`.

실제 X 계정에 요청하거나 사용자의 인증정보·설정·기록·미디어를 바꾸지 않았습니다. 시험 자료는 임시 폴더를 사용했고, 실제 휴지통 검사는 새 임시 파일 하나만 옮겼습니다.
