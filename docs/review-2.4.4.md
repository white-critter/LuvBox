# 2.4.4 전체 코드 검토·이전 저장 폴더·예약 결과 보완

검토일: 2026-10-09. 기준: `df5bbfa`의 2.4.3.

## 검토 범위

앱의 모든 Python 모듈과 실행 진입점, 빌드·배포·런타임 준비 도구를 나누어 검토했습니다. 다운로드·인증·요청 간격·취소·외부 도구 수명, 기록·병합·복구·삭제, UI·스레드·예약 실행을 확인했습니다. 2.4.3 작성자 목록의 지연 표시와 기존 통계·미리보기·다운로드 최적화는 유지합니다.

## 수정과 재현

1. **이전 폴더 경로 확인 속도**: `_media_path`는 승인된 이전 폴더의 정확한 기록 경로를 `SELECT ... WHERE path=? LIMIT 1`로 확인했습니다. 경로 인덱스가 없어 파일마다 `SCAN media`를 반복했습니다. `media_path` 인덱스를 추가하고 옛 DB의 표 재구성 시에도 다시 만듭니다. 임시 카탈로그 10,000행을 같은 폴더 캐시 조건으로 확인했을 때 **9.768초 → 2.937초**였습니다. 승인된 경로 수는 모두 10,000개로 같습니다. 파일 I/O와 화면 전체의 시간이 아니라 기록 경로 확인의 측정값입니다.
2. **이전 폴더 복원 파일 누락**: A 폴더에서 받은 파일의 기록을 B로 옮긴 뒤 파일을 삭제하고 A의 원래 경로에 복원하면, 새로고침이 B만 검색해 파일 목록·통계가 비고 ‘다시 받지 않기’가 남았습니다. 새로고침 때 빈 현재 경로의 `last_path`만 승인된 루트·일반 파일·링크 검사 후 연결합니다. 전체 이전 폴더는 검색하지 않으며, 다른 계정의 미등록 파일은 가져오지 않습니다. 저장일·작성자·출처·본문과 삭제 기록을 유지합니다. 삭제 당시 선택만 기존 정책대로 해제하며 이후 사용자가 지정한 선택은 유지합니다.
3. **예약 결과 확인 중 덮어쓰기**: 앱이 예전 실패 결과를 읽고 ‘확인함’을 기록하는 사이 새 예약 실행이 끝나면, JSON 전체를 다시 쓰면서 최신 결과가 없어졌습니다. 확인 상태는 결과 SHA256을 이름으로 하는 독립 파일에 원자적으로 저장합니다. 여러 창에서 서로 다른 결과를 확인해도 늦은 쓰기가 새 결과의 확인 상태를 지우지 않습니다. 실행별 UUID로 같은 초·동일한 내용의 결과도 구분합니다. 이전 버전의 `seen` 값과 호출 방식도 지원합니다.
