# LuvBox 검증

이 문서는 현재 지원하는 Qt 앱의 검사 절차와 최신 완료 결과를 기록합니다. 과거 UI·버전별 전체 원문은 [1.2.0 검증 기록](https://github.com/chobby-f/LuvBox/blob/v1.2.0/docs/verification.md)에 보존합니다. 실행하지 않은 항목이나 생략된 항목을 통과로 보고하지 않습니다.

## 검사 절차

[개발 안내](development.md)의 고정 입력·의존성 확인, 전체 unittest, 소스 자체 점검과 오프라인 저장 초기화를 실행합니다. 테스트는 임시 앱 데이터·생성한 미디어·합성 계정을 사용합니다. 링크 생성 권한이나 선택적 Chromium/Playwright가 없으면 해당 검사는 사유와 함께 생략될 수 있습니다.

`build.ps1`은 PyInstaller 전에 프로젝트 입력을 기록하고 빌드 후 불변 여부와 EXE·실행 폴더 전체 파일의 해시를 확인합니다. Python·QML·도구·배포 문서·의존성 또는 봉인한 런타임이 바뀌면 다시 빌드해야 합니다. 실제 EXE의 Qt 화면·종료와 오프라인 저장 시작 검사도 통과한 뒤에만 ZIP을 만듭니다. 직접 패키징에도 같은 입력 기록과 EXE별 시작 보고서가 필요합니다.

배포 검증은 ZIP CRC, 실행 파일·런타임·소스·라이선스, 체크섬과 개인정보 제외를 확인합니다. 공개 전 업로드 파일을 다시 받아 해시를 대조하고 한글·공백 경로에서 실행합니다. 세부 로그와 합성 화면은 `.test-output/`에 보관하며 배포 소스에 넣지 않습니다.

## 2026-10-25 1.2.1 소스 검증 결과

- 최종 Windows 전체 회귀 **990개 중 984개 통과·6개 생략**, 실패·오류 없음(285.102초). 생략은 심볼릭 링크 권한 4개, 선택적 Chromium/Playwright 통합 1개와 명시적 선택이 필요한 네이티브 휴지통 검사 1개입니다. 최종 전체 실행 중 제품·테스트·빌드 소스 148개의 해시가 유지됐습니다.
- 실제 제품 QML에서 680×480·1080×760·1600×1000 및 100%·150% 배율의 갤러리 두 줄 오른쪽 정렬을 확인했습니다. 로딩 중·유휴 상태, 실제 좌우 키 입력, 도구 버튼 포커스, 첫·마지막 사진 경계와 본문 커서 조작을 검사했습니다. QML 실행 오류는 없었습니다.
- 실제 Windows DPAPI로 구형 헤더·entropy의 세션을 읽고 새 형식으로 저장한 뒤 기존 계정 재선택과 쿠키 보존을 확인했습니다. 읽기·해독·계정 목록 오류와 암호화·파일 교체 실패는 기존 세션을 보존합니다. 첫 전체 검사에서 발견한 과거 테스트의 암호화 mock 오류를 고친 뒤 전체를 다시 실행한 결과입니다.
- 실제 Windows 프로세스로 강제 worker 종료 뒤 변환 도구도 종료되는지, 빠른 정상 종료와 Job 연결의 경쟁 상태, 보호 초기화 실패 시 도구 종료·원본 보존을 검사했습니다. 실제 GIF 변환·취소 및 메타데이터의 기존 메모리 상한도 확인했습니다.
- 빌드 봉인 후 소스·QML·DLL 변경, 파일 추가·누락·hardlink와 압축 중 소스·런타임 변경을 주입했습니다. 패키징을 거부하고 이전 ZIP·체크섬을 보존하며 임시 ZIP을 정리합니다. `pip check`, 고정 빌드 입력, 제품·빌드 Python 47개 컴파일과 변경 파일 검사를 통과했습니다.
- OSV의 현재 PyPI 버전 조회는 고정 의존성 **19개에서 보고된 항목 0개**였습니다. 모든 네이티브 구성요소나 취약점 부재를 뜻하지 않습니다.
- 날짜·버전별 검토/계획 문서 5개를 현행 안내로 통합했습니다. 로컬 구버전 산출물·중복 검증 ZIP/추출본·생성 spec·빌드 중간 파일 34개 묶음 **4,053,108,852바이트(약 4GB)**와 병합된 옛 로컬 브랜치 2개를 정리했습니다. 1.2.0 실행 폴더·ZIP, 검증 로그·화면, 사용자 데이터, Git 기록과 GitHub 과거 릴리스·태그는 보존했습니다.

세부 로그는 `.test-output/audit-121/`, 화면은 `.test-output/audit-ui/`에 있습니다. 최종 소스 검증 뒤 `build.ps1`의 실제 Windows EXE 검사와 배포 파일 재다운로드·한글/공백 경로 검사를 별도로 수행합니다. 완료된 배포 결과는 해당 GitHub 릴리스 설명을 따릅니다. 아래 1.2.0 결과를 1.2.1 실행 파일의 검증으로 대체하지 않습니다.

## 2026-10-25 1.2.0 완료 결과

- Windows 전체 회귀 **968개 중 964개 통과·4개 생략**, 실패·오류 없음(387.603초). 생략은 심볼릭 링크 권한 3개와 선택적 Chromium/Playwright 통합 1개입니다.
- 최종 화면·계정 보완 후 관련 **34개 모두 재통과**(17.618초)했습니다. 별도 통합 **53개 모두 통과**했고 실제 Windows DPAPI·합성 두 계정으로 계정/폴더 설정 실패와 작업 시작 경계를 검사했습니다.
- 680×480·1080×760·1600×1000, 150% 배율과 실제 Qt 이벤트 루프에서 큰 미리보기·확대·이동·이전/다음·저장 상세를 확인했습니다. 생성 GIF·MP4의 첫 프레임, 숨김 시 디코딩 없음, 최신 요청만 유지, 링크·클라우드 전용·파일 교체 거부와 닫기 후 파일 해제·저장 승인 순서를 검사했습니다.
- `pip check`, 고정 빌드 입력, Python 컴파일, 변경 QML 검사와 파일 검사를 통과했습니다. 당시 OSV의 PyPI 버전 조회는 고정 의존성 19개에서 보고된 항목 0개였으며 모든 네이티브 구성요소나 이후 시점의 취약점 부재를 뜻하지 않습니다.
- 실제 1.2.0 EXE의 Windows 창·갤러리·사진·설정·연결창·정상 종료, 네트워크를 차단한 저장 초기화와 격리 자체 점검을 확인했습니다. [1.2.0 배포](https://github.com/chobby-f/LuvBox/releases/tag/v1.2.0)는 이 버전의 자료이며 후속 변경의 검증을 대신하지 않습니다.

전체 테스트 인터프리터 종료 시 PySide6의 기존 유형 `ResourceWarning`이 남았습니다. 경고를 숨기지 않았고 테스트 실패나 EXE 종료 지연은 없었습니다. 장기 실행 메모리 누수 부재의 증명으로 해석하지 않습니다. 실제 사용자 X 로그인·추가 인증·장기 실행·확장 스토어 심사는 오프라인 검사와 구분합니다.
