# LuvBox 검증

이 문서는 현재 지원하는 Qt 앱의 검사 절차와 최신 완료 결과를 기록합니다. 과거 UI·버전별 전체 원문은 [1.2.0 검증 기록](https://github.com/chobby-f/LuvBox/blob/v1.2.0/docs/verification.md)에 보존합니다. 실행하지 않은 항목이나 생략된 항목을 통과로 보고하지 않습니다.

## 검사 절차

[개발 안내](development.md)의 고정 입력·의존성 확인, 전체 unittest, 소스 자체 점검과 오프라인 저장 초기화를 실행합니다. 테스트는 임시 앱 데이터·생성한 미디어·합성 계정을 사용합니다. 링크 생성 권한이나 선택적 Chromium/Playwright가 없으면 해당 검사는 사유와 함께 생략될 수 있습니다.

`build.ps1`은 PyInstaller 전에 프로젝트 입력을 기록하고 빌드 후 불변 여부와 EXE·실행 폴더 전체 파일의 해시를 확인합니다. Python·QML·도구·배포 문서·의존성 또는 봉인한 런타임이 바뀌면 다시 빌드해야 합니다. 실제 EXE의 Qt 화면·종료와 오프라인 저장 시작 검사도 통과한 뒤에만 ZIP을 만듭니다. 직접 패키징에도 같은 입력 기록과 EXE별 시작 보고서가 필요합니다.

배포 검증은 ZIP CRC, 실행 파일·런타임·소스·라이선스, 체크섬과 개인정보 제외를 확인합니다. 공개 전 업로드 파일을 다시 받아 해시를 대조하고 한글·공백 경로에서 실행합니다. 세부 로그와 합성 화면은 `.test-output/`에 보관하며 배포 소스에 넣지 않습니다.

## 2026-10-26 1.2.2 저장 상세 잠금 오류 회귀

- Windows 임시 PNG·MP4를 실제 공유 금지 핸들로 잠그고, PNG에는 바이트 범위 잠금도 적용해 같은 미리보기 실패를 재현했습니다. 잠금 해제 뒤 자동 재시도로 정지 미리보기가 만들어지고 원본 바이트가 유지됩니다. 최초 서명을 유지해 대기 중 파일 교체·일반 하드링크 추가는 거부합니다.
- 기존 동기화 업로드 링크 보완을 유지하면서 같은 상위 경로로 예외를 제한했습니다. 실제 볼륨의 링크 이름으로 같은 트리의 임시 업로드 링크는 표시하고 다른 위치의 같은 폴더명은 거부합니다.
- 실제 ExifTool 읽기와 Windows 파일 복사도 초기 잠금으로 즉시 실패하던 경계를 재현했습니다. 명확한 잠금만 단계당 최대 1초, 기존 전체 20초 상한 안에서 재시도합니다. 기존 태그·사진 바이트·mtime·파일 권한을 보존하며 중단하면 이미 저장한 파일·DB·archive를 마친 뒤 정상 `stopped`로 종료합니다.
- 최종 관련 **36개 모두 통과**(6.891초). 최초 전체 실행에서 새 중단 확인 인자를 반영하지 않은 기존 kwargs 검사 2개를 찾아 기대값과 실제 callback 상태 검증을 보강했습니다. 제품 코드는 이 테스트 보강으로 바뀌지 않았습니다.
- 실제 제품 QML 검사 **2개 통과**(23.392초). 680×480·1080×760 및 100%·150% 배율에서 실패 버튼 실제 클릭·이미지 복귀·성공 후 버튼 숨김·작성자/본문/게시 시각 유지·숨긴 상세의 재요청 차단을 확인했습니다. 기존 GIF·영상 첫 프레임도 통과했고 QML 오류는 없었습니다.
- 원격 main의 전체 검토 보완과 기존 미커밋 미리보기 수정을 함께 보존·통합했습니다. `pip check`, 고정 빌드 입력, 제품·빌드 Python 47개 컴파일과 변경 파일 검사를 통과했습니다. 로그·합성 화면과 통합 전 백업은 `.test-output/saved-details-122/`에 보관하며 배포하지 않습니다.

최종 전체 회귀와 Windows EXE 빌드는 같은 동결된 입력으로 실행합니다. ZIP의 컴파일된 모듈·실행 파일·소스·CRC·체크섬을 확인하며, 업로드 파일 재다운로드와 한글/공백 경로 실행까지 통과한 배포 결과는 1.2.2 릴리스 설명을 따릅니다. 아래 미배포 검토 기록이나 1.2.1 결과를 1.2.2 Windows 실행 검증으로 대체하지 않습니다.
