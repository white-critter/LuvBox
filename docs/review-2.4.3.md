# 2.4.3 전체 검토·저장 중 기록 창 반응 개선

검토·수정일: 2026-10-09. 기준은 `57395cb`의 2.4.2입니다.

## 검토 범위와 판단

- 2.4.2에서 바뀐 부분을 확인했습니다: 이전 형식 백업 복구(행마다 있는 열만 넣기), 경로 변경 전 기록 사본 병합, 성공한 미리보기만 캐시, 로컬 작업 완료 순서. 오류를 찾지 못했습니다. 미리보기 실패를 캐시하지 않아 새로고침 때 다시 시도하지만, 흔한 실패(FFmpeg 없음, 지원하지 않는 파일)는 바로 끝나므로 부담이 없습니다.
- 2.4.0에서 추가된 Edge 로그인(임시 프로필·127.0.0.1 DevTools·정리), 사진 드래그·여러 개 선택, 작성자별 최근 사진과 작성자 필터를 따로 확인했습니다. 수정할 문제를 찾지 못했습니다.
- 성능: 2.4.0부터 통계가 상위 20명 대신 **모든 작성자**를 보여 줍니다. 저장하는 동안 기록 창은 몇 초마다(이전 불러오기 시간의 3배, 2~30초) 새로고침되고, 그때마다 통계 탭을 보고 있지 않아도 작성자 목록 전체를 화면 스레드에서 다시 그렸습니다.

## 수정

작성자 목록은 통계 탭이 보일 때만 다시 그립니다. 다른 탭에 있는 동안 새 통계가 오면 ‘다시 그려야 함’만 표시하고, 통계 탭을 열 때 한 번 그립니다. 통계 탭을 보고 있으면 이전처럼 새로고침마다 바로 반영합니다. 작성자 찾기 입력, 작성자 선택 상자, 최근 사진, 월별 그래프는 그대로입니다.

| 작성자 수 | 목록 다시 그리기(측정) |
|---|---|
| 2,000명 | 약 0.02초 |
| 10,000명 | 약 0.1초 |
| 30,000명 | 약 0.4초 |

실제 기록 창에서 작성자 20,000명 통계로 새로고침 5회를 측정했습니다. 통계 탭이 숨어 있을 때 1회 약 11ms(시험용 통계를 만드는 시간 포함), 보일 때 약 345ms입니다. 다른 검사를 함께 돌리던 상태라 절대값은 크게 나왔습니다.
