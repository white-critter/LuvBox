## DPAPI와 브라우저 연결

[DPAPI 검증 결과](../.test-output/windows-20261022/dpapi-validation.json)는 `ok=true`, `real_dpapi=true`입니다. 합성 세션만 사용해 각각 새 프로세스로 저장·재시작·계정 선택·선택 후 재시작·취소·계정 제거·남은 계정으로 재시작·전체 연결 해제의 8단계를 모두 통과했습니다. 실제 Windows 사용자 범위의 암호화를 호출했으며 기존 사용자 앱 데이터와 실제 인증 값은 읽지 않았습니다. 이는 X가 합성 인증 값을 받아들인다는 검사가 아닙니다.

기본 브라우저는 Chrome입니다. 사용자가 격리된 임시 앱에서 확장 설치·코드 비교·연결 승인을 직접 수행하고 본인 아이디 자동 입력을 확인했습니다. [첫 저장 확인](../.test-output/windows-20261022/live-login-first-inspect.json)과 [실제 앱 재시작](../.test-output/windows-20261022/live-login-restarted-app.log)에서 연결 존재·확인된 계정·입력란 일치가 모두 참이었습니다. 인증 값이나 계정 이름은 진단에 출력하지 않았으며 일반 사용자 앱 데이터는 변경하지 않았습니다. 이는 실제 미디어 다운로드 검증은 아닙니다.

사용자 요청에 따라 **기본 브라우저에서 새 로그인**을 추가했습니다. Windows HTTPS 연결에서 실행 파일만 확인해 기본 Chrome·Edge를 선택하며 등록된 명령의 추가 인수는 실행하지 않습니다. 기존 프로필을 읽거나 복사하지 않고 이번 시도 전용 임시 프로필과 상속된 익명 파이프를 사용합니다. 지원하지 않는 기본 브라우저에서는 사용자가 Edge 보조 경로나 기존 로그인 연결을 선택합니다.

[실제 기본 Chrome 통신 검사](../.test-output/windows-20261022/default-browser-pipe-smoke.json)는 확장 없는 새 프로필의 `about:blank`에서 비공개 파이프·쿠키 API 통신·시간 초과·닫기·프로세스 종료·프로필 정리를 통과했습니다. X 로그인이나 세션 저장을 대신 수행한 검사는 아닙니다.

2026-10-23 실제 X 로그인 화면에서는 사용자가 “로그인이 일시적으로 제한되었습니다. 나중에 다시 시도해 주세요.”를 확인했습니다. 이 화면만으로 제한 원인을 단정하지 않았고 추가 로그인 제출을 하지 않았습니다. 사용자가 이번 Chrome 창과 검증 앱을 닫은 뒤 [정리 확인](../.test-output/windows-20261022/live-login-after-default-cancel.json)에서 기존 연결·계정 입력 일치가 유지되고 임시 로그인 프로필이 0개임을 확인했습니다. 확장 없는 경로의 **실제 X 인증 성공은 미검증**입니다. 합성 회귀나 기존 확장 경로의 성공으로 대신 통과 처리하지 않습니다.

갤러리의 긴 지연은 미해결입니다. 격리 1,000개 조건에서 스크롤 heartbeat p95는 **117.263→109.471ms**, 최대는 **450.221→292.381ms**였습니다. 기준은 HEAD의 `_mount`·`_render_viewport`를 복원한 진단 조건이며, 이 한 쌍으로 전반적인 부드러움 개선을 입증하지 않습니다. 근거는 [기준 진단](../.test-output/windows-20261022/gallery-isolated-baseline.json)과 [현재 1,000개](../.test-output/windows-20261022/gallery-isolated-1000.json)입니다. 네이티브 프레임 배치 실험도 개선을 입증하지 못해 제품에 적용하지 않았습니다.

초기의 게임 동시 실행 등 부하가 달랐던 측정은 최종 전후 성능 비교에서 제외합니다. 스크롤을 멈춘 최종 표시 영역은 모두 사진 준비가 끝나 준비 비율이 1.0이었지만, 이동 중 준비 비율의 표본 평균은 **0.286**이었습니다. 메모리와 위젯 수가 제한돼도 이동 중 미리보기 지연은 크게 남습니다. 이 결과를 10,000개 갤러리의 부드러움 해결로 기록하지 않습니다.

## EXE·ZIP 빌드와 무결성

`build.ps1`을 실행해 `release/LuvBox-1.0.0/LuvBox-1.0.0.exe`, `release/LuvBox-1.0.0.zip`, `release/SHA256-1.0.0.txt`를 새로 만들었습니다. 실행 파일은 같은 폴더의 `_internal`과 함께 사용하는 폴더형 배포입니다. 기존 2026-10-18 EXE 폴더·ZIP·체크섬은 이동 전 원본·목적지의 절대 경로가 작업 폴더 안인지 확인한 뒤 `.test-output/windows-20261022/previous-release/`로 보존했습니다.

[빌드 로그](../.test-output/windows-20261022/build-final.log)의 PyInstaller WARNING은 고정 ExifTool 상류 테스트 파일 `exiftool_files/t/images/EXE.exe`의 `cygwin1.dll` 의존성 1건입니다. 실제 ExifTool·Perl 실행과 메타데이터 왕복은 아래 frozen 자체 점검에서 통과했습니다. 임의 DLL을 추가하거나 고정 상류 입력을 수정하지 않았습니다.

새 빈 `배포 검증 20261023` 폴더에 ZIP을 풀고 그 안의 EXE와 소스를 각각 실행했습니다. 자체 점검은 실제 Tk 컨트롤·기본 글꼴·아이콘·미디어·FFmpeg·ExifTool/Perl·한글 파일 메타데이터·인증 전 중단되는 작업자 등을 검사하며, 사용자 앱 데이터가 아닌 임시 `LOCALAPPDATA`를 사용합니다. ZIP 소스 실행은 준비된 저장소 가상환경의 Python을 사용했습니다. 새 PC에서의 의존성 설치 검사는 아닙니다.

[ZIP 검사](../.test-output/windows-20261022/package-validation.json)는 **5,029개 항목의 CRC·안전한 경로·중복 없음·정확한 허용 목록·현재 입력별 전체 SHA256 대응**을 확인합니다. EXE의 현재 소스와 같은 32개 앱 모듈/진입점 코드 객체도 대조했습니다. 고정 글꼴·테마·FFmpeg·ExifTool/Perl·라이선스와 선택적 확장 자산 15개가 포함되며 사용자 설정·세션·쿠키·DB·진단 로그는 제외합니다. 상류 ExifTool의 테스트 미디어는 고정 런타임/소스 입력에 해당하는 파일만 허용합니다. 최초 진단 하네스가 `ExifTool.exe`의 이름을 소문자로 가정해 실패했던 검사는 [초기 결과](../.test-output/windows-20261022/package-validation-initial.json)로 남기고, 실제 고정 파일명의 대소문자를 반영해 재검사했습니다. 제품 파일 누락은 아니었습니다. 최종 문서를 반영한 뒤 ZIP과 외부 SHA256 파일을 다시 생성하고 재검사합니다. ZIP 자체 해시는 자기 참조를 피하도록 동봉 소스 문서가 아닌 외부 `SHA256-1.0.0.txt`에 기록합니다.

배포 EXE의 일반 실행은 격리 데이터로 프로세스 시작·응답과 창 목록의 존재까지 확인했으나, Computer Use가 같은 창에 대해 소유자 식별 오류를 두 번 반환해 화면 캡처·정상 닫기 직접 조작은 확인하지 못했습니다. 앱 입력은 보내지 않았고, 정리를 시도할 때 시작한 PID는 이미 없었습니다. 종료 원인을 관측하지 않았으므로 정상 종료나 제품 오류로 단정하지 않습니다. [추가 화면 검사 결과](../.test-output/windows-20261022/frozen-ui-validation.json)를 자체 점검 성공 및 앞선 소스 창 직접 조작 결과와 구분합니다.

## 남은 검증과 배포 경계

- 갤러리 스크롤의 긴 UI 지연과 낮은 이동 중 미리보기 준비 비율의 원인 규명·개선.
- X의 새 로그인 제한이 해제된 뒤 확장 없는 기본 Chrome 새 로그인 성공 확인. 자동 재시도하지 않습니다. 실제 다중 계정 선택·연결 해제는 합성 검증과 구분합니다.
- 배포 EXE 일반 창의 직접 화면 확인·정상 닫기 재확인. 자동화 도구의 창 식별 오류로 완료하지 못했으며 frozen 자체 점검으로 대신 통과 처리하지 않습니다.

GitHub 릴리스 업로드와 `main` 푸시는 하지 않았습니다. 검증 결과와 산출물을 먼저 사용자에게 제시하고 확인받은 뒤 별도로 진행합니다.
