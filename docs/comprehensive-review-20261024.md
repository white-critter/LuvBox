# LuvBox 1.1.3 종합 검토

2026-10-24, Windows 11 / Python 3.12.14 / PySide6 6.10.3. 원격 `main`의 `f1ff053`과 앞선 미커밋 저장 오류 수정을 보존해 함께 검토했습니다. 사용자는 앞선 수정도 이번 커밋·배포에 포함하도록 확인했습니다. 시작 상태의 패치와 새 파일 해시는 `.test-output/comprehensive-review/baseline.*`에 보관했습니다.

## Qt 전용 정리

추가 요청에 따라 이전 UI 모듈·실행 옵션·전용 테스트·도구·테마 이미지와 런타임 의존성을 제거했습니다. Qt에서 사용하지 않는 이전 미리보기 작업자도 제거했습니다. 현재 예약 실패 알림은 Qt 대화상자를 사용하고, 자체 점검은 공용 저장·메타데이터·기록 검사와 실제 Qt 화면 검사로 구성했습니다. 이미지·아이콘·폰트의 현재 Qt 경로는 유지합니다.

혼합 테스트에서 공용 저장·미디어·복구·보안 검사는 남기고 삭제된 화면과 작업자만 검사하던 항목을 정리했습니다. 현재 진입점·worker·예약·Qt 컨트롤러는 이전 툴킷의 import를 차단한 상태에서도 동작해야 하며, PyInstaller의 실행 파일 목록에 제거한 런타임이 섞이면 패키징을 거부합니다. 기존 이름의 계정·설정·사진·기록을 읽는 데이터 호환 코드는 유지합니다.

## 검토 범위

Qt 저장·갤러리·계정·연결·예약·미리보기·휠 및 QML 화면, 작업 프로세스 IPC, 다운로드 엔진, 요청 보호, DPAPI와 브라우저 확장 연결, 기록·정렬·폴더 이전·복구·삭제 권한, 미디어·메타데이터·썸네일·외부 도구 제한, 설정과 예약 실행, PyInstaller·배포 소스·ZIP 생성 경로를 검토했습니다. 실제 사용자 DB 삭제·스키마 파괴 변경·계정 초기화·예약 변경은 수행하지 않았습니다.

## 성능 측정

격리된 새 SQLite 기록에 좋아요 100,000개를 방문·기록하는 합성 벤치마크를 구현별 3회 순차 실행했습니다. 수정 전 중앙값 **2.864초**(2.857–2.904), 수정 후 **0.779초**(0.732–0.790)였고 모든 표본에서 DB 정렬 순서가 같았습니다. 이 결과는 해당 로컬 기록 경로의 약 3.68배 개선이며 X 요청 속도·다운로드 대역폭이나 모든 갤러리 작업의 성능을 뜻하지 않습니다. 원자료는 `.test-output/audit/like-order-benchmark-repeat.json`입니다.

소비자가 멈춘 합성 상황에서 진행 이벤트 100,000개를 저장·확인·완료 경계와 함께 넣었을 때 큐에는 필요한 최신 진행 값과 제어 이벤트 7개만 남았습니다. 파일별 성공·오류 기록은 합치거나 버리지 않습니다.

## 검증과 배포

최종 Qt 전용 전체 검사 **912개 중 906개 통과·6개 생략**, 실패·오류 0개(432.174초)입니다. 생략은 Windows 링크 생성 권한 5개와 선택적 실제 Chromium/Playwright 검사 1개입니다. 새 임시 파일을 사용하는 Windows 휴지통 검사도 실행했습니다. 전체 검사 시작 시 Python·QML·빌드·설정 파일 해시를 기록했고 종료 시 변경이 없음을 확인했습니다. 로그는 `full-tests.log`, 해시 목록은 `full-suite-source-final.json`입니다.

최종 패키지 대조에서 참조가 끊긴 표시 도우미와 삭제된 로그인 경로를 가리키던 안내도 정리했습니다. 영향 범위 **72개를 재검사해 모두 통과**했고(31.462초), 해당 소스로 전체 EXE·ZIP을 다시 빌드했습니다. 로그는 `final-auth-notice-tests.log`와 `release-build-final.log`입니다.

사진·GIF·MP4 재생과 파일 해제·승인 순서, 세대가 바뀐 갤러리 작업, 다중 프로세스 계정·설정 변경, 엄격한 설정 보존, IPC 경계와 실제 Qt 시작 검사를 포함합니다. `pip check`, Python AST·PowerShell 문법, QML 검사를 수행했습니다. 자체 점검은 생성 미디어·임시 DB·가짜 연결만 사용하며 실제 계정·예약에 접근하지 않습니다.

`build.ps1` 전체 빌드가 종료 코드 0으로 완료됐으며 실제 1.1.3 EXE의 Qt 창·갤러리·사진 미리보기·설정·연결창·종료와 오프라인 다운로드 초기화를 통과했습니다. 같은 EXE의 `--self-test`도 종료 코드 0으로 생성 미디어의 출처·작성자 기록, 사진·영상·GIF, 기록 이전·복구·정렬·임시 삭제 및 Qt 화면을 확인했습니다.

기존 연결·저장 폴더에서 실행별 사진 1개 제한으로 **사진 1개 저장과 기존 사진 건너뛰기**를 확인했고 새 JPEG의 무결성 검사도 통과했습니다. 사용자 설정·연결·예약을 바꾸지 않았고 운영 파일을 삭제하지 않았습니다. 이 결과는 제한된 사진 저장이며 전체 좋아요 목록이나 실제 영상 다운로드 검증으로 확대하지 않습니다.

EXE·ZIP SHA-256은 `release/SHA256-1.1.3.txt`에 기록합니다. ZIP CRC·해시·소스 일치·이전 UI 런타임 배제·개인 파일 제외는 `final-package-validation.json`, GitHub 업로드·재다운로드·한글 경로 실행 확인은 `deployment-result.json`에 기록합니다. 개발 로그는 `.test-output/comprehensive-review/`와 `.test-output/audit/`에 보관하며 배포에 포함하지 않습니다. 릴리스와 커밋은 [1.1.3 배포 기록](https://github.com/chobby-f/LuvBox/releases/tag/v1.1.3)을 기준으로 확인합니다.

## 남은 범위

전체 테스트 종료 시 PySide6의 GC ResourceWarning이 남습니다. 앱·worker·파일 없이 `QObject`에 `Property` 하나만 선언한 최소 프로세스에서도 종료 경고 1개를 재현했고, 실행 중 명시적 GC의 `garbage`는 0개였습니다. 이 바인딩 종료 경고를 숨기는 필터는 추가하지 않았습니다. 원자료는 `qt-property-gc-minimal.log`이며 실행 중 메모리 증가 여부와 구분합니다.

OSV 조회는 알려진 공지의 버전 매칭 결과이며 취약점 부재를 보증하지 않습니다. FFmpeg·ExifTool·Qt·Python에 들어 있는 모든 네이티브 코드의 형식 검증이나 퍼징을 수행한 것은 아닙니다. Windows 코드 서명은 제공하지 않으며, Qt 휴지통·복구 및 새 예약 생성 UI와 브라우저 확장 스토어 배포는 이번 작업 범위에서 추가하지 않았습니다.
