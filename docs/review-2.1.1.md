# 2.1.1 안정화

검토·수정일: 2026-10-07. 기준은 `81faa7b`의 2.1.0입니다. 앞선 [패치 검토](review-2.1.0.md)에서 재현한 7건을 보완했습니다.

| 문제 | 수정 후 동작 |
| --- | --- |
| 다른 계정·저장 폴더로 다시 받기 | 선택한 계정·기록 DB·저장 경로를 먼저 대조하고, 바뀌었으면 새로고침 안내 |
| 저장과 숨김 선택이 겹침 | UI와 진입점에서 교차 실행 차단, 다른 프로세스도 계정·출력 잠금으로 보호 |
| 비공개 트윗 하나가 전체 재시도를 중단 | 비공개·연령 제한 트윗만 건너뛰고 다음 항목 처리. 실제 인증 오류·401/403·요청 제한은 계속 중단 |
| 숨김 선택 사본이 오래됨 | DB를 닫은 뒤 폴더 사본과 PC 백업 즉시 갱신. 갱신 실패 시 로컬 선택을 보존하고 안내 |
| 부분 복원 후 중단 시 성공 파일도 계속 숨김 | 종료 경로에서 복원 완료 파일만 숨김 해제. 미처리 항목의 선택 유지 |
| 최신 5,000개가 오래된 사라진 파일을 가림 | 전체 스냅숏을 숨김 필터 후 50·100·200개씩 표시. 페이지 이동에 추가 DB·폴더 조회 없음 |
| 불완전 테마 캐시로 시작 실패 | 필수 자산과 PNG 디코딩을 확인하고 실패하면 전체 재생성. 정상 캐시 재사용 유지 |

확인창 전의 선택·계정·저장 위치·세대를 캡처합니다. 확인창이 열린 동안 새로고침·저장 시작·창 닫기가 발생하면 오래된 선택을 적용하지 않습니다. 숨김 선택 작업 중 창을 닫으면 기록과 사본 갱신까지 기다립니다. 일반 라이브러리 읽기는 저장을 막지 않습니다.

## 추가 발견과 수정

손상된 DB가 초기 출처 URL 보정 시 `SQLITE_CORRUPT` 대신 `SQLITE_CONSTRAINT_NOTNULL(1299)`를 반환하는 경우도 확인했습니다. 이때만 `quick_check`로 실제 손상을 확인해 기록 복구 안내로 연결합니다. 정상 DB의 제약 오류는 일반 오류로 유지하고, 정상 시작에는 전체 무결성 검사를 추가하지 않습니다. 두 경우 모두 실제 SQLite 회귀 검사로 확인했습니다.
