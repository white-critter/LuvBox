# 2.5.1 삭제 기능 제거 확인·기록 새로고침 속도

검토·수정일: 2026-10-11. 기준은 `33cfbb1`의 2.5.0입니다.

## 2.5.0 삭제 기능 제거 확인

- 기록 창의 ‘선택한 파일 삭제’ 버튼, 우클릭 메뉴 항목, Delete 키, 삭제 확인창, 삭제 작업자, `deletion.py`·`recycling.py`가 모두 빠졌습니다. 앱 코드와 빌드 설정에 남은 참조가 없습니다. 화면 점검 도구(`tools/ui_qa.py`)만 화면 확인용 옛 삭제 기록을 만듭니다.
- 앱 종료·작업 중 상태 확인(`_library_job_active`, `close`)에서도 삭제 상태가 빠졌습니다.
- 탐색기에서 지운 파일: 새로고침하면 목록·통계에서 빠지고 ‘사라진 파일’에 나옵니다. 완료 기록이 남아 있어 일반 저장이 자동으로 다시 받지 않습니다. 고른 파일만 ‘다시 받기’로 받거나 ‘다시 받지 않기’로 숨깁니다.
- 옛 삭제 기록과 다시 받지 않기 선택은 그대로 있고 ‘이전 삭제 기록’ 탭에서 조회만 합니다. 이전 버전이 남긴 처리 중 기록은 저장 시작 때 확인만 하고 파일을 다시 지우지 않습니다.
- 휴지통을 쓰는 곳은 이제 GIF 변환 하나입니다. 성공한 뒤 원본 MP4를 휴지통으로 옮기고, 휴지통에 넣을 수 없으면 Windows가 먼저 묻습니다. 휴지통이 없는 위치는 MP4로 둡니다.
- 2.5.0 기준 전체 회귀 **686개 중 683개 통과, 3개 생략**. `.test-output/review250-full-tests.log`.

## 속도 개선

탐색기로 지우는 방식에서는 사라진 파일이 계속 쌓입니다. 2.4.4의 ‘복원된 파일 다시 연결’은 새로고침 버튼마다 사라진 파일을 모두 확인하므로 실제 비용을 쟀습니다. 프로파일링 결과 디스크 확인보다 **경로 비교 계산**이 더 오래 걸렸습니다.

- 원인: 파일마다 ‘저장 폴더 안인지, 앱 데이터 폴더가 아닌지’를 여러 번 확인합니다. Python 3.12의 `Path.is_relative_to`는 비교할 때마다 상위 폴더 경로를 하나씩 모두 새로 만듭니다. 18만 번 비교에 6.7초, 같은 결과의 문자열 비교는 0.46초였습니다.
- 수정: `_path_in_root`의 포함 검사 다섯 곳을 같은 결과의 문자열 비교로 바꿨습니다. 대소문자는 pathlib과 똑같이 처리합니다. 폴더 검색에서 상위 폴더 이름을 구하던 `relative_to`도 바꿨습니다. 링크·정션 검사와 파일 확인은 그대로입니다.

| 임시 라이브러리 | 수정 전 | 수정 후 |
|---|---|---|
| 파일 4만 개 · 창 열기/저장 후 새로고침 | 9.7초 | 5.0초 |
| 파일 4만 개 · 새로고침 버튼 | 20.6초 | 10.5초 |
| 파일 2만 개 + 탐색기로 지운 2만 개 · 새로고침 버튼 | 약 16초 | 7.7초 |
| 그중 지운 파일 복원 확인 | 약 4.7초 | 2.3초 |

모두 임시 폴더의 시험 기록으로 측정했습니다. 새로고침은 화면과 별도로 뒤에서 실행되므로 창이 멈추지는 않지만, 결과가 나오기까지의 시간이 줄었습니다.
