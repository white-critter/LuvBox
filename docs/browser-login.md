# X 로그인 연결

현재 Qt 앱은 **브라우저 연결(확장)**과 **토큰 입력** 두 가지입니다. 별도 Chrome/Edge 새 로그인은 제공하지 않습니다.

1. 앱에서 **X 연결**을 누릅니다.
2. 브라우저 연결은 [확장 설치 안내](../assets/browser-extension/README.md)를 따라 코드와 계정을 확인하고, 앱에서 **이 계정 연결 승인**을 누릅니다.
3. 토큰 입력은 `auth_token` 값을 입력해 **연결 저장**을 누른 뒤 저장 화면에서 X 아이디를 입력합니다. 토큰 저장만으로 실제 X 인증이 확인된 것은 아닙니다.

연결 정보는 이 Windows 계정에 암호화해 저장합니다. 토큰·쿠키는 다른 사람에게 보내지 마세요. 확장 자동 설치·스토어 배포는 아직 제공하지 않습니다.

## 이전 구현 참고

아래는 이전 Tk 앱과 개발 과정의 기술 기록입니다. 현재 Qt 앱의 버튼이나 새 로그인 제공 여부를 설명하는 사용 안내가 아닙니다.

후속 사용자 확인: 같은 계정으로 다른 환경에서는 로그인이 됩니다. 앱 전용 새 Chrome에서 표시된 제한 문구만으로 계정 전체의 X 임시 제한을 확정하지 않습니다. 앱 전용 임시 프로필·파이프 연결 환경과 분리 진단이 필요하며 반복 제출이나 탐지 우회는 하지 않습니다.

## 확장 없는 새 로그인

**기본 브라우저에서 새 로그인**은 Windows의 기본 HTTPS 브라우저가 Chrome 또는 Edge일 때 사용할 수 있습니다. 사용자가 새 별도 창에서 X에 로그인하면 앱이 본인 계정을 확인해 아이디를 자동 반영하고, 로그인 연결을 Windows 사용자 범위 DPAPI로 저장합니다. 다음 앱 실행과 예약 저장은 이 연결을 사용합니다. 연결이 만료되면 다시 로그인합니다. 기본 Firefox·Brave 등은 이 새 로그인 경로에서 지원하지 않으며, 사용자가 **Edge에서 X 로그인** 또는 아래의 기존 로그인 연결을 선택합니다. Edge로 자동 전환하지 않습니다.

`luvbox.browser_login.find_default_browser()`는 Windows 기본 HTTPS 연결의 실행 파일을 확인하고 설치된 `chrome.exe`·`msedge.exe`만 선택합니다. `sign_in_default()`와 Edge 보조 경로는 이번 시도 전용 임시 프로필과 상속된 전용 익명 파이프를 사용하며, TCP 디버깅 포트를 열지 않습니다. 기존 브라우저 프로필은 읽거나 복사하지 않습니다. X의 프로필 탐색 링크와 `twid`에 연결된 계정 신원을 확인한 뒤 인증 세션을 저장합니다. 비밀번호는 사용자가 브라우저에 직접 입력하며 앱이 보관하지 않습니다. 완료·취소·시간 초과 시 이번 시도의 프로세스와 임시 프로필을 정리합니다.

## 기존 로그인 연결 (확장 필요)

이미 사용 중인 브라우저의 X 로그인을 다시 로그인하지 않고 연결하는 선택 사항입니다. 사용자 설치 안내는 [브라우저 연결 확장 안내](../assets/browser-extension/README.md)에 있습니다. 이 경로만 Chrome/Edge 개발자 모드 또는 Firefox 임시 부가 기능으로 확장을 직접 설치해야 합니다. 스토어 서명 배포나 자동 설치는 제공하지 않습니다. Firefox 임시 설치는 재시작하면 사라집니다. Safari·비공개 창·Firefox 컨테이너·관리 정책으로 확장이 차단된 환경은 확장 연결을 지원하지 않습니다.

## 확장의 계정 확인과 저장

`luvbox.browser_bridge.BrowserBridge`는 앱에서 연결 버튼을 누른 뒤에만 시작합니다. 앱이 먼저 `127.0.0.1` 임의 포트를 바인드한 후 기본 브라우저를 엽니다. 확장은 연결 요청을 자신의 확장 페이지로 넘깁니다. 앱과 확장에 표시된 8자리 코드가 같음을 사용자가 확인한 뒤 계정을 확인하고 최종 연결을 승인합니다.

계정 확인에는 기존 로그인 프로필 안의 새 `https://x.com/home` 탭 하나만 사용합니다. 다른 사람의 프로필이나 오래된 X 탭에서 계정을 추정하지 않습니다. 본인 프로필 탐색 링크와 `twid`의 숫자 사용자 ID를 읽고, 탭 확인 전후 및 연결 직전에 로그인 쿠키가 같은지 검사합니다. 자동으로 만든 탭만 닫습니다. 브라우저 프로필 파일·다른 사이트 쿠키·X 비밀번호는 읽지 않습니다.

`BrowserSession`은 `auth_token`, `username`, `user_id`, `display_name` 및 저장 API용 `identity`를 반환합니다. 호출자는 취소 상태를 다시 확인하고 `login.save_authenticated_session(session.auth_token, session.identity, cancel=cancel)`로 저장합니다. 브라우저는 전달 결과만 표시하고 최종 암호화 저장 성공은 앱이 표시합니다. 이미 연결한 여러 계정의 선택은 앱의 계정 저장소가 담당합니다.

## 확장의 로컬 전달 경계

- 임시 포트를 고른 뒤 닫고 재사용하는 단계가 없습니다. Windows에서는 `SO_EXCLUSIVEADDRUSE`를 바인드 전에 설정해 다른 `SO_REUSEADDR` 소켓의 포트 공유를 막습니다. 바인드 실패 시 연결을 중단합니다.
- 연결마다 256비트 무작위 비밀을 생성해 URL fragment로만 확장에 넘깁니다. 확장은 즉시 fragment를 현재 기록에서 제거합니다. 비밀과 X 토큰을 HTTP URL·요청 헤더·로그·응답에 넣지 않습니다.
- 앱이 종료되거나 취소된 뒤 다른 프로세스가 같은 포트를 열 수도 있으므로 로그인 쿠키를 평문 POST하지 않습니다. 확장은 WebCrypto AES-256-GCM으로 계정 데이터를 암호화합니다. 비밀과 정확한 로컬 수신 주소를 문맥에 포함한 SHA-256으로 암호화 키와 별도 HMAC-SHA-256 키를 각각 유도합니다. 요청에는 nonce·암호문·GCM 태그·HMAC만 담습니다. 앱은 상수 시간 HMAC 검증 후 기존 고정 의존성 `gallery_dl.aes`의 AES-GCM 검증 복호화를 사용합니다. 다른 포트·다른 연결 비밀로는 복호화할 수 없습니다.
- 수신 주소는 IPv4 loopback 하나이며 Host·경로·브라우저 확장 Origin을 검사합니다. 일반 웹페이지의 교차 출처 요청과 CORS preflight는 허용하지 않습니다. 중복 보안 헤더·청크 전송·잘못된 길이·8 KiB 초과 본문을 거부하고 요청 읽기 시간을 제한합니다. 정상 결과는 한 번만 받으며 기본 3분·최대 5분에 만료됩니다.
- 쿠키 승인 UI는 웹에서 접근 가능한 자원으로 노출하지 않은 확장 자체 페이지에 있습니다. localhost 페이지에는 승인 버튼이 없고, 확장 페이지의 실제 사용자 입력만 승인합니다. 다른 페이지·하위 프레임·외부 메시지를 통한 확장 호출을 받지 않습니다. 쿠키는 확장 background 메모리에만 잠시 유지하고 디스크에 저장하지 않습니다.

loopback TCP 자체는 상대 프로세스가 LuvBox임을 증명하지 않습니다. 앱과 확장의 연결 코드 비교가 사용자의 실제 앱 요청을 확인하는 단계입니다. 같은 사용자 권한으로 프로세스 메모리·브라우저 확장·앱 파일을 수정할 수 있는 악성코드까지 격리하는 설계는 아닙니다. 확장이 아닌 페이지가 쿠키 승인 버튼을 흉내 내도 확장의 쿠키 읽기·전달 함수를 실행하지 못하도록 승인 페이지를 분리했습니다.

## 검증과 남은 확인

`python -m unittest tests.test_browser_bridge -v`로 loopback 경계·취소·만료·암호화·포트 바인드·일회성 연결과 확장의 합성 API 동작을 검사합니다. 선택적으로 Playwright와 Chromium이 설치되어 있으면 합성 X HTML/쿠키를 사용한 실제 확장 통합 검사를 실행합니다. 실제 네트워크의 X 로그인은 하지 않습니다.

이전 클라우드 환경의 Chromium 154는 관리 정책 `ExtensionInstallBlocklist: ["*"]` 때문에 개발 확장을 로드하지 못했습니다. 이런 통합 검사는 사유를 표시하고 건너뛰며 정책을 바꾸지 않습니다. 2026-10-22 Windows에서는 사용자의 명시적 확장 승인, 실제 X 계정 아이디 자동 반영과 실제 앱 재시작 후 연결 유지를 확인했습니다. 합성 세션으로 실제 DPAPI 저장·계정 선택·취소·연결 해제·별도 프로세스 재시작도 검증했습니다.

2026-10-23 기본 Chrome 새 프로필에서 확장 없는 파이프 통신과 취소·프로세스/프로필 정리를 확인했습니다. 실제 X 로그인은 앱 전용 창에서 제한 안내가 표시돼 인증 성공을 확인하지 못했습니다. 다른 환경의 로그인은 된다는 후속 확인이 있으므로 원인을 계정 제한으로 단정하거나 기다리기만 하면 해결된다고 안내하지 않습니다. 이번 시도를 닫은 뒤 기존 저장 연결은 유지됐습니다. Firefox 설치·연결과 확장 없는 경로의 실제 X 인증 성공은 별도 확인 대상이며, 기존 확장 경로의 결과로 통과 처리하지 않습니다. 자세한 범위는 [Windows 검증 기록](windows-validation-20261022.md)에 있습니다.
