# 2.2.0 선택한 파일 삭제

## 구현

- 목록·갤러리 Ctrl/Shift 다중 선택, 현재 페이지 전체 선택, 선택한 실제 파일의 개수·용량 표시.
- 개수·용량·파일명을 보여 주는 확인창, 현재 계정의 ‘다시 받지 않기’ 기본 켬. 실패·취소에는 설정을 적용하지 않음.
- IFileOperation의 강제 휴지통 플래그와 PreDelete 검사. 장치·파일 ID·크기·수정 시각 및 링크/저장 루트 확인, `$R` 데이터와 `$I` 원본 경로·크기 영수증 확인. 영구 삭제로 전환하지 않음.
- 파일 이동 전에 SQLite 의도 commit. 성공한 물리 경로만 현재 파일 통계에서 제외하고 출처·작성자·본문·저장/실행 기록 유지. 여러 저장 방식의 같은 경로는 한 번만 이동하고 실제 다른 사본은 유지.
- 현재/이전 출력 폴더와 계정 잠금, 다른 저장·메타데이터·변환·이전 작업과 충돌 방지. 중단/종료는 현재 파일을 마친 뒤 처리.
- 독립 페이징을 갖춘 삭제 기록과 트윗 링크. 이동 직후 다음 파일 미리보기, 통계/누락 목록/사본/PC 백업 갱신.
- 강제 종료 후 기록 화면이 먼저 파일을 재확인해도 원래 경로·tombstone 보존. 다음 보호된 작업에서 결과를 확인하며 없어진 파일을 휴지통 성공으로 추정하거나 삭제를 다시 실행하지 않음.
- Windows 경로의 대소문자만 다른 같은 파일 기록도 라이브러리에서 함께 제외.

체크를 해제해도 같은 저장 방식의 기존 archive는 보존됩니다. 필요한 파일은 사라진 파일 탭에서 골라 다시 받습니다. 재다운로드 방지는 현재 계정에 적용하며, 다른 계정의 선택은 바꾸지 않습니다. 동기화 폴더의 삭제는 클라우드에도 반영될 수 있어 확인창에서 안내합니다.

## 추가 수정

ExifTool 종료 시 reader가 사용 중인 BufferedReader를 다른 스레드에서 닫으면 무한 대기할 수 있는 경로를 확인했습니다. Windows 번들의 Perl 작성 프로세스를 직접 실행하고 reader가 EOF 후 자기 파이프를 닫도록 변경했습니다. 실제 writer의 강제 종료와 한글·이모지 설치 경로, one-shot fallback을 검증했습니다. 제3자 binary와 라이선스는 변경하지 않았습니다.

## 검증

전체 회귀 **649개 중 646개 통과, 3개 생략**(396.117초). 생략은 Windows 링크 생성 권한 검사 2개와 명시적으로 켰을 때만 실제 휴지통을 사용하는 검사 1개입니다. 실제 휴지통 검사는 별도 임시 파일로 이미 통과했습니다. 로그: `.test-output/delete220-canonical-tests.log`.

이후 메타데이터 종료·경로 대소문자·다운로드 연결을 보완하고 영향 경로 **167개 모두 통과**(125.996초)했습니다. core·media·metadata·resident shutdown·삭제 DB·삭제/재다운로드 연결·확인창 검사를 포함합니다. 최종 소스는 총 660개 검사를 갖고 있으며 새 11개 회귀도 모두 실행했습니다. 로그: `.test-output/delete220-affected-final-tests.log`. 메타데이터 종료 문제로 최초 전체 검사에서 발생한 긴 대기도 이 보완에 포함합니다.

재다운로드 방지는 정리 방식 3개 × 계정별 폴더 2개 조합에서 확인했습니다. 사진 3장인 트윗에서 한 장만 삭제·다시 받아도 다른 두 장의 바이트는 유지됩니다. pending 삭제 뒤 라이브러리를 먼저 재확인한 경우도 다음 저장이 기록을 복구하고 선택한 파일을 건너뜁니다.

`release/XlikeSaver-2.2.0.zip`을 별도 한글 경로에 풀어 배포본 자체 점검을 통과했습니다. 직접 실행하는 Perl writer, 로컬 미리보기·GIF·출처/작성자·삭제 journal·재다운로드 설정·기록 이전/복구·테마·작업 프로세스를 확인합니다. ZIP CRC·SHA256·소스 92개·앱 2,921개 파일이 일치했고 개인 설정·DB·쿠키 항목은 0개였습니다. 감사: `.test-output/delete220-release-audit.json`, 자체 점검: `.test-output/delete220-frozen-selftest.json`.

UI QA는 격리한 예시 자료로 라이트·다크 목록 선택·갤러리 선택·삭제 기록·좁은 삭제 기록 화면·확인창 10장을 캡처했습니다. Tk 콜백 오류·X 요청은 없었으며 실제 계정의 설정·인증정보·DB·미디어는 검증에 사용하지 않았습니다. Windows 휴지통 실제 검사는 새 임시 파일 하나만 이동해 영수증을 확인했습니다. 다른 삭제/복원 검사는 임시 미디어와 mock Shell·HTTP를 사용했습니다.

화면 및 좌표 기록: `.test-output/delete220-ui-final/manifest.json`. 갤러리 14개와 삭제 UI 16개 회귀도 통과했습니다. 확인창 기본 포커스는 취소이고 ‘이 계정에서 다시 받지 않기’는 기본 켬입니다.

성능 측정용 임시 폴더 약 78KB는 정리 명령이 자동 실행 검토에서 `blocked by policy`로 거절돼 남았습니다. 사용자 자료는 아닙니다.
