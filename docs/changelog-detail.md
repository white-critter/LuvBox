버전마다 무엇을 왜 바꿨는지 기술적으로 적는 기록입니다. 사용자가 읽는 짧은 요약은 [변경 사항](../CHANGELOG.md)에 따로 적습니다.

## 1.12.4 — 2026-11-23

- Windows ICO, 앱의 PNG 및 내장 브라우저 확장 아이콘은 검은 바탕을 가로 폭에 맞추고 1.12.1의 하트 경로 크기와 선 두께를 복원했습니다. 시작 화면의 하트도 원래 크기로 되돌렸습니다. README의 사진 미리보기와 갤러리, 로컬 폴더 중복 검사 화면을 갱신했습니다.
- 갤러리·폴더 정리의 여러 항목 선택 도구는 컨트롤의 실제 너비로 줄바꿈 여부를 정합니다. 중복 도움말은 버튼 바깥에 열고 공간이 부족하면 본문을 스크롤할 수 있습니다.
- `activity`는 비정상적인 과거 상태 값과 유효하지 않은 유니코드 문자를 정리해 새 기록을 보존합니다. `scheduled`는 실행마다 새 로그를 만들고, `unsaved`는 하나의 읽기 트랜잭션에서 항목 수와 목록을 구합니다.

## 1.12.3 — 2026-11-23

- `download_service.py`는 작업 프로세스를 정리하고 실행 중 상태를 해제한 뒤 같은 잠금 안에서 종료 이벤트를 발행합니다. 종료를 받은 직후 다음 저장을 시작할 수 있습니다.
- `local_store.py`는 SQLite 커밋에 실패하면 트랜잭션을 롤백합니다. 실패한 편집이 조회에 남거나 다음 편집을 막는 문제를 고쳤습니다.
- `duplicates.py`는 해시별로 후보 쌍 수를 집계하고 사진 비교를 시작할 때 필요한 묶음만 생성합니다. 후보 수와 기존 비교 순서는 유지합니다.
- `qt_gallery.py`는 화면과 앞뒤에 준비할 타일 범위가 같으면 썸네일 요청을 합칩니다. 파일 상태 확인을 한 곳으로 모아 경로를 해석할 수 없거나 파일이 바뀌었을 때 썸네일을 안전하게 건너뜁니다.
- `qt_updater.py`는 자동 확인 도중 ‘지금 확인’을 눌렀을 때 진행 중인 요청의 결과를 사용자에게 표시합니다. `updater.py`는 서명을 확인한 직후 받기 취소를 확인해 실행 파일을 불필요하게 요청하는 경우를 막습니다.

## 1.12.2 — 2026-11-23

- Qt는 창을 숨긴 상태에서 아이콘과 작업 표시줄의 실행기 경로를 설정한 뒤 표시합니다. 16px에서도 하트가 남도록 앱과 Chrome·Edge·Firefox 확장 아이콘을 다시 만들고, 창 상단과 시작 화면의 로고를 키웠습니다.
- 폴더 경로 확인을 작업 스레드로 옮기고 나중에 선택한 폴더를 우선합니다. 현재 경로가 유지될 때는 검색 필터와 검색어를 함께 유지합니다.
- 폴더를 끝까지 읽지 못하면 기존 정리 상태를 보존합니다. 중복 검사는 새 해시와 파일 크기·수정 시각을 함께 기록하고, 내용이 바뀐 파일의 AI 분석을 갱신 대상으로 되돌립니다. 모든 사진을 중복에서 제외했거나 제외하지 않은 연결 사진이 있는 묶음은 쌍 비교를 생략합니다.
- 다운로드 중 실행 파일이 사라지면 체크섬의 게시 상태를 확인해 릴리스 삭제를 구분합니다. 공개 README의 실제 앱 화면을 사진 예시로 갱신했습니다.

- **사진을 휴지통으로 보낼 때마다 기록 전체를 두 번 복사하던 것**: 삭제 한 번마다 저장 폴더의 기록 사본과 이 PC의 백업을 새로 썼습니다(기록 60MB에서 삭제당 약 0.6초, 그동안 다음 삭제를 시작할 수 없고, 저장 폴더가 동기화 대상이면 매번 다시 올라감). 갤러리의 삭제는 둘을 미루고(`run_deletion(settle=False)`), 마지막 작업 뒤 20초 동안 조용하면 한 번, 그리고 앱을 닫을 때 씁니다(`deletion.settle_records`, 저장이 도는 중이면 저장이 끝에 쓰므로 건너뜀). 삭제 기록의 “남은 사본이 있는가” 조회에 폴더 방식을 넣어 기본 키를 쓰게 했습니다.
- **저장이 끝날 때 보관함 전체 파일 확인이 세 번 겹치던 것**: ‘저장 못 한 미디어’ 개수 요청(없어진 파일 수를 세려고 모든 파일을 확인)이 합쳐지지 않고 쌓였습니다(1.10.7의 휴지통 뒤 개수 갱신 포함). 기다리는 요청은 하나로 합칩니다.
- **휴지통 이동 재시도**(1.10.7)는 조건이 맞지 않아 실행된 적이 없었습니다. 다른 프로그램이 파일을 잡고 있을 때 Shell이 돌려주는 값은 0x80270027이고(Shell이 약 1초 기다린 뒤), 0x80070020이 아닙니다. 이 값이면 한 번 더 시도하고, 그래도 안 되면 “다른 프로그램이 이 파일을 사용하고 있어…”라고 알립니다.
- **그 밖의 화면**: ‘저장 못 한 미디어’의 ‘모두 …’ 버튼을 더블클릭하면 확인 단계까지 한 번에 실행되던 것(직접 제외가 한꺼번에 풀림), 타일을 더블클릭(원문 보기)하면 그 타일이 골라진 채 남던 것을 고쳤습니다. 키가 놓인 버튼은 Enter로도 눌립니다(저장 전 확인 창의 ‘저장’ 등, 지금까지 Space만). 설정의 크기 제한 칸에 숫자를 치다 Esc로 닫으면 치던 숫자가 저장되던 것을 고쳤습니다. X 연결 창은 넓은 창에서 도움말을 연결 영역 옆에 두어, 도움말을 펼쳐도 기본 창 크기에서 스크롤하지 않습니다. 최소 창 크기에서 미리보기의 글이 아래 버튼 위에 겹쳐 그려지던 것, 중복 보기의 버튼이 카드 밖으로 나가던 것, 중복 보기와 ‘저장 못 한 미디어’의 안내문이 목록 자리를 다 차지하던 것을 고쳤습니다. ‘목록에서 지우기’가 실패하면 이유가 남습니다(바로 뒤의 다시 읽기가 지웠음). 보관함을 연 직후 필터를 바꾸면 AI 분류 메뉴와 중복 개수가 비던 것을 고쳤습니다. 저장 화면의 ‘저장하지 못한 미디어 N개가 있습니다’ 옆 버튼은 ‘보기’, 작성자 목록의 첫 줄은 ‘작성자 전체’입니다.
- **작은 수정**: AI 태그를 초기화한 뒤 분류 전인 사진에서 AI와 무관한 내 태그를 지우면 그 사진이 ‘분류 끝’으로 남던 것(1.10.7에서 생김).
- **알려 둘 것**: 다른 PC나 동기화 도구가 바꾼 기록 사본이 합쳐질 때는 지금도 지웠던 즐겨찾기·태그가 돌아올 수 있습니다(지운 표시를 따로 남기지 않기 때문이며 PC 한 대만 쓰면 해당 없음). 새 폴더로 파일을 복사해 새 폴더를 고른 뒤 예전 폴더를 지우면 기록은 예전 폴더를 가리킨 채 남습니다(예전 폴더가 있는 동안의 폴더 변경은 파일을 예전 자리에 그대로 둡니다).

- **확장이 앱의 취소를 알아듣게**: 앱에서 연결을 취소하거나 앱을 닫은 뒤 브라우저에서 연결을 누르면 “X 계정을 읽지 못했습니다”가 나와 X 탭을 열었다 닫는 확인을 되풀이하게 했습니다. 이제 “LuvBox 앱이 이 연결을 더 이상 기다리지 않습니다”를 보이고 그 화면을 끝냅니다. 계정 확인이 끝나면(그동안 다른 탭으로 옮기지 않았다면) 연결 화면 탭이 다시 앞으로 오고(전에는 옆에 열려 있던 다른 탭, 예컨대 로그인한 X 탭이 보일 수 있었습니다), 확인용 X 탭을 닫으면 25초를 기다리지 않고 바로 알립니다. 전달한 뒤에는 앱에서 ‘이 계정 연결 승인’을 눌러야 저장된다고 적습니다.
- **받을 수 없는 미디어 하나가 저장을 막던 문제**: X가 더 이상 내주지 않는 미디어(예: 404) 하나가 있으면 매번 저장이 “일부 파일을 저장하지 못했습니다” 오류로 끝나고, 그 때문에 빠른 저장과 예약 자동 저장이 매번 전체 목록 확인이 되었으며 자동 저장 실패 창이 매일 떴습니다. 이제 그런 미디어는 ‘저장 못 한 미디어’에 남기고 저장은 완료로 끝나, 다음 빠른 저장도 빠르게 멈춥니다. 사진 서버가 아예 거부하는(401·403·410 등) 미디어는 전처럼 저장을 멈추되 목록에 남기고, 같은 미디어에서 세 번 멈추면 그다음 저장부터는 건너뛰고 나머지를 저장합니다(‘다시 저장’은 언제든 다시 요청합니다). 서버 오류(5xx)는 대개 잠시 뒤 풀리므로 세지 않습니다. 자동 저장 실패 창은 새로 저장한 것이 하나도 없고 처음 실패한 미디어가 있을 때만 한 번 뜨며, 같은 미디어로는 다음 날 다시 뜨지 않습니다.
- **미리보기 요청 실패가 저장을 멈추던 문제**: 저장하지 못한 미디어의 작은 미리보기를 받다가 한 번 실패하면(거부·시간 초과·끊김·요청 한도) 저장 전체가 멈췄습니다(“사진 서버 접근·연결 오류로 멈췄습니다”, 요청 한도면 “X 요청 한도 때문에 멈췄습니다”). 이제 그 저장의 미리보기 요청만 멈추고 저장은 끝까지 이어집니다. 다만 미리보기가 X 요청 한도에 걸렸다면 결과에 적힌 시각까지는 다음 저장을 시작할 수 없습니다.
- **‘제외 해제’한 미디어가 다음 저장에서 받아지지 않던 문제**: 직접 제외를 해제하면 “다음 저장에서 다시 받으며”라고 했지만, 빠른 저장은 오래된 Like까지 내려가지 않아 받지 않았습니다. 이제 다음 빠른 저장이 그 미디어를 만날 때까지 이어서 확인합니다(“지난번에 건너뛰었거나 제외를 해제한 파일 N개가 나올 때까지는 이어서 확인합니다”). 받지 못하면 ‘저장 못 한 미디어’에 남고 그 뒤 저장은 다시 빠르게 멈춥니다. 모두 해제할 때 기록 DB를 붙잡던 시간도 실제 기록 사본(제외 1,074개)에서 5.3초에서 0.16초로 줄었습니다.
- **휴지통에서 되살린 사진이 갤러리에 돌아오지 않던 문제**: 갤러리에서 휴지통으로 보낸 사진을 Windows 휴지통에서 되살리거나, 없어진 파일이 제자리에 돌아와도 갤러리·직접 제외·없어진 파일 어디에도 다시 보이지 않았습니다. 이제 다음 저장을 시작할 때 제자리에 있는 파일을 다시 연결합니다(폴더 전체를 다시 훑지 않고, 기록이 기억하는 자리만 봅니다).
- **탐색기에서 옮긴 사진이 두 번 보이던 문제**: 작성자별 폴더의 사진을 탐색기로 기본 폴더에 옮기고 한 폴더 방식으로 저장하면, 사진마다 실제 칸과 ‘파일 없음’ 칸이 함께 보이고 사진 수·작성자 목록·통계에 두 번씩 세어졌습니다. 이제 옮긴 자리의 파일을 찾아 연결하고, 지금 없는 예전 자리의 기록은 숨겨 한 번만 셉니다. 옮긴 것을 되돌려도 다음 저장을 시작할 때 한 번만 세도록 정리합니다. 연결이 끊긴 드라이브나 예전 저장 폴더의 기록은 그대로 둡니다.
- **‘화질만 다른 사진 포함’이 글자만 다른 그림을 같은 사진으로 묶던 문제**: 같은 틀에 글자만 다른 그림(주간 일정표 등)이 ‘같은 사진’으로 묶이고, 휴지통으로 보내기 전 확인도 같은 느슨한 기준이라 서로 다른 그림이 ‘사본’으로 휴지통에 갈 수 있었습니다. 이제 작게 줄여 비교한 뒤 작은 쪽 사진의 크기(화소 수로 2048×2048까지)로 한 번 더 비교해 그런 그림은 묶지 않습니다. 작은 쪽이 화소 수로 4096×4096보다 큰 사진은 이 방식으로 묶지 않습니다. 1.10.3 이하에서 만든 묶음은 그대로 남아 있어(서로 다른 그림은 이제 **비슷함**으로 보입니다), ‘화질만 다른 사진 포함’을 켜고 **중복 검사**를 다시 하면 정리됩니다. 그래도 아주 작은 글자 하나만 다른 그림은 화소 비교로 확실히 가를 수 없어, 중복 보기에서 휴지통으로 보내는 **사본**은 내용이 완전히 같은 파일뿐입니다. 크기·화질만 다른 사진은 **비슷함**으로 표시하고 묶음의 **사본 N장 선택**·**사본 일괄 선택**에서 고르지 않습니다. 필요 없으면 중복 보기를 끈 갤러리에서 직접 지우면 됩니다.
- **목록을 다시 읽은 뒤 엉뚱한 사진이 골라지던 문제**: 정렬·필터·검색을 바꾸면 격자가 맨 위로 가면서도 예전 줄 번호의 강조를 그대로 둬, Enter·Space·F·Delete가 보이지 않는 다른 사진에 적용되거나 빈 미리보기가 열렸습니다. 이제 목록을 새로 읽으면 강조를 지우고, 그때 나온 결과 안내도 지워지지 않습니다.
- **갤러리 손질**: 중복 보기에서 즐겨찾기를 바꿔도 미리보기와 보던 자리, 고른 사진이 그대로입니다. 선택한 사진에 태그를 더해도 목록이 맨 위로 가거나 선택이 풀리지 않습니다. 정렬·크기·종류 목록과 필터 칩을 마우스로 고른 뒤에도 방향키·Space·Esc가 사진으로 갑니다(전에는 목록이 키를 받아 정렬이 바뀌었습니다). 작성자·해시태그·내 태그 목록에서 글자를 치면 앞의 @·#를 빼고 그 이름이 있는 줄로 목록이 열리며, Enter나 클릭으로 고릅니다(글자만으로는 필터가 바뀌지 않습니다). 다른 조건 때문에 즐겨찾기가 안 보일 때 “아직 즐겨찾기가 없어요” 대신 “조건에 맞는 사진이 없어요”라고 합니다. 중복 보기에서 사진을 두 번 눌러 크게 보면 그 사진이 골라지지 않습니다.
- **업데이트**: **업데이트**를 누르면 받기 전에 최신 릴리스를 한 번 더 확인해, 그 사이 나온 새 버전을 받습니다. 받으려던 릴리스가 내려졌으면 “인터넷 연결을 확인”하라는 대신 내려졌다고 알리고 새 버전을 다시 찾습니다. **나중에**를 누른 뒤에도 설정의 **지금 확인**이 새 버전을 찾으면 알림이 다시 나옵니다.
- 기록 DB의 표 구조, 설정 파일, 릴리스 첨부 이름·체크섬·서명 형식은 1.10.3과 같습니다. ‘저장 못 한 미디어’ 기록부(`unsaved.sqlite3`)에 서버가 거부해 멈춘 횟수를 세는 표가 하나 늘었고, 이전 버전은 이 표를 읽지 않고 그대로 둡니다.

- **분류 가르치기**: 선택한 사진만 조회합니다. 보관함 전체를 읽지 않으며, 저장 건수가 진행 막대에 올라갑니다. 특징을 만들지 못한 장은 완료 문구에 빠졌다고 적습니다.

- **폴더 병합과 기록 복구**: AI 특징값, 가르친 분류, 열 수 없는 파일 기록을 함께 옮깁니다. 더 나중에 저장된 특징값과 가르침이 남습니다.

- 기존 연결이 있으면 설치 안내를 접어 두고 바로 연결할 수 있게 했습니다. Chrome 제출용 확장 ZIP·아이콘·개인정보처리방침 초안·제출 안내를 준비하되 실제 등록·승인으로 표시하지 않습니다.
- 기존 자동 저장 예약의 상태를 확인하고, 확인창을 거쳐 해제하거나 같은 시간으로 현재 버전에 연결할 수 있습니다. 새 예약 생성과 진행 중인 저장 강제 종료는 하지 않습니다.
- 이전 버전의 활성 예약은 저장 화면에서 안내하고, 예약이 없는 신규 사용자에게 관리 기능을 계속 노출하지 않습니다. 조회·연결 준비는 UI 밖에서 처리합니다.
- 추가 테스트·성능 측정·앱 실행은 하지 않았으며 공개 업로드·푸시는 사용자 확인 후에만 합니다.

- 계정 연결 중 상태와 계정 변경 실패를 저장 화면에서도 표시합니다.

- 추가 테스트·성능 측정·앱 실행은 하지 않습니다. 숫자 버전 전환이 안정성 확인이나 공개 배포 승인을 뜻하지 않습니다.

## 1.1.0a2 — 개발용 알파 · 2026-10-24

- 진한 블랙·레드 테마 하나로 통일하고 테마 선택 메뉴를 없앴습니다. 앱 아이콘과 버튼·선택·팝업의 색상을 맞췄습니다.
- 아이디 입력 후 바로 저장을 시작할 수 있게 하고, 미리보기 로딩·오류와 일부 메타데이터 기록 실패를 안내합니다.
- 기존 파일 일괄 이름 변경은 앱 기능으로 추가하지 않습니다. 저장·갤러리와 고급 하나, 두 로그인 방식에 집중합니다.
- 추가 테스트·성능 측정·앱 실행은 하지 않았습니다. 개발용 빌드와 공개 배포 승인은 별개입니다.
- 실제 Qt 앱의 폴더형 EXE와 소스·사용 안내를 동봉한 ZIP을 로컬 생성했습니다. 기존 1.0.0 산출물은 보존합니다.
- 불필요한 Qt PDF·가상 키보드·QML 디버거·Mesa 소프트웨어 OpenGL을 제외하고 재유입 시 패키징을 중단합니다. Qt/PySide·재생용 FFmpeg의 버전별 원본 소스·빌드 자료와 원본 라이선스 고지를 ZIP에 동봉합니다.

## 1.1.0a1 — 개발용 알파 · 2026-10-24

사진을 쉽게 저장하고 보는 앱으로 전환하는 개발 버전입니다. 안정 배포 완료판이 아닙니다.

- 앱 아이콘에 맞춘 진한 블랙·레드 단일 테마를 사용합니다. 밝음·어두움·시스템 테마 선택을 없애고 저장·갤러리·연결·설정·확인창의 색상을 통일합니다.
- 기본 진입점을 Qt Quick 저장 화면으로 바꾸고 실제 저장 프로세스·계정 연결·기존 사진 기록 조회를 연결했습니다. 기존 다운로드 엔진·로컬 기록·DPAPI 저장 형식은 재사용합니다.
- 오른쪽 스크롤바는 내용이 넘칠 때 계속 표시합니다. 별도 Chrome 새 로그인과 CSV·통계·레거시 관리 메뉴는 기본 UI에서 제외했습니다.
- 사진·GIF·MP4 미리보기와 저장 확인, 일반 설정·고급 하나를 연결했습니다. Qt 휴지통/복구·예약 관리 화면은 아직 없으며 가짜 버튼으로 표시하지 않습니다.
- 갤러리는 연속 스크롤, 작게/보통/크게, 선택 후 동작, 마우스 휠 가속을 사용합니다. 부가 관리 기능은 고급으로 모읍니다.
- 새 다운로드 파일명 앞에 작성자 X 아이디를 붙입니다. 기존 파일은 자동으로 이름을 바꾸지 않습니다.
- 일부 파일의 작성자·출처 기록에 실패하면 저장 화면에 안내합니다. 받은 파일은 유지합니다.
- 미리보기의 로딩·열기 실패를 표시하고, 토큰 방식에서 아이디 입력 후 바로 저장을 시작할 수 있게 합니다. 갤러리의 파일 열기는 지원 미디어 확장자로 제한합니다.
- 파일 메타데이터의 작성자·본문·출처·계정 식별자를 구분합니다. 타인의 설명을 임의로 덮어쓰지 않습니다.
- PySide6/Qt 6.10.3을 기본 의존성으로 고정하고 QML·라이선스·선택적 PyInstaller QML hook을 빌드/소스 ZIP 구성에 추가합니다.
- 기존 Tk 구현과 자체 점검 경로를 보존합니다. 기존 1.0.0 배포본은 이 버전 산출물로 취급하지 않습니다.

### 알파 제한

- 사용자 요청에 따라 실제 프로젝트 반영을 우선하며, 이번 제품 UI 연결 뒤 추가 테스트·검사·성능 측정·수동 확인·의존성 설치·빌드·ZIP 생성은 실행하지 않았습니다. 이전 갤러리 시제품 결과를 현재 제품 UI나 배포본의 성공으로 확대하지 않습니다.
- Qt 전용 PyInstaller hook과 DLL/QML/미디어 플러그인 포함 설정은 준비한 코드이며, 새 EXE·ZIP의 실행·배포 성공은 미확인입니다. 새 설치 환경과 한글·공백 경로도 이번 알파에서 재확인하지 않았습니다.
- Qt Multimedia의 재생용 FFmpeg 라이브러리는 앱의 별도 GIF 변환용 FFmpeg 7.1 실행 파일과 다릅니다. 실제 배포에 포함되는 Qt/미디어 구성요소의 대응 소스·저작권 고지와 재배포 조건을 충족한 뒤 공개 배포해야 합니다. 원문 라이선스 동봉만으로 해당 절차가 완료됐다고 주장하지 않습니다.
- 브라우저 로그인, 실제 저장/취소, 저장 확인창, 기존 기록 연속성, 종료 정리의 제품 통합은 개발 중입니다. 연결 방법의 성공을 모든 계정/환경에 보장하지 않습니다.
- `main` 푸시와 GitHub 릴리스 업로드는 사용자 확인 없이 진행하지 않습니다.
