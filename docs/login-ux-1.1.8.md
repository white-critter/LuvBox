# LuvBox 1.1.8 로그인 개선

## 확인한 문제와 변경

1. 설치 안내는 Edge를 선택하고 실제 연결은 시스템 기본 브라우저를 여는 경로가 있었습니다. Chrome·Edge·Firefox 중 선택한 브라우저를 설치 안내·X 열기·연결에 공통으로 사용하고 마지막 선택을 보관합니다. 사용자 프로필 파일은 읽지 않으며, 브라우저가 선택한 일반 프로필을 화면에서 확인하도록 안내합니다.
2. 확장 미응답·X 로그아웃·계정 확인 중이 모두 같은 대기로 보였습니다. 확장이 암호화해 보낸 고정 단계와 남은 시간을 표시합니다. 8초 동안 응답이 없으면 설치·업데이트·프로필 도움말을 제공하며 확장이 없다고 단정하지 않습니다.
3. 처음 설치 안내가 재연결에도 기본으로 펼쳐졌습니다. 안내는 접고 연결 버튼을 먼저 표시합니다. 코드 확인 체크 후 계정을 자동으로 확인하고, 재확인 버튼·브라우저 동의·앱 최종 동의는 유지합니다.
4. 로컬 토큰 보관이 실제 인증 완료처럼 보였습니다. 보관·브라우저 확인·실제 비공개 X 목록 접근 확인을 구분하며, 토큰 보관만으로 연결창을 닫지 않습니다. 기존 저장 요청의 응답을 관찰하므로 시작 시 추가 접속이나 주기적인 계정 확인 요청을 만들지 않습니다.
5. 재연결을 취소하거나 같은 계정을 다시 선택하면 이미 확인한 만료 상태까지 초기화될 수 있었습니다. 기존 상태를 보존합니다. 성공한 새 연결은 이전의 인증 관련 오류만 지우고, 별도 저장 폴더·기록 오류는 보존합니다.

## 인증 상태와 보안 경계

- 비공개 Likes 응답이 성공하고 알려진 timeline 구조가 있을 때만 목록 접근을 확인합니다. 공개 사진·홈 화면·다른 API 성공은 인증 확인의 근거로 사용하지 않습니다.
- 명확한 인증 거부만 재연결로 안내합니다. 일반 403·요청 제한·서버 오류·통신 실패 때문에 연결 정보를 삭제하거나 만료로 바꾸지 않습니다.
- 단계 전달은 `/progress` 전용 키 문맥의 AES-GCM·HMAC으로 인증하며, 허용 단계·1 KiB 본문·128개 순서 번호·재전송 거부·기존 만료 시간을 적용합니다. 단계 응답이 사용자 동의를 대신하거나 대기를 연장하지 않습니다.
- 기존 `/session` 전달은 호환을 유지합니다. 앱이 확장 파일을 갱신한 뒤 브라우저 확장 관리에서 한 번 새로고침해야 새 단계 표시가 적용될 수 있습니다.
- 계정·설정·미디어·기록을 초기화하지 않습니다. 테스트는 합성 인증 정보와 임시 폴더를 사용하며 실제 사용자 계정의 로그인을 자동으로 수행하지 않습니다.

## 확장 없는 로그인 검토

별도 프로세스의 QtWebEngine 시험에서 네트워크 요청을 차단한 채 합성 화면·격리 메모리 프로필·Secure/HttpOnly 쿠키 처리를 확인했습니다. 실제 X 로그인·2단계 인증·계정 전환·재시작 후 연결 유지의 성공을 증명하는 검사는 아닙니다. QtWebEngine 핵심 DLL만 약 193 MiB여서 배포 크기·보안 업데이트·호환성 부담도 별도 검토가 필요합니다. 안정 배포에는 이 시험 코드·WebEngine 의존성·지원하지 않는 로그인 버튼을 넣지 않습니다.

정식 확장 스토어 배포는 발행자 등록·공개 지원 정보·개인정보처리방침·심사가 필요합니다. 이번 GitHub 릴리스에는 갱신된 Chromium 확장 패키지를 제공하고, 스토어 등록 완료로 표시하지 않습니다.

## 검증 기록

최종 테스트·실제 EXE·배포 ZIP 검증 결과는 [검증 기록](verification.md)에 기록합니다. 로그인 단계·취소·최종 승인·고급 토큰 입력은 실제 Qt 이벤트 루프에서 합성 계정으로 검증하며, 실제 X 인증과 구분합니다.
