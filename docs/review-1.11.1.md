# 1.11.1 검토·안정화 결과

검토일: 2026-10-06. 기준: `main`의 1.11.0 (`1a03321`).
UI 전면 개편과 2.0.0 변경은 다음 작업으로 남깁니다.

## 유지한 개선

Claude의 PC 내부 기록 DB + 저장 폴더의 검증된 사본 구조, 폴더형 배포, 기록 재확인의 불필요한 쓰기 제거는 유지했습니다. 페이징 조회는 합성 기록 1만 건에서 약 23–55ms라서 인덱스·검색 구조를 추가로 바꾸지 않았습니다. 경로 권한 확인도 기존에 페이지당 DB를 한 번만 여는 방식이라 캐싱을 추가하지 않았습니다.

## 재현하고 수정한 문제

| 영역 | 재현된 문제 | 수정 |
| --- | --- | --- |
| 기록 사본 | 일시적인 DB 잠금으로 합치기 실패한 외부 사본을 이미 읽은 것으로 표시하고 나중에 덮어씀 | 실패한 병합은 대기 상태로 유지. 내보내기 직전 재확인하며 정상 사본을 합치지 못하면 원본 사본 보존 |
| 기록 백업 | 같은 계정의 다른 저장 폴더가 같은 날 백업을 덮어쓰고 복구에 다른 기록을 섞음 | 계정 + 기록 폴더 식별값으로 백업 분리 |
| 복구 파서 | 잘린 정수를 0으로 만들거나 잘린 실수 한 건 때문에 복구 중단 | 불완전한 숫자·헤더는 잘못된 셀로 처리하여 건너뜀 |
| 모아보기 | 창 축소 후 사라진 열의 폭이 남아 150px 섬네일이 50px로 줄어듦 | 사용하지 않는 열 가중치 초기화 |
| 창 종료 | 갤러리 디코더와 예약 상태 확인 스레드가 닫힌 Tk 창을 계속 보유 | UI 참조 없는 작업자/이벤트 큐로 분리하고 Tk 자원은 UI 스레드에서 해제 |
| 기존 GIF 변환 | 변환 중 외부에서 바뀐 MP4를 휴지통으로 이동하거나 기록 복원이 실패한 GIF를 지움 | 원본 파일 상태를 다시 확인. 변경된 MP4와 DB가 참조하는 GIF 보존 |

과거 계정 단위 백업은 삭제하지 않습니다. 출처 저장 폴더를 확정할 수 없는 백업은 자동 복구에 섞지 않습니다.

## 성능·리팩토링

- 섬네일 모아보기는 단일 디코더가 최신 대기 페이지만 처리합니다. 같은 페이지 갱신은 타일과 Tk 이미지를 다시 만들지 않고 필요한 내용만 갱신합니다. 읽기 허용 여부와 파일 변경 여부는 매번 확인합니다.
- 같은 합성 페이지의 GUI 갱신 중앙값: 100개 **230.34 → 2.05ms**, 200개 **417.69 → 2.07ms**. 최초 로딩·디코딩·X 다운로드 시간을 포함한 수치가 아닙니다.
- 이미 저장한 파일 2,000개 로컬 재확인(같은 데이터로 변경 전/후 각 3회 교대 측정): 중앙값 **8.548 → 8.206초**, 약 **4%** 개선. DB 조회 **4,000 → 2,000회**, 파일 상태 조회 **110,158 → 104,158회**. 외부 통신·메타데이터 도구 기동 비용은 시험에서 제외했습니다.
- 다운로드 처리와 메타데이터 처리 사이에서 이미 읽은 기록을 재사용하고, 한 번 얻은 파일 상태를 사용해 중복 조회를 줄였습니다. 경로·링크·상위 폴더 검사는 그대로입니다(재확인 2,000개에서 8,000회).
- X 요청 간격, 재시도 정책, 요청 제한 보호는 변경하지 않았습니다. 갤러리와 예약 작업자의 UI 의존성만 분리했고, 2.0 개편에 앞선 대규모 모듈 재작성은 하지 않았습니다.

## 검증

기존 1.11.0 기준 테스트 436개 중 435개 통과, 1개 생략. 최종 통합 테스트는 총 457개 중 **456개 통과, 1개 생략**했습니다. 실제 FFmpeg·ExifTool의 GIF 변환·출처/작성자 기록과 소스 자체 점검도 통과했습니다. 배포 ZIP의 앱 폴더를 한글 경로의 별도 폴더로 풀어 실행한 1.11.1 설치본 자체 점검도 통과했습니다. 로그와 JSON은 `.test-output/review-1.11.1-*.log/json`에 남깁니다.

검증은 임시 기록·합성 미디어를 사용했습니다. 실제 사용자 저장 폴더·기록 DB·인증정보는 수정하지 않았고 X에 요청하지 않았습니다.
