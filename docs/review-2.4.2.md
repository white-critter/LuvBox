# 2.4.2 전체 코드 검토·안정화

검토일: 2026-10-08. 기준: `e6720e1`의 2.4.1.

## 검토 범위와 판단

앱의 모든 Python 모듈, 실행 진입점, 빌드·배포·런타임 준비 도구를 검토했습니다. 다운로드·로그인·요청 간격·암호화 연결 정보·메타데이터 도구·파일 변환·삭제·휴지통·예약 작업·화면 상태와 스레드 수명·DB 병합과 복구를 나누어 확인했습니다.

기존 SQLite 페이지 조회, 통계 재사용, 제한된 이미지 캐시, 단일 디코더, ExifTool 상주 방식에서 추가 성능 수정을 정당화할 문제는 찾지 못했습니다. 기존 최적화를 유지하며 오프라인으로 재현한 안정성 문제만 수정했습니다.

## 수정

1. **이전 형식의 백업 복구 누락**: 현재 DB와 백업의 열 전체를 합쳐 없던 열에 NULL을 넣으면 `NOT NULL DEFAULT` 제약으로 백업 행이 조용히 제외됐습니다. 행에 실제로 존재하는 열만 삽입해 기본값을 적용합니다. 같은 열 구성을 가진 연속 행은 일괄 삽입하며, 현재 DB가 중복 백업 행보다 우선하는 순서를 유지합니다. 실제로 손상된 명시적 NULL은 임의로 채우지 않습니다.
2. **경로 변경 시 최신 기록 사본 누락**: 로컬 DB가 있으면 다른 PC에서 받은 새 사본을 확인하지 않고 경로를 바꿨습니다. 원본·대상 폴더의 사본을 임시 복사본에서 먼저 합쳐 파일 내역과 다운로드 아카이브를 함께 옮깁니다. 원본 DB와 사본은 바꾸지 않습니다. 접근·잠금·병합 오류는 경로 변경 확정 전에 중단합니다.
3. **미리보기 실패의 영구 캐시**: 일시적 파일 접근·디코더 실패도 경로·크기·수정 시각으로 캐시해 새로고침해도 빈 이미지가 남았습니다. 성공한 이미지 결과만 캐시하며 실패한 파일은 다음 요청에 재시도합니다.
4. **로컬 작업 완료 순서**: GIF 변환·출처와 작성자 기록이 사본 저장 전에, 기록 복구가 잠금 해제 전에 완료 이벤트를 보냈습니다. 정리를 마친 뒤 알리도록 바꿔 완료 직후 종료나 다음 저장이 정리 중인 작업과 겹치지 않게 합니다.
