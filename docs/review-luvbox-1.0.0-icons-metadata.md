X 서버(`pbs.twimg.com`·`abs.twimg.com`으로 확인)는 `416 · Content-Range: bytes */<크기>`로 답합니다. 앱은 416을 일부러 실행 중단으로 다루므로 ‘서버가 이어받기를 거부해 멈췄습니다’로 멈췄습니다. 예약 자동 저장을 포함해 같은 파일에서 매번 멈추고, 사용자가 `.part`를 찾아 지워야 풀렸습니다. 확인 직전에 중단한 경우와 GIF(확인창이 변환 전 완료 표식보다 먼저 나옴)도 같았습니다.
- GIF 변환에만 쓰던 완료 표식(`.xlikesaver-complete`, 크기·수정 시각)을 확인창을 거치는 모든 미디어에 씁니다. 다 받은 직후, 확인창보다 먼저 남깁니다. 다음 실행은 표식이 맞는 `.part`를 요청 없이 그대로 쓰고, 확인을 켜 두었으면 다시 묻습니다. 저장하면 표식을 지우고, 건너뛰기·저장 안 함은 지금처럼 임시 파일과 함께 지웁니다. 표식이 없는 `.part`의 416은 지금처럼 멈춥니다(앱이 끝까지 받았는지 알 수 없음). 함수 이름은 `_transfer_complete`·`_mark_transfer_complete`로 바꿨습니다.

### 검증

- 실제 gallery-dl 다운로더로 재현했습니다. 사진을 확인창에서 중단한 뒤 다시 실행하면, 이전 코드는 416 요청 1회 뒤 오류로 끝나고 새 코드는 요청 없이 저장을 마칩니다.
- 새 검사 2개: 사진·동영상 각각, 중단 뒤 확인 없이 실행·다시 저장·이번엔 건너뛰기에서 요청 0회, 남은 `.part`·표식 없음, archive 결과를 확인합니다. 이전 코드에서 6개 모두 실패했습니다. 표식이 없는 다 받은 `.part`는 계속 416에서 멈추는지도 확인합니다.
- 관련 모듈: `test_interactive_save`·`test_review_app`·`test_media`·`test_core` 통과, `test_gif_conversion`은 기존과 같은 Windows용 FFmpeg 6개 외 통과.
- 전체 947개: 864개 통과, 41개 실패·오류, 42개 생략. 실패·오류 목록은 앞 단계와 같으며 모두 Windows 전용입니다. 실제 X 요청은 하지 않았고, 416 응답 확인만 공개 정적 이미지 두 개로 했습니다.
