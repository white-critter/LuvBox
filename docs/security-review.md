# 보안 경계와 검증

현재 제품은 PySide6 + Qt Quick 앱입니다. 이 문서는 지원하는 경계와 검증 방법을 설명합니다. 버전별 변경은 [CHANGELOG](../CHANGELOG.md), 최신 실행 결과는 [검증 기록](verification.md), 연결 절차와 암호화 상세는 [브라우저 연결](browser-login.md)을 참고하세요.

## 계정·설정·요청

- 계정 세션은 현재 Windows 사용자의 DPAPI로 암호화합니다. 토큰·쿠키·브라우저 프로필·개인 DB를 일반 설정·로그·Git·배포 파일에 넣지 않습니다. 연결 실패·취소는 기존 세션을 초기화하지 않습니다.
- 기존 세션의 읽기·해독·계정 목록 형식 오류를 빈 저장소로 간주하지 않습니다. 세션 파일이 실제로 없을 때만 새로 만들며, 읽을 수 없는 원본을 새 로그인으로 덮어쓰지 않습니다.
- 계정·설정은 경로별 Windows mutex 아래에서 읽기·수정·원자적 교체를 수행합니다. 잠금 획득 시간과 핸들 수명을 제한하고 비정상 종료한 소유자를 처리합니다. 설정 읽기·쓰기 실패 시 원본을 보존하며 성공하기 전에는 변경한 설정으로 저장을 시작하지 않습니다.
- 브라우저 확장 연결은 일회성 비밀과 사용자 코드 대조, 확장 자체 승인 화면, 앱의 최종 승인을 사용합니다. loopback Host·Origin·경로·본문 크기·만료·순서를 검사하고 AES-GCM과 독립 HMAC으로 세션과 진행 단계를 보호합니다. 앱은 기존 브라우저 프로필 파일을 직접 읽지 않습니다.
- 연결 서버의 요청 읽기는 헤더·본문 전체에 최대 0.75초 기한을 적용하고 연결 만료도 넘지 않습니다. 바이트를 조금씩 보내 소켓의 유휴 시간 제한을 계속 연장할 수 없습니다.
- 로컬 토큰 보관·브라우저 확인·실제 비공개 Likes 목록 접근 확인을 구분합니다. 명확한 인증 거부만 재연결로 안내하며 통신 실패·요청 제한·일반 403 때문에 연결 정보를 삭제하지 않습니다.
- API·미디어 요청의 간격과 리다이렉트에 요청 보호를 적용하고 HTTP·GraphQL 제한, 계정 잠금 및 서버가 지정한 재개 시각을 보존합니다. TLS 검증을 끄지 않습니다.

## 파일·미디어·작업 프로세스

- 공유 기록 사본의 `allowed_media_roots`는 이 PC의 파일 관리 권한으로 가져오지 않습니다. 외부 사본의 트리거·비정상 스키마를 거부하고 정상적인 로컬 폴더 이전으로 승인한 이력은 보존합니다. 이전 버전에서 이미 가져온 잘못된 로컬 승인값을 자동 판별해 제거한다고 보장하지 않습니다.
- 미리보기는 실제 디코더 형식을 제한하며 EPS 등 외부 렌더러를 부를 수 있는 형식을 확장자만으로 허용하지 않습니다. 링크·클라우드 전용 파일·디코딩 중 파일 교체를 거부하고 픽셀·출력 크기·처리 시간을 제한합니다. 사진 원본과 기존 메타데이터를 보존합니다.
- 래스터 미리보기와 원본 크기 조회는 압축된 입력도 64MiB로 제한합니다. 열린 파일의 크기와 디코더가 읽는 범위를 함께 검사해, 확인 뒤 커진 WebP 파일도 무제한으로 읽지 않습니다. 상한을 넘는 파일은 미리보기에서 제외하며 원본은 유지합니다.
- 갤러리와 저장 전 확인창의 GIF는 논리 화면의 한 변이 2,048px를 넘으면 긴 변 2,048px로 비율을 유지해 Qt에 디코딩을 요청합니다. 화면 크기는 GIF 헤더 10바이트만 읽으며, 그 확인에서 픽셀을 풀지 않습니다. 2,048px 이하의 GIF는 원본 프레임 크기를 유지합니다. 화면 정보가 작은데 압축 데이터가 매우 큰 GIF는 이 한도 밖에 있으며, 정지 사진의 64MiB 읽기 한도와는 별개입니다.
- 로컬 썸네일 캐시는 SQLite 조회에서 BLOB 형식과 1–262,144바이트 범위를 확인한 값만 읽습니다. 손상된 정수 값을 `bytes()`의 할당 크기로 해석하거나 큰 BLOB을 먼저 메모리에 복사하지 않습니다. 정상 썸네일은 150×112이며, 거부된 행은 원본에서 다시 생성해 교체할 수 있습니다. DB 스키마와 원본 파일은 바꾸지 않습니다.
- 저장 상세의 짧은 재시도는 Windows 공유·범위 잠금(32/33)으로 확인한 경우에 한정합니다. 최초 파일 서명을 고정하며 잠금 해제 사이 파일이 교체되면 표시하지 않습니다. Python이 일반 권한 오류만 반환하면 읽기 전용으로 최대 한 바이트를 확인해 잠금을 구분합니다. 영구 권한·손상·시간초과·클라우드 전용 오류를 무조건 반복하지 않습니다.
- 저장 상세의 임시 업로드 하드링크 예외는 실제 볼륨의 링크 이름을 열거하고 같은 상위 폴더에 속한 `.tmp.driveupload` 형태만 인정합니다. 다른 위치의 같은 폴더명과 일반 하드링크는 거부합니다. 이는 동기화 서비스의 신원을 인증하는 기능은 아닙니다.
- 동영상 미리보기 도구의 사용하지 않는 오류 출력은 버립니다. 손상된 영상의 반복 오류를 앱 메모리에 쌓지 않습니다.
- 외부 메타데이터 도구의 stdout·stderr와 줄 수를 제한합니다. Windows Job으로 도구와 자식 프로세스의 메모리를 제한하며, 상한을 넘으면 무제한 방식으로 재시도하지 않습니다. 실패 시 원본을 교체하지 않습니다.
- 메타데이터 초기 읽기·복사도 확인된 공유 잠금만 단계당 최대 1초 기다립니다. 파일 서명과 기존 20초 전체 상한을 유지하며, 추가 재시도 중 중단을 요청하면 저장된 원본·기록을 정리하는 기존 순서를 따릅니다.
- FFmpeg 변환도 별도 Windows Job으로 소유하여 저장 worker가 강제 종료되어도 변환 도구가 남지 않게 합니다. 변환에는 메타데이터 도구의 메모리 상한을 적용하지 않습니다. 프로세스 보호 초기화가 실패하면 변환 도구를 종료하고 원본 MP4를 보존합니다.
- GIF 변환 진단 파일이 1MiB를 넘으면 도구를 중단하고 원본 MP4를 보존합니다. 0.1초 주기 검사이므로 검사 사이의 초과 기록을 포함한 엄격한 디스크 상한은 아닙니다. 진단 원문은 사용자 오류나 로그에 노출하지 않습니다.
- worker IPC는 읽기·줄 길이 상한을 적용합니다. 진행 알림은 최신 상태로 합치되 저장·확인·오류·완료 이벤트의 순서를 보존합니다. 오래된 작업 결과와 닫힌 화면의 미디어 결과는 발행하지 않습니다.

- 파일 선택은 계정·갤러리 세대에 묶고 실제 파일·서명을 다시 확인한 뒤 Windows 휴지통으로 이동합니다. 결과가 불확실하면 자동으로 재삭제하지 않습니다. 누락 파일은 드라이브·권한·클라우드 확인 실패를 실제 누락으로 간주하지 않습니다.
- 직접 입력한 태그는 앞의 `#`와 ASCII 제어 문자를 제거한 뒤 50자 이하만 저장합니다. AI 분류 엔진이 한 묶음에서 실패하면 그 사진에 빈 분류 기록을 남기지 않아, 일시적인 오류가 다음 분류에서 영구히 건너뛰어지지 않습니다. 손상되었거나 용량·화소 한계를 넘는 파일은 크기와 수정 시각이 같은 동안만 다시 열지 않으며, 잠금·권한·파일 없음은 다음 분류에서 다시 시도합니다. 모델 다운로드의 User-Agent는 실행 중인 앱 버전을 사용합니다.

- 저장하지 못한 미디어의 미리보기는 앱이 시작한 저장에서만(`JobOptions.unsaved_previews`) 요청합니다. HTTPS의 `pbs.twimg.com`만 허용하고 사용자 정보·다른 포트·경로 이탈을 거부하며, 리다이렉트를 따르지 않고 JPEG·PNG·WebP 응답만 256KiB까지 읽습니다. 미디어당 1회, 저장 한 번에 200회까지이고 연속 3회 실패하면 그 저장에서는 더 요청하지 않습니다. 받은 바이트는 기존 미리보기 디코더(형식 제한·64MiB·화소 상한)로만 열며 어떤 실패도 저장 결과에 영향을 주지 않습니다. X의 로그인 쿠키는 이 호스트로 보내지 않습니다(쿠키 도메인이 다름).
- 중복 검사의 해시 캐시는 장치·파일 식별자·크기·수정 시각에 묶습니다. 열린 파일과 경로의 식별 정보를 대조하고 읽은 뒤 다시 확인하며, 해시 입력이 읽는 중 커져도 64MiB에서 중단합니다. 잘못된 지각 해시는 비교하지 않습니다. 중복 묶음은 원자적으로 교체하고 폴더 병합 시 서로 다른 검사의 묶음 번호와 로컬 파일 서명을 무효화합니다. 수정 시각과 파일 식별자까지 의도적으로 유지한 변조를 감지하는 보안 무결성 검증으로 해석하지 않습니다.

## 실행기와 업데이트

- `LuvBox.exe`는 실행기에 압축한 앱을 붙인 파일입니다. 실행기는 풀기 전에 붙은 앱 전체의 SHA-256을 파일 끝의 꼬리표와 대조하고, 확인부터 풀기까지 같은 파일 핸들을 쓰기 금지로 엽니다. 압축을 읽는 모든 곳이 이 핸들 하나를 쓰고 `LuvBox.exe`를 이름으로 다시 열지 않으므로, 그 사이 업데이트가 파일 이름을 바꾸고 새 파일을 놓아도 확인한 파일만 풉니다. 열었을 때 꼬리표가 시작할 때 읽은 것과 다르면 풀지 않고 다시 실행하라고 알립니다. 이 검사는 손상되었거나 받다가 끊긴 파일을 실행하지 않기 위한 것입니다. 꼬리표도 같은 파일에 있으므로 파일 전체를 바꿔치기한 경우를 가려내는 서명은 아닙니다.
- 풀 때 ZIP 항목 이름의 상위 폴더·절대 경로·드라이브·역슬래시·`:`·예약 이름·끝의 점과 공백을 거부하고, 최종 경로가 새로 만든 임시 폴더 안인지 확인합니다. 심볼릭 링크 항목을 거부하며, 앱 데이터의 `LuvBox`·`app`·버전 폴더가 junction 같은 링크면 풀지 않습니다. 임시 폴더에 다 푼 뒤 이름을 바꿔 완성하므로 중간에 끊긴 폴더는 실행하지 않습니다.
- 여러 실행기가 동시에 시작해도 잠금 파일로 한 번만 풉니다. 이전 버전 정리는 실행기가 남긴 표시가 있는 버전 폴더만 대상으로 하고 실행 중인 버전은 지우지 않습니다.
- 풀린 앱은 사용자 프로필 안에 있고 실행할 때마다 다시 검사하지 않습니다. 같은 사용자 권한으로 그 폴더를 바꿀 수 있는 프로그램은 막지 못하며, 이는 이전의 폴더 배포와 같은 수준입니다. Qt DLL은 그 폴더에 따로 남아 교체할 수 있습니다.
- 업데이트 확인은 GitHub의 공개 최신 릴리스 설명을 한 번 읽습니다. 요청에는 고정된 클라이언트 이름과 Accept만 넣고 쿠키·계정·기기 정보·현재 버전을 보내지 않습니다. 자동 확인은 하루에 한 번이며 끌 수 있고, 테스트·시작 검사·소스 실행은 스스로 접속하지 않습니다. 접속한 IP 주소와 시각은 다른 웹 요청과 마찬가지로 GitHub에 보입니다.
- 받기는 사람이 누를 때만 시작합니다. 주소는 버전에서 직접 만들고 HTTPS의 `github.com`·`*.githubusercontent.com`만 따르며 TLS 검증을 끄지 않습니다. 릴리스 설명은 1MiB, 체크섬 파일은 64KiB, 프로그램은 2GiB까지만 읽고 알린 길이와 받은 길이가 다르면 버립니다. 받는 중에 앱이 닫혀 남은 파일은 다음에 시작할 때 접속 없이 지우며, 10분 안에 손댄 파일은 다른 LuvBox의 것일 수 있어 남깁니다.
- 받은 프로그램은 SHA-256이 릴리스의 체크섬 파일과 같고 꼬리표의 버전이 그 릴리스와 같을 때만 실행기 자리에 둡니다. 체크섬 파일과 프로그램은 같은 릴리스에서 오므로 이 대조만으로는 전송 중 손상과 잘못 올라간 파일을 막을 뿐입니다.
- 1.9.2부터 체크섬 파일에 릴리스 서명 한 줄이 있고, 앱은 프로그램을 받기 전에 그 서명이 들어 있는 공개 키로 확인되는지, 이 버전과 이 체크섬 줄들에 대한 것인지 봅니다(RSA 3072, PKCS#1 v1.5, SHA-256). 서명한 블록 전체를 다시 만들어 통째로 비교하며 블록 안을 해석하지 않습니다. 개인 키는 관리자 Windows 계정의 키 저장소에만 있어, GitHub의 릴리스를 바꿀 수 있어도 그 키가 없으면 설치된 앱이 받는 업데이트를 만들 수 없습니다. 다른 버전의 서명된 파일을 가져다 놓는 것도 버전이 서명에 들어 있어 통하지 않습니다.
- 이 서명이 막지 못하는 것: 서명 키가 있는 PC나 Windows 계정이 탈취된 경우, 키 백업 파일과 그 암호가 함께 새어 나간 경우(백업은 `tools/release_key_backup.ps1`이 암호로 잠근 PKCS#8로만 만들고 프로젝트 폴더에는 쓰지 않습니다), 릴리스 페이지에서 처음 직접 받는 `LuvBox.exe`(Windows 코드 서명이 없으므로 체크섬 대조뿐), 서명을 확인하지 않는 1.8.0~1.9.1이 받는 업데이트. 키를 잃으면 이후 버전의 앱 안 업데이트는 멈추고 직접 받아야 합니다.
- 교체는 같은 폴더 안의 이름 바꾸기 두 번이며 둘째가 실패하면 되돌립니다. 실행 중인 앱은 자기 버전 폴더에서 돌고 있어 바뀌지 않습니다. 실행기 폴더에 쓸 수 없으면 바꾸지 않고 직접 받도록 안내하며, 관리자 권한을 요청하지 않습니다.
- 예약 작업과 작업 표시줄 고정은 실행기 경로를 가리킵니다. 앱이 환경 변수로 받은 실행기 경로는 실제로 앱이 붙은 `LuvBox.exe`인지 꼬리표로 확인한 뒤에만 씁니다.

## 빌드와 재배포

Python 3.12.16의 유출된 중간 CA 키 차단과 Expat 2.9.0 보안 수정을 포함한 런타임을 사용합니다. 준비·빌드는 각 계열의 최소 보안 버전(3.12.16·3.13.18·3.14.10·3.15.2)을 검사합니다. [Python 공식 보안 공지](https://www.python.org/downloads/release/python-31216/)를 기준으로 하며, 패키지 취약점 조회만으로 인터프리터 보안을 대신하지 않습니다.

고정 의존성과 Git LFS 입력은 버전·크기·SHA-256을 확인합니다. Python·QML·실행기 소스·배포 소스·번들 도구 입력과 의존성 버전을 PyInstaller 실행 전에 기록하고 빌드 후 다시 대조합니다. 이 기록에 EXE와 실행 폴더 전체 파일의 상대 경로·SHA-256을 결합하며 패키징 때도 대조하므로 소스만 수정한 뒤 이전 EXE와 묶거나 봉인 뒤 번들 QML·DLL을 바꿀 수 없습니다. 패키징은 `LuvBox.exe` 안의 ZIP을 풀어 파일마다 그 실행 폴더와 대조합니다. 소스 ZIP 압축 뒤에도 교체 직전에 다시 대조하고, 그동안 입력이 바뀌었다면 기존 배포 파일과 체크섬을 보존합니다.

Qt 시작과 오프라인 저장 초기화 보고서는 배포하는 `LuvBox.exe`를 실행기부터 실행한 것이어야 하고 현재 버전·그 파일의 해시와 일치해야 합니다. 풀린 앱만 직접 실행한 보고서로는 패키징하지 않습니다. 이 검사는 실행기가 격리된 폴더에 풀도록 실행하며 개발자의 앱 데이터를 쓰지 않습니다. 실행 폴더는 PyInstaller COLLECT 목록과 비교해 추가·누락 파일을 거부합니다. 프로젝트 소스는 명시적 허용 목록과 제한된 Python/QML 패턴만 포함하며 파일·상위 폴더의 심볼릭 링크·junction·hardlink를 거부합니다. 사용자 데이터·쿠키·프로필·개발 로그를 재귀적으로 수집하지 않습니다. Qt·FFmpeg·ExifTool의 원본 소스와 라이선스는 유지합니다.

Windows SSL·crypto DLL은 빌드 인터프리터의 원본 경로를 강제하고 실제 배포 파일의 SHA-256도 대조합니다. 같은 이름의 다른 PATH 도구 DLL과 COLLECT만 정상인 변조된 복사본도 거부합니다.

Qt 실행 검사와 직접 ZIP 패키징은 같은 보고서 검증을 사용합니다. 창 표시·갤러리·미리보기·대화상자·종료·격리 데이터 정리 중 하나라도 빠지거나 실패하면 패키징을 거부하며, QML 오류 목록도 명시적으로 비어 있어야 합니다.

## 검증과 한계

관련 회귀는 `test_browser_bridge`, `test_file_mutex`, `test_image_security`, `test_package_release`, `test_build_snapshot`, `test_launcher`(실제 실행기), `test_updater`(로컬 릴리스 서버), `test_release_contract` 및 파일 권한·미디어·설정 테스트를 포함합니다. 실제 Windows DPAPI를 쓰는 검사는 임시 경로와 합성 인증 정보를 사용합니다. 전체 명령과 실행 결과는 [개발 안내](development.md)와 [검증 기록](verification.md)에 있습니다.

고정 의존성의 알려진 공지 조회는 조회 시점과 버전에 한정됩니다. FFmpeg·ExifTool·Qt·Python의 모든 네이티브 코드에 대한 퍼징이나 취약점 부재를 보증하지 않습니다. 같은 사용자 권한으로 앱·브라우저·메모리를 수정할 수 있는 악성코드까지 격리하는 설계는 아닙니다. 실제 X 로그인·추가 인증·장기 실행과 확장 스토어 심사는 오프라인 테스트와 구분합니다. Windows 코드 서명은 제공하지 않습니다. 서명이 없는 실행 파일이 붙은 앱을 풀어 실행하는 방식은 Windows SmartScreen이나 백신이 경고하거나 막을 수 있으며, 이 프로젝트에서는 확인하지 못했습니다.

이전 구현의 TCP/DevTools 로그인 및 Tk 아이콘 검토는 현재 지원 경로가 아닙니다. 날짜별 원문은 [1.1.3 소스 기록](https://github.com/white-critter/LuvBox/tree/v1.1.3/docs)과 [1.2.0 소스 기록](https://github.com/white-critter/LuvBox/tree/v1.2.0/docs)에서 확인할 수 있습니다.
