# 보안 검토와 자동 미리보기 보완

2026-10-16, LuvBox 1.0.0 수정판. 재현에는 생성한 미디어·DB·쿠키 값과 격리된 임시 폴더만 사용했습니다. 실제 X 계정·개인 로그인·기존 휴지통·예약 작업은 사용하지 않았습니다.

## 재현한 경계 문제와 보완

| 경로 | 확인한 문제 | 보완 |
| --- | --- | --- |
| 공유 저장 폴더의 기록 사본 | 공격자가 공유 폴더에 기록 DB를 넣을 수 있으면, 첫 가져오기에서 `allowed_media_roots`와 파일 경로를 함께 지정해 출력 폴더 밖 파일도 관리 대상으로 인정하게 할 수 있었습니다. 실제 삭제에는 사용자의 선택·확인이 추가로 필요합니다. | 외부 사본의 경로 선언을 로컬 권한으로 가져오지 않습니다. 가져올 개인 사본에서 트리거도 제거하고 비정상 메타데이터 스키마를 거부합니다. 사본끼리 합칠 때도 같은 규칙을 적용합니다. 정상 로컬 폴더 이전으로 승인한 경로와 파일 이력은 유지합니다. |
| Edge 로그인 연결 | 앱이 고른 TCP 포트를 선점한 합성 로컬 서버가 가짜 X 세션을 정상 로그인 결과로 저장시키는 경로를 재현했습니다. 원격 단독 공격이나 실제 토큰 탈취를 재현한 것은 아닙니다. | HTTP 검색·TCP·WebSocket 연결 경로를 제거했습니다. 실행한 Edge에만 제한된 두 핸들을 상속하는 익명 파이프로 CDP를 연결합니다. 요청·응답 크기, 시간, 취소와 핸들 정리를 제한합니다. |
| 사진 미리보기 | EPS를 JPEG·임시 사진 파일로 위장하면 Pillow가 외부 Ghostscript 렌더러를 선택할 수 있었습니다. 별도의 Ghostscript 설치가 필요한 조건부 경로이며 현재 장치에는 없었습니다. | 원본 사진은 JPEG·PNG·WebP·GIF, 영상의 출력 프레임은 BMP, 보관 캐시는 JPEG·WebP로 실제 디코더 형식을 제한합니다. 확장자만으로 허용하지 않습니다. |
| 출처·작성자 기록 도구 | 작은 압축 PNG의 XMP 설명이 수 MiB로 팽창하고, 도구의 출력·파싱 메모리에 상한이 없었습니다. X 서버가 해당 메타데이터를 그대로 배포하는지는 검증하지 않았습니다. | stdout·stderr 각각 2 MiB·4,096줄로 제한하고 초과 시 도구를 종료합니다. 같은 입력을 무제한 출력 방식으로 재시도하지 않습니다. 단독 호출도 동일한 제한을 사용하며, Windows의 비공개 Job으로 도구와 자식 프로세스의 합계 메모리를 512 MiB로 제한합니다. 실패 시 원본을 교체하지 않습니다. |
| 배포 패키징 | 실행 폴더 전체를 압축하므로, 사용자가 그 안에 넣은 다른 파일도 재패키징에 들어갈 수 있었습니다. 직전 배포 파일의 개인정보 검사는 0건이었습니다. | PyInstaller의 COLLECT 파일 목록과 실행 폴더·번들 도구 소스 목록을 대조합니다. 추가·누락 파일과 링크·junction·hardlink가 있으면 압축 전에 중단하고, 검증한 파일만 포함합니다. |

공유 사본이 주장하는 이전 폴더는 이 PC에서 명시적으로 선택·이전하기 전까지 관리 권한을 얻지 않습니다. 이미 존재하는 로컬 DB는 정상 이전 이력과 구분할 수 없어 승인 경로를 유지합니다. 따라서 이전 버전에서 이미 가져온 잘못된 로컬 승인값을 자동으로 지운다고 보장하지 않습니다.

## 자동 미리보기와 아이콘

- 새 파일의 작은 미리보기는 사진·영상·GIF와 저장 폴더 정리 방식에 관계없이 다운로드 확정 때 보관합니다. 기록 DB 쓰기 실패와 미리보기 저장을 분리했습니다.
- 일시적인 캐시 잠금이 실행 전체의 미리보기 저장을 끄지 않습니다. 작은 이미지 최대 32개를 잠시 보관해 다음 파일·정상 종료·중단·건수 제한 종료 때 재시도합니다. 영구 쓰기 실패는 원본 다운로드를 유지하고 고정된 경고를 한 번 표시합니다.
- 기존 파일은 다운로드 목록에서 다시 만났거나 라이브러리에서 열어볼 때 부족한 미리보기를 보완합니다. 이미 보관한 이미지는 다시 디코딩하지 않습니다. 클라우드 전용 파일을 미리보기 때문에 내려받지 않습니다.
- 파일 관리의 수동 항목은 **이전 파일 미리보기 보완**, **이전 파일 출처·작성자 보완**으로 표시합니다. 새 파일은 자동 기록하며 이전 파일이나 실패 항목의 일괄 보완에 사용하는 기능입니다.
- Windows에서 Tk 내부 기본 아이콘과 모든 Tk/Toplevel 창의 작업표시줄 식별 정보를 함께 설정합니다. 창의 native wrapper가 다시 만들어지는 경우도 검사했습니다. 사용자 화면의 깃털 자체를 소스 실행에서 직접 재현하지는 못했으며, 기본 아이콘·독립 창의 식별 정보가 빠지는 경로를 재현해 보완했습니다. 사용자의 고정 바로가기·작업표시줄 설정은 변경하지 않았습니다.

## 검증 범위와 한계

실제 설치된 Edge 155.0.4283.45의 새 임시 프로필과 `about:blank`에서 파이프 통신·빈 쿠키·페이지 세션 연결을 확인했습니다. 브라우저 프로세스의 IPv4/IPv6 TCP LISTEN은 0개였고, 정상 종료·임시 프로필 삭제를 확인했습니다. 실제 X 로그인 과정은 수행하지 않았습니다.

Python 고정 의존성 15개의 설치 버전을 OSV API에 조회했을 때 알려진 취약점이 반환되지 않았습니다. 이는 OSV가 해당 버전에 연결한 공지의 조회 결과이며, 취약점이 전혀 없다는 증명은 아닙니다. 번들 FFmpeg 7.1·ExifTool 13.59와 Python에 포함된 모든 네이티브 라이브러리의 전체 취약점 부재를 보증하지 않습니다.

FFmpeg는 네트워크와 대부분의 디코더를 비활성화한 별도 빌드이며 MP4 입력 형식을 고정합니다. 예를 들어 [CVE-2026-40962](https://nvd.nist.gov/vuln/detail/CVE-2026-40962)의 CENC 복호화 경로는 앱이 복호화 키를 전달하지 않아 현재 호출 조건과 구분했습니다. [FFmpeg 보안 공지](https://ffmpeg.org/security.html)에 있는 모든 CVE를 버전 문자열만으로 이 앱의 원격 코드 실행 취약점으로 계산하지 않았습니다. 악성 MP4에 대한 네이티브 코드 전체의 영향 평가는 남아 있으며, 일반적인 정상 미디어·변환·중단 검증과 구분합니다.

코드 서명은 적용하지 않았습니다. 최종 전체 검사 수·UI·EXE·ZIP 검증 결과는 [검증 기록](verification.md)에 기록합니다. 개인정보가 없는 개발 로그는 `.test-output/`에 두며 배포 소스에 넣지 않습니다.
