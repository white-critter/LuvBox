# LuvBox 1.0.0 수정판 검토 · 건너뛰기 기억과 사라진 파일 탭 통합

2026-10-12. Codex의 `cbb752d`(아이콘·저장소 이름), `d3eb701`(휴지통 보내기 복구), `85364fb`(저장 전에 하나씩 확인)를 검토했습니다. 버전은 1.0.0 그대로이며 빌드·커밋·배포는 하지 않았습니다. 이 문서는 배포 ZIP에 포함하지 않습니다.

## 검토 결과

- 휴지통 보내기: 2.4.3에서 검증한 `deletion.py`·`recycling.py`를 거의 그대로 되살렸고, 빈 선택·중단·사라진 저장 폴더·휴지통 영수증 크기 제한이 보강되었습니다. 고칠 문제는 없었습니다.
- 저장 전에 하나씩 확인: 승인 전 최종 파일·archive·성공 기록을 남기지 않는 흐름, 디코더 핸들 해제 확인, 예약 실행의 무인 처리가 맞게 되어 있습니다.
- 문제 1 (속도): 건너뛰기가 하나라도 있으면 실행을 `partial`로 마쳐, 다음 ‘새 Like만 확인’이 전체 목록 확인으로 바뀌었습니다. 그 실행에서 다시 건너뛰면 또 전체 확인이 되어, 한 번 건너뛴 뒤에는 매번 전체 확인이 반복되었습니다. 안내도 ‘이전 확인이 끝까지 되지 않아’로 잘못 나왔습니다.
- 문제 2 (안정성): 제어 파일을 한 번 읽지 못하거나(백신 검사 등), 부모의 heartbeat 쓰기가 한 번 실패하면 저장 작업 전체가 멈췄습니다. 절전 복귀 직후에도 같은 일이 생길 수 있었습니다.

## 수정

- 건너뛴 파일은 `catalog_meta.review_pending`에 기억합니다. 다음 빠른 확인은 이미 저장한 파일이 이어져도 그 파일들에 닿을 때까지만 더 확인하고 평소처럼 멈춥니다. 저장·이미 있음·용량 초과·숨김으로 처리되면 지우고, 목록 끝까지 확인했는데 없으면(좋아요 취소) 지웁니다. 중단된 실행은 닿지 못한 항목을 그대로 둡니다. 값이 손상되면 그 실행만 전체 확인합니다.
- 제어 파일 읽기는 0.5초 동안 다시 시도하고, 오래된 heartbeat는 1.2초 동안 새 값을 기다립니다. 어떤 경우에도 승인으로 해석하지 않습니다. 부모의 heartbeat 쓰기 실패는 다음 초에 다시 쓰며, 파일 교체 재시도는 약 0.5초로 늘렸습니다.
- 사용자 질문(사라진 파일과 삭제 기록을 따로 둘 필요)에 따라 기록 창의 ‘삭제 기록’ 탭을 없애고 ‘사라진 파일’로 합쳤습니다. 휴지통으로 보낸 파일은 목록의 종류에 ‘휴지통’, 상세 카드에 ‘휴지통으로 보낸 때’와 복원 안내가 나옵니다. 탐색기에서 지운 파일은 ‘사라진 것을 안 때’로 구분합니다. 실패한 파일은 완료 안내에 이름과 이유를 3개까지 적습니다. 삭제 저널(`deletion_items`)은 중단 정리·병합·복구용으로 유지합니다.
- 도움말·README·사용안내·개발 안내를 맞췄고, `tools/ui_qa.py`는 삭제 기록 화면 대신 휴지통 표시가 있는 사라진 파일 화면을 캡처합니다.

## 저장 안 함 버튼 (사용자 요청)

- 확인창 위 줄은 이 파일의 선택(저장 · 이번엔 건너뛰기 · 저장 안 함), 아래 줄은 작업 전체의 선택(이후 자동 저장 · 전체 작업 중단)입니다. 기본 초점은 계속 ‘이번엔 건너뛰기’입니다.
- ‘저장 안 함’은 ‘다시 받지 않기’로 휴지통에 보낸 파일과 똑같이 기록합니다. 임시 파일을 지우기 전에 작은 미리보기를 남기고, 숨긴 사라진 파일(‘저장 안 함’ 표시, 저장하려던 위치)과 archive에 넣습니다. 다시 묻지 않고 예약 자동 저장도 받지 않으며, ‘다시 받기’로 언제든 받을 수 있습니다.
- 사라진 파일 다시 받기 중에 고르면 숨김만 켭니다. 버전은 1.0.0 그대로입니다.
