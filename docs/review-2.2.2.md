# 2.2.2 재검토와 속도 개선

검토·수정일: 2026-10-07. 기준은 `ab983b1`의 2.2.1입니다. 코드 전체를 다시 훑되, 이번에는 사용자가 실제로 기다리는 지점을 기록 2만·6만·12만 개의 임시 DB로 측정해 개선할 곳을 정했습니다. 정확성 문제는 2.2.1 이후 새로 발견하지 못했습니다.

## 측정과 개선

| 지점 | 원인 | 2.2.1 → 2.2.2 (12만 개) |
| --- | --- | --- |
| 페이지 넘기기·검색·정렬·필터 변경 | 바뀌지 않은 전체 통계·차트·사라진 파일 목록을 매번 모든 기록에서 다시 계산 | 약 3.3초 → 약 0.2초 |
| 목록 한 페이지 조회 | 트윗 본문까지 붙인 모든 행을 정렬한 뒤 100개만 사용 | 첫 페이지 0.58초 → 0.19초, 마지막 페이지 1.25초 → 0.31초 |
| 라이브러리 열기·새로고침의 전체 통계 | 기록 하나뿐인 파일도 여러 기록을 합치는 일반 경로로 처리, Row 객체 변환, 파일마다 날짜 정규식 | 2.69초 → 1.55초 |
| 저장 중 열어 둔 라이브러리 | 기록 수와 관계없이 2초마다 전체 다시 계산 | 마지막 불러오기 시간의 3배(2~30초) 간격 |

2만 개에서도 전체 통계는 0.51초 → 0.25초, 페이지 이동은 약 0.6초 → 0.1초 수준입니다.

## 결과가 같은지 확인한 방법

- 목록 조회: 예전의 한 번에 정렬하는 SQL과 새 두 단계 조회를 정렬 4종 × 검색·종류·작성자·기간 필터에서 모든 페이지를 이어 붙여 비교했습니다. 동점과 저장 시각 없음, Like 순서 공백을 포함합니다.
- 전체 통계: 예전 병합 구현을 검사에 그대로 두고, 같은 경로·대소문자만 다른 경로·빈 저장 시각·출처 상태를 무작위로 섞은 기록 400개에서 결과를 비교했습니다.
- 화면: 페이지·검색·페이지 크기 변경은 전체 통계를 다시 계산하지 않고, 새로고침은 다시 계산하는 것을 확인했습니다.

## 검증

- 전체 회귀 **676개 중 673개 통과, 3개 생략**(416.4초). 생략은 Windows 심볼릭 링크 생성 권한이 필요한 검사 2개와, 명시적으로 켰을 때만 실제 휴지통을 쓰는 검사 1개입니다. 로그: `.test-output/perf222-full-tests.log`.
- 새 회귀 검사 5개: 목록 조회 동등성, 전체 통계 빠른 경로 동등성, 화면 변경 시 통계 재사용과 새로고침 시 재계산, 자동 갱신 간격 계산과 메인 창의 적용.
- `build.ps1`로 `release/XlikeSaver-2.2.2` 폴더 빌드와 ZIP을 만들었습니다. 로그: `.test-output/perf222-build.log`.
- 배포본 감사: ZIP CRC·SHA256, 소스 94개·앱 2,921개 파일 일치, 개인 설정·DB·쿠키 항목 0개. ZIP을 한글 경로(`.test-output/2.2.2 단독폴더`)에 풀어 exe 자체 점검을 통과했습니다. 자체 점검은 바뀐 목록 조회와 삭제 기록 제외 조회도 실행합니다. 감사: `.test-output/perf222-release-audit.json`, 자체 점검: `.test-output/perf222-frozen-selftest.json`.
