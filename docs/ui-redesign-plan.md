# LuvBox UI 재설계 계획과 이어받기

기준: 2026-10-23 사용자 결정, 2026-10-24 구현 진행. `main` HEAD `7bfbf15` + 보존된 로컬 미커밋 변경.

**목표는 관리 도구가 아니라 사진을 쉽게 저장하고 보는 앱이다.** 이 문서가 이전 Windows 인수 문서의 UI·로그인 방향보다 우선한다. 다른 코딩 에이전트는 이 문서와 `WINDOWS_CONTINUE.md`를 먼저 읽고, 아래 진행 상태를 확인한 뒤 작업한다.

## 현재 개발 지시 — 실제 제품 전환

2026-10-24 사용자는 시제품 검증 반복보다 실제 프로젝트 반영을 우선하도록 지시했다. 이후 1.1.1의 실제 실행 오류를 보고하고 **실제 EXE 실행 확인이 필요함을 명시**했다. 반복 성능 측정이나 전체 회귀를 자동으로 재개하지 않되, 시작 오류 관련 회귀와 실제 frozen EXE의 최소 실행 확인은 필수로 한다. 빌드만 성공한 상태를 실행 성공이라고 취급하지 않는다. 과거 검사 결과는 해당 소스 시점의 기록으로만 보존한다.

현재 **1.1.2** 소스 반영 (이전 실제 Qt 연결을 계승; 이후 버전은 숫자만 사용):

- `entry.py` 기본 실행은 `luvbox/qt_app.py`의 실제 Qt 앱. `--worker`·`--run-saved`는 기존 엔진을 유지하며, 이전 Tk 화면은 `--legacy-ui`로 보존한다.
- `assets/qt/MainWindow.qml`에 실제 저장 기본 화면·계정/폴더·시작/중단·간단한 진행·갤러리·설정을 연결했다. `GalleryPreview.qml`은 같은 화면을 쓰는 이전 도구 호환 래퍼다. 사용자에게 시제품 실행을 다시 요청하지 않는다.
- `download_service.py`/`qt_download.py`는 기존 별도 작업 프로세스와 JSONL·중단·저장 확인·종료 정리를 UI에서 분리한다. 엔진을 Qt 스레드에서 직접 실행하지 않는다.
- `app_settings.py`/`qt_accounts.py`는 기존 설정의 알 수 없는 키와 DPAPI 연결을 보존한다. 현재 UI의 로그인은 기존 브라우저 확장 연결과 토큰 입력 두 가지다. 별도 Chrome 새 로그인은 노출하지 않는다. 확장 자동 설치/스토어 배포가 해결됐다고 주장하지 않는다.
- `qt_library.py`는 실제 계정/저장 위치의 SQLite를 읽기 전용 작업자에서 조회한다. 검색·종류·정렬·선택·원본 파일/폴더/원문 열기를 연결한다. 아래의 사용자 요청 일회성 파일 변경은 앱 기능과 분리한다.
- `MediaPreview.qml`/`SaveReviewDialog.qml`은 사진·GIF·MP4와 저장/건너뛰기를 연결한다. 미디어를 해제한 뒤 응답하고, 닫기는 중단이다. 계정·다운로드·라이브러리·설정 작업 종료를 기다린 뒤 앱을 닫는다.
- 필수 흐름 보완: 미리보기 로딩·실패 표시, 수동 아이디 입력 직후 저장 버튼 활성화, 중복 계정 갱신 생략, 갤러리 파일 열기의 미디어 확장자 제한. 추가 테스트나 앱 실행은 하지 않았다.
- 1.1.0부터 접미사 없이 숫자 버전만 사용하며 Windows EXE의 파일·제품 버전도 기록한다. 계정 작업 상태·실패는 저장 화면에서도 표시한다. 과거 접미사 빌드와 기록을 삭제하거나 이름만 바꿔 덮어쓰지 않는다.
- 계정 작업은 완료 이벤트와 작업자 종료가 모두 확인될 때까지 busy를 유지한다. 완료 상태 읽기·설정 저장은 작업자에서 수행하고, 시작하지 못한 토큰 입력을 보존한다. 로그인 성공과 계정 선택/해제를 분리해 해제 후 다른 계정이 남았다는 이유로 연결 창이 닫히지 않게 했다.
- 1.1.1은 연결창에서 기본 Chrome·Edge 확장 관리 열기·폴더 경로 복사·X 열기를 제공한다. 여전히 처음 한 번 직접 설치해야 하며 자동 설치나 스토어 등록을 했다고 안내하지 않는다. Chrome 제출용 ZIP·아이콘·개인정보처리방침 초안·제출 문서는 준비하되 게시하지 않는다.
- 1.1.2는 QtCore가 요구하는 Windows ICU 대신 빌드 PATH의 Poppler ICU가 동봉된 원인을 수정한다. System32 우선 수집·ICU 오염 차단·실제 EXE 시작 게이트를 추가했다. `entry.py --qt-smoke REPORT`는 임시 계정/사진 기록과 비활성 예약 스텁을 사용해 Windows 실제 창·이미지·팝업·종료만 확인한다. 사용자 데이터/실제 인증/작업 스케줄러를 읽거나 변경하지 않는다. ZIP 생성 시 성공 보고서와 EXE 해시도 요구한다.
- 이번 수정 확인: 관련 회귀 30개 중 28개 통과·기존 링크 환경 의존 2개 생략. 실제 frozen 1.1.2와 ZIP에서 한글·공백 경로에 추출한 동일 EXE 모두 Windows/Direct3D11 창 표시, 갤러리 썸네일·사진 미리보기, 설정/예약 확인창/연결창, 종료와 임시 데이터 정리를 통과했다. QML 오류는 없었다. 보고서는 `build/qt-startup-1.1.2.json`과 `build/qt-startup-1.1.2-extracted.json`이며 배포물에 개인 로컬 보고서를 동봉하지 않는다. 실제 X 인증·다운로드·예약 변경은 이번 확인 범위가 아니다.
- `qt_schedule.py`는 기존 예약만 읽고, 확인창을 거친 해제/현재 버전 연결만 수행한다. 시간은 유지하고 꺼진 예약을 켜지 않으며 새 예약 생성·진행 중인 저장 강제 종료는 하지 않는다. 앱 종료 시 두 새 작업자도 마무리한다. 기존 이전 버전 활성 예약만 저장 화면에서 안내한다.
- `ConnectionDialog.qml`/`PreferencesDialog.qml`: 짧은 연결 창과 일반 설정, **고급 하나**. CSV·통계·레거시 관리 기능은 기본 UI에서 제외했다.
- 사용자는 가속감이 자연스럽다고 확인했다. 이어서 제보한 **오른쪽 스크롤바 숨김**은 기본 스타일의 자동 fade를 없애고 내용이 넘칠 때 항상 표시하는 정책으로 변경했다. 사진 이동 문제로 오해해 디코더를 다시 바꾸지 않았다.
- 버전/기본 Qt 요구사항/선택 QML hook/라이선스/소스 ZIP 구성을 갱신하고 1.1.0a2의 폴더형 EXE·소스 동봉 ZIP을 로컬 생성했다. README와 사용 안내의 이전 내용은 별도 레거시 문서로 보존했다. 앱 실행·추가 테스트는 하지 않았다.
- 배포 수집에서 미사용 PDF·가상 키보드·QML 디버거/Quick3DUtils·선택적 Mesa를 제외했다. 버전 고정 원본 소스 11개와 원본 고지 478개를 준비해 ZIP에 동봉한다. `tools/qt/README.md`가 실제 구성과 소스·빌드 자료 대응표이며 생성된 대용량 자료는 Git에서 제외하고 ZIP에 명시적으로 포함한다. 공개할 때 바이너리와 같은 버전의 소스·고지를 함께 제공해야 하며 자동 업로드하지 않는다.

추가 우선순위: 실제 저장·연결·갤러리의 막히는 부분과 배포에 필요한 구성은 충분히 마무리하되 불필요한 반복은 피한다. Qt 휴지통/복구·새 예약 생성 등 부가 기능은 보류한다. 기존 예약 상태/해제/현재 버전 연결은 구버전 사용자 호환에 필요한 최소 기능으로 진행한다. **기존 파일 일괄 이름 변경은 앱 기능으로 만들지 않는다.** 사용자의 별도 요청에 따른 실제 파일 일회성 변경은 아래 기록처럼 완료했고, 일반 앱 실행에서는 예전 파일을 자동 변경하지 않는다. 없는 기능을 회색 버튼이나 가짜 성공으로 대신하지 않는다. 이전 `release/1.0.0`을 현재 Qt 배포본으로 안내하지 않는다. 사용자 확인 전 커밋·푸시·공개 업로드하지 않는다.

2026-10-24 일회성 작업 완료: 중복된 기록 행을 제외한 기존 실제 파일 5,409개에 작성자 아이디를 붙이고 로컬 기록과 저장 폴더의 기록 사본 경로를 함께 갱신했다. 작성자 기록이 충돌하는 13개는 변경하지 않았다. 파일 덮어쓰기·미디어 내용 수정은 하지 않았다. 기록 백업·이전/새 이름 목록·작업 저널은 해당 PC의 `%LOCALAPPDATA%/LuvBox/backups/filename-author-20261024-113403`에만 보관하며 저장소나 배포물에 포함하지 않는다. 일회성 스크립트도 임시 폴더에만 있으며 제품 기능으로 추가하지 않았다.

## 사용자와 확정한 결정

- UI는 **PySide6 + Qt Quick**으로 전환한다. CustomTkinter를 추가하지 않는다.
- 앱 버전은 **숫자로 된 주.부.수정** 형식만 사용한다. 숫자 버전과 안정성 확인·공개 배포 승인은 별개다.
- 사용자 추가 결정: 테마는 앱 아이콘에 맞춘 **진한 블랙·레드 하나**만 제공한다. 밝음/어두움/시스템 선택은 없애고 기본 배경·버튼·선택·설정·연결·미리보기·폴더 선택을 같은 팔레트로 통일한다. 기존 설정 파일의 과거 테마 키는 보존하되 Qt UI에서 사용하지 않는다.
- 앱 시작 화면은 **저장**. 주요 화면은 **저장 / 갤러리**, 설정은 별도 진입점이다.
- 부가 기능을 여러 고급 메뉴로 쪼개지 않고 **고급 하나**로 모은다. 필요 없는 기능은 제거한다.
- CSV·통계·이전 파일 보완·계정 기록 합치기를 기본 화면에 노출하지 않는다. 핵심은 연결 → 저장 → 보기다.
- 설명은 짧고 핵심만. 선택 전 파일 작업 버튼을 나열하지 않고, 선택한 뒤 관련 동작만 표시한다. 아이콘만으로 의미를 추측하게 하지 않는다.
- 갤러리는 페이지 버튼 없는 연속 스크롤. 보이는 사진과 가까운 사진만 로딩한다. **작게 / 보통 / 크게**를 제공하고 크기 변경 시 보던 항목을 유지한다.
- 로그인은 최종 UI에서 **두 가지 방법만** 제공한다. 검증되지 않은 Chrome/Edge 새 로그인은 기본 기능에서 제외한다. 어떤 두 방법을 남길지는 아래 제안과 남은 결정을 구분한다.
- 새 파일명은 작성자의 `@` 뒤 아이디를 앞에 붙인다. 예: `artistname_1234567890123456789_1.jpg`. 표시 이름이나 숫자 계정 ID가 아니다. 기존 파일은 앱에서 자동 이름 변경하지 않는다. 구·신 파일명을 함께 인식하며 기존 기록과 이어받기를 유지한다. 일괄 변경 UI는 만들지 않으며 사용자 요청에 따른 기존 파일 일회성 작업과 구분한다.
- 파일 메타데이터는 작성자·게시글 본문·원본 링크·숫자 계정 ID를 분리한다. 본문 설명란에 출처·작성자 안내를 다시 합쳐 넣지 않는다. 타인이 기록한 원본 메타데이터를 임의로 덮어쓰지 않는다.
- GitHub 릴리스 업로드, `main` 푸시는 결과를 제시하고 사용자 확인을 받은 후에만 진행한다. 지금은 커밋·푸시·업로드하지 않는다.

## 현재 사실과 남은 결정

- 기존 다운로드·SQLite·DPAPI·작업자/미디어 엔진을 재사용한다. UI 교체를 이유로 전체 엔진을 다시 작성하지 않는다.
- 현재 `entry.py`는 1.1.0a1 Qt 앱 소스로 전환했다. 아래 전체 검사 수와 시제품 결과는 각각 이전 소스에서 얻은 기록이지 이번 제품 통합 결과가 아니다.
- 기존 Tk 갤러리는 이미 가시 영역 가상화·캐시 제한을 한다. Windows 10,000개 조건의 heartbeat p95 115.183ms/최대 629.262ms가 남았고, 가로줄처럼 보이는 끊김의 정확한 원인은 미확정이다.
- 다른 브라우저 환경에서는 X 로그인이 된다는 사용자 확인이 있다. 새 Chrome 경로에서 나온 제한 문구를 계정 전체의 X 일시 제한으로 단정하지 않는다. 원인은 앱 전용 로그인 환경과 분리해 조사해야 하며 제출을 반복하거나 탐지 우회 플래그를 추가하지 않는다.
- 로그인 두 방법의 현재 제안은 **기존 브라우저 연결(확장)**과 **직접 입력**이다. 두 방법만 남긴다는 것은 승인됐지만 이 조합 자체는 추가 확정 대상이다. 개발자 모드로 확장 폴더를 고르는 설치는 초보 사용자용 완료 상태가 아니다. 정식 스토어 배포는 별도 승인·검토 대상이다.
- 본문을 넣을 설명란에 타인의 기존 설명이 있으면 보존을 우선하고 충돌 상태를 기록한다. 본문은 앱 DB에 유지한다. 이 경우 파일에도 본문이 기록됐다고 표시하면 안 된다.
- 직전 `release/LuvBox-1.0.0*`는 **재설계 이전 Tk 빌드**다. 새 소스 변경 뒤에도 이 산출물을 현재 소스의 Qt 배포본으로 소개하지 않는다.

| 위치 | 기본 구성 |
| --- | --- |
| 저장 | 연결 계정, 저장 위치, 시작/중단, 짧은 진행 상태 |

## 작업 순서와 완료 기준

### 2026-10-24 빠른 주입 휠과 Qt 배율

같은 속도보다 더 큰 이벤트, 휠 30칸, 중앙값 1,883px, 약 8행에서는 준비 최소가 0이었다. 그때 창 버퍼 `qt-wheel-fast-during-1.png`는 캡션만 있고 사진이 비어 있다. 두 행 속도의 `qt-wheel-row-during-2.png`는 위 행이 비고 아래 행에는 색 타원이 있다. 버퍼를 저장한 실행은 프레임 콜백이 한 번 250ms까지 벌어졌다. 저장하지 않은 실행의 프레임 최대는 18ms다.

`QT_SCALE_FACTOR=1.5`는 이 프로세스만의 배율이다. 창은 `27QAF65CE`로 갔고 Qt가 보고한 화면은 1707×960, 장치 픽셀 배율 1.5, 논리 DPI는 그대로 96이다. 물리 DPI는 72.5로 줄어 보이는데, Qt가 배율로 나눈 값이다. Windows 150%가 아니다. 이 배율에서는 보이는 칸의 디코드 크기를 장치 픽셀에 맞춰, 첫 화면 17칸이 34번이 아니라 17번 디코드된다. 17장 캐시는 1,718,400바이트로 배율 1의 1,198,080바이트보다 크다. 버퍼를 찍지 않은 1.5배 휠은 준비 평균 0.999, 최소 0.917, 빈 표본 1개, 이동 중앙값 480px다. 버퍼를 찍은 실행은 최소 0.25였고 `qt-wheel-150-end-during-2.png`에 가운데 행이 비어 있다. 그 저장이 프레임을 105ms 멈춘 뒤의 장면이다.

### 2026-10-24 Windows 150%

두 모니터를 Windows 배율 150%로 올린 뒤 같은 빠른 주입 휠을 실행하고, 끝나자마자 둘 다 100%로 되돌렸다. 되돌린 뒤 읽은 값은 둘 다 100%다. 로그아웃은 없었다. `QT_SCALE_FACTOR`는 쓰지 않았다. 미리보기 프로세스가 배율을 바꾼 것은 아니므로 그 JSON의 `os_display_scale_changed`는 false다. 배율 변경은 바깥 프로브가 했다.

실행 중 Windows가 보고한 배율은 150%였다. Qt 화면은 `27QAF65CE`, 논리 1707×960, 장치 픽셀 배율 1.5, 논리 DPI는 96이다. Qt 6은 이 배율을 장치 픽셀 비율로 들고 논리 DPI를 96에 둔다. 첫 화면 17칸은 17번 디코드됐고 캐시는 1,718,400바이트다. 휠 중앙값은 480.5px. 준비 평균 0.990, 최소 0.333, 빈 표본 3개. 방향키는 0에서 16, 크기 변경은 위쪽 6·6·4와 세로 174·578·228px로 배율 1과 같은 행을 유지했다. 결과 파일은 `qt-wheel-os150.json`.

창 버퍼 `qt-wheel-os150-end-during-2.png`에는 일부 칸만 색 타원이 있고 나머지는 비어 있다. 그 저장이 프레임을 109ms 멈춘 뒤의 장면이다. 사람이 굴린 휠도, 모니터를 직접 본 장면도 아니다.

다음 작업 우선순위:

1. **다음은 사람이 모니터를 보면서 빠른 휠을 굴리는 것**이다. Windows 150%의 주입 휠과 창 버퍼로 가로줄이 없어졌다고 쓰지 않는다. 그 확인 뒤에만 P3로 간다.
2. cacheBuffer를 키워 빠른 휠의 빈 칸을 메우지 않는다. 크기 변경이 맨 위로 돌아가던 현상은 스크롤 좌표 기준으로 고쳤다.
3. Qt 최종 배포 버전을 검토할 때 Property 최소 재현의 종료 경고도 비교한다. 6.10.3에서 최소 재현됐다는 사실을 보존하고, 실행 중 누수 여부는 별도 RSS/객체 수 추적으로 판단한다.
4. ledger와 catalog가 없고 작성자 아이디도 이전 값으로 찾을 수 없을 때, 다른 접두사 파일은 재사용하지 않는다. `former_801_1.jpg`는 바이트 그대로 남고 `renamed_801_1.jpg`만 새로 받는다. 검사는 `test_other_author_prefix_is_left_alone_when_records_and_author_id_are_gone`. 현재/무접두사 파일명을 넘어 임의 파일을 추정하는 코드는 추가하지 않았다.

이 단계에서 새 EXE/ZIP을 만들거나 Git 커밋·푸시·업로드하지 않았다. 이전 release는 이전 소스의 Tk 산출물이다.

### 2026-10-24 P2 가시 요청 정확성 회귀

사용자에게 실제 휠 확인을 요청하기 전 읽기 전용 동료 검토와 실제 QML 회귀로 다음 문제를 찾고 수정했다.

1. 위로 스크롤할 때 마지막 가시 행의 첫 열만 요청했다. 같은 행 나머지 사진은 음수 lookahead에도 들어가지 않아 영구 빈칸이 될 수 있었다. 고정 셀의 행 전체를 포함하도록 범위를 계산한다.
2. 미리보기 A→B→A 왕복에서 모델의 준비 상태만 지우고 provider의 발행 상태는 남겼다. 캐시 이미지도 다시 준비 완료를 알리도록 크기 전환 시 함께 초기화한다. 추가 디코딩 없는 A→B→A→B를 실제 provider로 검증한다.
3. 창 너비·높이·셀 너비·DPR 변화 후에는 스크롤하지 않으면 새로 보인 사진이 요청되지 않았다. 재배치 뒤 focus를 갱신한다.
4. 밀도 변경 뒤 GridView의 `originY`가 -3978로 이동하는 실제 회귀를 찾았다. `contentY`를 곧바로 행 번호로 바꾸면 다른 사진을 요청했다. 가시 행·앵커·추가 조회 임계값을 `contentY - originY` 기준으로 통일하고 원점 변경 뒤에도 갱신한다. 깊게 스크롤한 뒤 크기를 네 번 왕복해 이전 맨 위 사진이 계속 보이는지 별도 검사한다.
5. 가시 항목 자체를 48개로 자르던 제한은 2560×1440·작게에서 98개 중 50개를 요청하지 않았다. 가시 항목은 모두 허용하고 **48은 lookahead 상한에만 적용**한다. 작업자 2개·이미지 캐시 240개·delegate `cacheBuffer` 한 셀·이탈한 대기 작업 취소는 유지한다. 실제 provider에서 가시 260개와 lookahead 48개가 모두 준비되고 캐시는 240개를 넘지 않는지 검사했다.

`tests/test_qt_gallery_qml.py`는 별도 offscreen/software 프로세스에서 **실제 GalleryPreview.qml**을 실행한다. 문자열 포함 여부가 아니라 실제 가시 delegate의 키와 provider 요청 키를 비교한다. 위 스크롤·부분 마지막 행·정적 높이/너비 확대·깊은 위치의 크기 왕복·2560×1440/3840×2160 뷰포트를 검사한다. 수정 전 위 스크롤과 정적 확대가 실패했고, 큰 화면의 48개 제한도 별도 실패를 재현했다. 이 검사는 Windows 입력을 주입하지 않으며 모니터의 끊김 여부를 검증하지 않는다.

### 2026-10-24 마우스 휠 가속 구현

- `luvbox/qt_wheel.py`의 `WheelInputFilter`는 **해당 Qt 창의 가시 갤러리 내부**에서 수정키·픽셀 델타·스크롤 phase가 없는 일반 마우스 각도 휠만 받는다. 원본 pixel/TouchPad 이벤트는 재생성·재전송하지 않고 `False`로 그대로 통과시킨다. 전역 입력 hook·Windows 입력 주입은 없다. 장치가 마우스로만 보고하는 레거시 터치패드까지 구별한다고 주장하지 않는다.
