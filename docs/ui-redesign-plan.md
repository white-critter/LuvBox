# Qt 화면과 구현 방향

LuvBox 1.1.9는 PySide6 + Qt Quick만 사용합니다. 저장·다운로드·기록·계정과 미디어 처리는 공용 Python 엔진을 사용합니다. 현재 검토·변경·측정 결과는 [검증 기록](verification.md), 1.1.3 구조 검토는 [종합 검토](comprehensive-review-20261024.md)에 기록합니다.

## 현재 구조

- `qt_app.py`가 저장 화면과 설정·계정·예약 컨트롤러를 연결합니다.
- `qt_download.py`와 `download_service.py`가 별도 다운로드 프로세스의 실행·중단·상태·저장 확인을 관리합니다.
- `qt_gallery.py`는 가시 항목을 우선 디코딩하고 작업자 수와 이미지 캐시를 제한합니다. 세대가 바뀐 요청은 결과를 발행하지 않습니다.
- `qt_library.py`는 기록 읽기와 파일 접근을 작업 스레드에서 수행합니다. 화면은 선택과 현재 작업의 세대를 확인한 결과만 사용합니다.
- `assets/qt`의 QML은 화면·저장 확인·미디어 재생을 담당합니다.
- `qt_browser_setup.py`는 Chrome·Edge·Firefox 선택과 설치 안내를 처리하고, `qt_accounts.py`는 실제 확장 단계·코드 대조·승인·취소와 인증 상태를 연결합니다. 최초 설치 도움말과 고급 토큰 입력은 접어 두며 재연결 때 설치 단계를 반복시키지 않습니다.

설정 변경은 저장 성공과 화면 반영을 연결하며, 실패한 설정으로 저장을 시작하지 않습니다. 계정·설정 쓰기는 Windows 프로세스 간 잠금과 원자적 파일 교체를 사용합니다. 토큰 입력란은 비밀 표시·닫을 때 지우기를 적용하고, 토큰·쿠키는 일반 설정·진행 이벤트·로그에 넣지 않습니다.

브라우저가 선택한 실제 일반 프로필을 안내하며 앱이 특정 프로필을 확인했다고 주장하지 않습니다. 확장 무응답은 8초 뒤 해결 안내를 보여 주는 기준이며 설치 실패를 확정하지 않습니다. 확장 1.1.0의 인증된 진행 응답과 저장 엔진의 Likes API 근거를 사용해 로컬 보관·브라우저 확인·목록 접근 확인·재연결 필요를 구분합니다.

## 표시와 성능

갤러리는 연속 스크롤과 세 가지 미리보기 크기를 사용합니다. 가시 행 전체를 요청하고 제한된 lookahead만 미리 읽습니다. 마우스 휠은 화면 안에서만 처리하며 터치패드의 pixel delta는 기본 Qt 입력으로 전달합니다. 스크롤·이미지 캐시·선택 상태는 각자의 생명주기를 유지합니다.

Qt 색상과 컨트롤은 QML에서 관리합니다. Pretendard와 앱 아이콘은 Qt의 글꼴·아이콘 API로 불러옵니다. 미디어를 새 UI 때문에 자동 이동하거나 이름 변경하지 않습니다.

## 검증

전체 회귀 검사는 `python -m unittest discover -s tests -v`입니다. `entry.py --self-test REPORT`는 생성한 미디어·임시 DB·가짜 연결 정보와 Qt 화면을 사용합니다. 빌드는 실제 EXE의 Qt 화면·다운로드 초기화 검사와 실행 파일 해시를 확인한 뒤 ZIP을 만듭니다.

## 별도 기능 범위

Qt 휴지통·복구 UI와 새 예약 생성 UI, 브라우저 확장의 스토어 배포는 별도 구현 대상입니다. 지원하지 않는 동작을 화면 버튼으로 노출하지 않습니다. 기존 예약은 상태 확인·해제·동일 시각의 현재 버전 연결을 지원합니다.

확장 없는 전용 로그인 창은 별도 타당성 확인 단계입니다. 합성 WebEngine 쿠키 수신 확인은 실제 X·추가 인증 호환성이나 제품 배포 성공을 뜻하지 않습니다. 현재 제품에는 WebEngine을 추가하지 않습니다.
