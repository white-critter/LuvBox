# 2026-10-24 보안·동시 저장 검토

검토와 회귀 검사는 격리한 임시 폴더, 합성 계정·쿠키, 생성한 이미지로 수행했습니다. 기존 사용자 로그인·미디어·기록 DB와 실제 X 요청은 사용하지 않았습니다.

## 확인한 문제와 수정

### 여러 앱 창의 계정·설정 변경 유실

암호화 세션은 임시 파일을 `os.replace`로 교체해 부분 기록을 방지하지만, 계정 목록을 읽고 수정하는 전체 구간에는 Python 스레드 잠금만 있었습니다. 두 앱 프로세스가 동시에 연결하면 먼저 읽은 계정 목록으로 다른 프로세스의 새 계정을 덮어쓸 수 있었습니다. 설정의 서로 다른 옵션 변경도 같은 형태로 유실될 수 있었습니다.

`luvbox/file_mutex.py`에 경로별 Windows named mutex를 추가하고, 계정 연결·선택·해제와 Qt 설정 갱신의 전체 읽기·수정·교체 구간에 적용했습니다. 잠금 이름에는 정규화한 경로의 SHA-256만 사용하며 토큰·경로 원문을 포함하지 않습니다. 기본 대기는 최대 5초이며, 예외·시간 초과에도 핸들을 닫습니다. 이전 소유자가 비정상 종료한 잠금은 Windows의 `WAIT_ABANDONED` 소유권을 받아 마지막 원자적 사본으로 진행합니다. 일반 읽기는 기존 원자적 파일 사본을 읽습니다.

이 보호는 Windows의 같은 로그인 세션에서 실행되는 앱 프로세스에 적용됩니다. 다른 플랫폼은 기존 스레드 잠금을 유지합니다.

`tests/test_file_mutex.py`는 독립 Windows 프로세스 두 개로 재현합니다. interprocess 잠금만 끈 대조군에서는 새 계정 하나와 다른 옵션 변경이 사라지고, 수정된 경로에서는 두 계정·두 옵션과 알 수 없는 설정 키가 모두 유지됩니다. 합성 세션 파일에 토큰 평문이 없는지도 확인합니다. 실제 DPAPI를 사용하되 테스트 전용 경로만 사용합니다.

### 의존성 보안 수정 반영

2026-10-24 OSV 질의 결과를 개별 공지의 영향 범위·철회 여부와 공식 배포 자료에 대조했습니다. 기존 Pillow 결과 41개는 모두 철회되지 않은 공지였지만, 전부 이 앱에서 실행 가능한 경로라고 계산하지 않았습니다.

| 의존성 | 이전 → 적용 | 앱과의 관계 |
| --- | --- | --- |
| Pillow | 12.3.0 → 13.0.0 | JPEG 축소 디코딩의 메모리 덮어쓰기와 APNG 크기 검사 전 대용량 할당은 허용된 JPEG·PNG 미리보기 경로에 해당합니다. EPS·TIFF 등 앱이 허용하지 않는 형식의 공지는 구분했습니다. |
| certifi | 2026.7.22 → 2026.10.19 | X 요청의 TLS 신뢰 저장소에서 손상된 emSign 중간 인증서 체인을 신뢰할 수 있는 오래된 루트를 제거한 버전으로 갱신했습니다. 빌드 Python의 별도 인증서 거부 정책도 유지합니다. |
| setuptools | 84.0.0 → 84.1.0 | Windows의 legacy wheel 설치 시 namespace 메타데이터로 설치 경로를 벗어나는 문제를 수정한 버전입니다. 앱에는 wheel 설치 기능이 없으므로 런타임 원격 공격으로 설명하지 않습니다. |

근거: [Pillow 13.0.0 변경·보안 안내](https://pillow.readthedocs.io/en/stable/releasenotes/13.0.0.html), [JPEG 축소 디코더 공지](https://github.com/python-pillow/Pillow/security/advisories/GHSA-8g5g-8vmr-9782), [APNG 사전 할당 공지](https://github.com/python-pillow/Pillow/security/advisories/GHSA-5xm2-6676-qcp9), [certifi 공지](https://github.com/certifi/python-certifi/security/advisories/GHSA-6q48-6c7w-9gw2), [setuptools 공지](https://github.com/pypa/setuptools/security/advisories/GHSA-xmj3-9gf7-h52w).

공식 PyPI의 Python 3.12 Windows wheel과 Python 요구 버전을 확인해 최소 수정 버전으로 고정했습니다. Pillow 13에서 제거한 API를 앱이 사용하는지 확인했으며, 현재 사용하는 `draft`, `thumbnail`, `Resampling`은 유지됩니다. 설치 후 `pip check`를 통과했고, 변경한 세 버전을 OSV에 다시 질의했을 때 반환된 공지는 각각 0개였습니다. 이는 해당 조회의 결과이며 모든 네이티브 구성요소의 취약점 부재를 뜻하지 않습니다.

`tests/test_image_security.py`는 작은 APNG의 큰 캔버스 선언이 미리보기에서 거부되는지 검사합니다. native 할당 함수를 별도로 감싸 큰 할당을 실행 전에 차단하므로, 오래된 의존성으로 되돌아가더라도 테스트가 실제 대용량 메모리를 할당하지 않습니다. 원본 바이트 보존도 확인합니다.

## 검토한 경계와 남은 범위

- 로그인 저장: DPAPI의 현재 Windows 사용자 범위, 암호문만 쓰는 임시 파일, 실패·취소 시 기존 세션 보존, 계정별 쿠키 선택.
- 브라우저 확장 연결: 일회성 capability, loopback Host·Origin 검사, 본문 상한, AES-GCM과 독립 HMAC, 확장 소유 승인 화면과 신뢰된 클릭, 전송 직전 계정 쿠키 재확인.
- 별도 브라우저 로그인: 새 임시 프로필, 사용자 프로필을 가로채는 정책 거부, 허용한 두 핸들의 파이프 CDP, 응답·명령 크기와 취소·시간 제한, 이번 시도의 프로세스와 프로필 정리.
- 요청 보호: API·미디어 요청 간격, 리다이렉트에도 적용되는 보호 함수, HTTP·GraphQL 요청 제한과 계정 잠금 감지, 서버의 재개 시각을 보존하는 cooldown.

위 앱 경계 검토에서는 새로운 고위험 인증 정보 유출 경로를 재현하지 못했습니다. 이는 취약점 부재의 보증이 아닙니다. 실제 X 계정 연결, 실제 확장 설치가 허용된 브라우저에서의 최종 사용자 승인, 네이티브 디코더 전체의 적대적 입력 평가는 이 오프라인 검토와 구분합니다. 파일 경로 승인·삭제와 미디어 자원 사용 검토는 이번 통합 검수의 해당 회귀 결과를 따릅니다.

보안·로그인 관련 기존 112개 검사 중 111개가 통과했고, 선택적 실제 Chromium 확장 통합 검사 1개는 실행 조건이 없어 생략됐습니다. 이후 추가한 mutex·이미지 보안 검사와 전체 통합 검사·빌드 결과는 [검증 기록](verification.md)에 기록합니다. 원시 의존성 조회 자료와 진단 로그는 `.test-output/comprehensive-review/`에 보관하며 배포 소스에 포함하지 않습니다.
