# 1.0.0 정식 버전 준비

검토·수정일: 2026-10-12. 기준은 `7740445`의 2.7.1(Codex)입니다. 2.7.1까지를 개발 버전으로 두고, 다른 사용자가 쓸 수 있는 첫 정식 버전 1.0.0을 만들었습니다. 이 문서는 저장소에만 두며 배포 ZIP에는 넣지 않습니다.

## 1. 2.7.1 변경 확인

Codex의 2.7.1을 검토했습니다. 수정이 필요한 문제는 없었습니다.

- 기록 합치기: 모든 계정을 임시 기록에서 준비·검증한 뒤 한 번에 반영합니다(중간 실패 시 기존 기록 유지). 상대 계정의 저장 폴더 사본까지 합칩니다. 합친 뒤 첫 빠른 저장은 전체 확인으로 바꿔 새 Like를 놓치지 않습니다(`quick_scan_merge_run`).
- 저장 폴더 사라짐: 현재 미디어 폴더에 과거 경로가 있었는지로 판단해, 다른 계정 기록만 합친 새 계정 폴더를 오인하지 않습니다. 저장 작업이 잠금을 잡은 뒤 다시 확인하고, 이번 실행에서 사용자가 승인했을 때만 새 폴더를 만듭니다.
- 미리보기 캐시: 정리 주기 유지, 다른 프로세스의 정리 반영(세대 파일), 읽기 전용 조회, 클라우드 전용 파일 읽지 않기.
- 2.7.1 그대로 전체 회귀 **760개 중 757개 통과, 3개 생략**.

보완 1건: 미리보기 캐시의 링크 검사가 드라이브 루트까지 모든 상위 폴더를 확인해, AppData를 정션으로 다른 드라이브에 옮긴 PC에서는 미리보기가 조용히 꺼졌습니다. 기록 저장소처럼 앱 데이터 폴더(`XlikeSaver`)까지만 확인합니다. Codex의 캐시 폴더·바로 위 폴더 정션 거부 검사는 그대로 통과합니다.

## 2. 사용자 친화적으로 다듬기

화면 전체를 캡처해(`tools/ui_qa.py`, 임시 데이터·네트워크 차단) 살폈습니다.

- 메인 화면
  - 저장 폴더 아래에 같은 경로를 한 번 더 보여 주던 줄을 없앴습니다. 작성자별·날짜별·계정별 폴더처럼 실제 위치가 다를 때만 “실제 저장 위치”로 보입니다.
  - 화면 아래에 항상 떠 있던 요청 한도 안내를 뺐습니다(필요할 때 오류 안내와 도움말에 나옴).
  - 사이드바 버전 표시를 “버전 1.0.0”으로 바꿨습니다.
- 도움말: 해야 할 일 위주로 다시 썼습니다. 내부 동작(빠른 확인이 멈추는 개수, 자동 전체 확인 조건, 암호화 방식, 비공식 API 등 용어)은 뺐고, ‘파일을 지웠을 때’·‘로그인이 안 될 때’를 더했습니다.
- 저장 설정: “직전 실행이 중단되거나 … 다음 한 번은 전체를 확인합니다”를 빼고, 확인 방식 설명을 “지난번 이후 새로 누른 Like만 빠르게 받습니다”로 바꿨습니다.
- 기록 창
  - 머리의 ‘기록 위치’(내부 DB 경로 표시)를 ‘폴더 열기’로 바꿨습니다. 없는 폴더는 만들지 않고 안내합니다. 기록 보관 위치는 ‘파일 관리’ 아래 작은 버튼으로 옮기고 내부 파일 목록은 뺐습니다.
  - 삭제 기능이 없어진 뒤로 새 사용자에게는 의미 없는 ‘이전 삭제 기록’ 탭은 기록이 있을 때만 보입니다.
  - 아래 상태 줄의 “출처 기록 N개 · 작성자 기록 N개” 대신, 출처가 없는 예전 파일이 있을 때만 해야 할 일을 안내합니다.
  - ‘확인된 용량’을 ‘용량’으로, 크기 단위를 KiB·MiB에서 Windows 탐색기와 같은 KB·MB로 바꿨습니다.

## 3. 1.0.0 정리

- 버전을 1.0.0으로 정했습니다. 코드는 버전 순서를 비교하지 않으며(표시와 화면 이미지 캐시 이름에만 사용), 기록·설정 형식은 2.7.1과 같아 그대로 이어 씁니다. 예약 작업은 새 실행 파일로 바꿀지 처음 실행 때 묻습니다.
- README와 `docs/사용안내.txt`를 사용자용으로 다시 썼습니다(설치·처음 사용·자동 저장·지운 파일·여러 계정·자주 묻는 질문·주의). 개발 버전의 버전별 기록과 자세한 동작 설명은 `docs/development.md` 아래쪽으로 옮겼습니다.
- 배포 ZIP의 `source/docs`에는 사용 안내와 개발 안내만 넣습니다. 개발 중 검토 기록은 로컬 경로·계정 이름이 들어 있어 저장소에만 둡니다. 배포 감사에 검토 기록과 개인 경로·계정 이름이 ZIP에 없는지 확인을 더했습니다.

## 4. 이름과 아이콘: 러브박스(LuvBox)

- 사용자 요청으로 이름을 **러브박스(LuvBox)**로 바꿨습니다. 창 제목(“러브박스 (LuvBox) 1.0.0”), 사이드바(아이콘 + “러브박스”, “LuvBox · 나만의 미디어 보관함”), 도움말·확인창·기록 창 제목, 실행 파일·폴더·ZIP 이름(`LuvBox-1.0.0`), 새 사용자의 기본 저장 폴더(`사진\LuvBox`), CSV 기본 이름, 자동 저장 실패 알림, README·사용 안내를 바꿨습니다.
- 아이콘: 어두운 둥근 사각형 위의 분홍 하트 테두리로 단순하게 그렸습니다(`tools/draw_icon.py`). 16~256px 모두 모서리가 투명합니다.
- 이어 쓰기: 패키지 이름, 앱 데이터 폴더(`%LOCALAPPDATA%\XlikeSaver`), 저장 폴더의 `.xlikesaver` 사본, 기록 파일 이름, 로그인 정보 암호화 표시는 그대로입니다. 개발 버전에서 쓰던 기록·설정·로그인을 그대로 씁니다.
- 예약 작업: 새 이름은 ‘LuvBox 자동 저장’입니다. 예전 이름으로 등록된 작업도 찾아 “다른 실행 파일로 등록됨”으로 보여 주고, ‘예약 갱신’ 때 새 이름으로 등록하면서 예전 작업을 지웁니다(예약이 두 개 생기지 않음). ‘예약 끄기’는 두 이름을 모두 지웁니다.

## 검증

- 새 검사 6개: 실제 저장 위치 줄 표시 조건, 도움말에 내부 용어 없음, 기록 창 기본(크기 단위·빈 삭제 기록 탭 숨김·폴더 열기·없는 폴더 안 만듦), 출처 안내 조건, AppData 정션 PC의 미리보기, 예전 이름의 예약 작업 찾기·바꾸기·끄기.
- 화면 확인: 라이트·다크 테마의 메인 화면·도움말·기록 창·파일 관리·저장 설정을 캡처해 확인했습니다(임시 데이터, 네트워크 차단).
- 전체 회귀: **766개 중 763개 통과, 3개 생략**(309.3초). 생략은 Windows 링크 생성 권한 검사입니다. `git diff --check` 통과. 로그: `.test-output/v100-final-tests.log`.
- `build.ps1`로 `release/LuvBox-1.0.0` 폴더 빌드와 ZIP을 만들었습니다. 배포본 감사: ZIP CRC·SHA256, 소스 96개·앱 2,924개 파일 일치, 개인 설정·DB·쿠키 항목 0개, 개발 검토 기록·로컬 경로·계정 이름 0개. 한글 경로에 풀어 실행 파일 자체 점검 통과(버전 1.0.0, `frozen=true`, 새 아이콘 파일 확인). 로그: `.test-output/v100-build.log`, `.test-output/v100-release-audit.json`, `.test-output/v100-frozen-selftest.json`.

실제 X 계정에 요청하거나 사용자의 인증정보·설정·기록·미디어를 바꾸지 않았습니다.
