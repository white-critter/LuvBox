# 2.7.1 변경 검토와 안정화

검토일: 2026-10-12. 기준은 Claude Code가 만든 2.6.0·2.7.0이며, 배포된 `b121718`(2.7.0) 이후의 보완입니다.

## 검토 범위

기록 합치기·폴더 누락 대응·미리보기 캐시를 중심으로 다운로드, 로그인, GIF 변환, 기록·통계, 예약 실행, 패키징 코드를 검토했습니다. 일반 파일 삭제 기능은 계속 제공하지 않습니다. GIF 변환 성공 후 원본 MP4 정리와 GIF 성공 기록·외부 삭제·복원 동작은 유지합니다.

## 재현한 문제와 수정

- 정상 파일 기록을 합친 뒤 손상된 다운로드 archive를 만나면 오류가 나지만, 파일 기록과 합친 계정 표시가 이미 반영됐습니다. 선택한 여러 계정 중 뒤 계정이 실패할 때도 같은 문제가 있었습니다. 모든 변경을 임시 기록에서 준비·검증하고, 기존 기록 이전의 복구 가능한 공개 절차로 한 번에 반영합니다. 실패하면 기존 기록을 유지하며, 상대 계정의 기록과 미디어는 바꾸지 않습니다.
- 상대 계정의 이 PC 기록이 있으면 저장 폴더 사본에만 있는 최신 기록과 다운로드 완료 키가 빠졌습니다. 원본을 변경하지 않고 두 기록을 임시 사본에 합친 뒤 가져옵니다.
- 기록을 합친 뒤 빠른 저장은 상대 계정에서 가져온 완료 키를 연속으로 만나 새 Like를 방문하기 전에 멈출 수 있었습니다. 새 기록이나 완료 키를 합치면 다음 빠른 저장을 전체 확인으로 전환하며, 전체 확인이 정상 완료되면 다시 빠른 확인을 사용합니다. 기존 실행 통계는 바꾸지 않습니다.
- 계정별 폴더를 쓰는 새 계정이 다른 계정의 기록만 합치면, 아직 만들지 않은 자기 폴더를 사라진 폴더로 오인했습니다. 현재 미디어 폴더에 과거 저장된 경로가 있는지 확인해 판단합니다.
- 창이나 예약 실행이 폴더를 확인한 뒤 다운로드 worker가 시작하기 전에 폴더가 옮겨지면, 예전 위치에 빈 폴더를 다시 만들었습니다. worker가 잠금을 확보한 뒤 다시 확인하며, 사용자가 해당 실행에서 새 폴더 생성을 명시적으로 선택했을 때만 허용합니다. 이 선택은 설정이나 예약 실행에 저장하지 않습니다.
- 갤러리·미리보기에서 저장하는 캐시는 매번 DB를 열어 용량 정리 주기에 도달하지 않았습니다. 여러 호출 간에도 정리 주기를 유지하고, 캐시 DB를 외부에서 지웠을 때 같은 이미지 키도 다시 저장합니다.
- 다른 다운로드 프로세스가 오래된 미리보기를 정리한 뒤에도 화면의 메모리 캐시가 이전 키를 기억하고 재저장을 건너뛰었습니다. 정리 시 파일별 세대 표시를 바꿔 다른 프로세스에서도 필요한 키를 다시 저장합니다.
- 캐시 조회는 읽기 전용 SQLite 연결을 사용해 미리보기를 보면서 불필요한 DB 생성·수정을 하지 않습니다.
- 클라우드에만 있는 파일도 자동 갤러리·선택 미리보기가 원본을 읽었습니다. 이런 파일은 원본 디코딩을 건너뛰고 이미 저장한 작은 미리보기를 사용합니다. 캐시 폴더와 DB·보조 파일의 링크 경계도 확인합니다.
- 좁은 기록 창에서 사라진 파일 설명의 줄바꿈 폭이 창 전체 폭으로 늘어나 목록을 밀었습니다. 작은 미리보기 카드의 설명 폭을 유지합니다.

## 성능 판단

기존 기록 새로고침 개선을 유지합니다. 이번에는 자동 미리보기의 불필요한 클라우드 원본 읽기와 캐시 용량 정리가 누락되는 경로를 보완했습니다. 캐시 조회는 읽기 전용으로 바꿨습니다.

경로와 캐시 세대 확인에 파일 stat이 추가됩니다. 이미 저장한 키를 재사용할 때는 DB를 열거나 이미지를 다시 저장하지 않습니다. 용량 합산은 프로세스 첫 쓰기와 파일별 200회 주기에 수행하며, 매 이미지마다 전체 DB를 합산하지 않습니다. 이번 변경의 목적은 용량 관리와 원본 읽기 동작을 정확히 유지하는 것입니다.
