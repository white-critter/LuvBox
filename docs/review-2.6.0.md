# 2.6.0 사라진 파일 대비

검토·수정일: 2026-10-12. 기준은 `bc3f365`의 2.5.3입니다. 2.5.0부터 파일 삭제는 탐색기 등 프로그램 밖에서 합니다. 그 사용 방식에서 앱의 대비가 충분한지 확인하고, 사용자가 고른 네 가지를 만들었습니다.

## 확인한 것 (수정 전)

임시 폴더의 시험 기록으로 직접 재현했습니다.

- 이미 되던 것: 지운 파일은 새로고침 때 목록·통계에서 빠지고 ‘사라진 파일’에 모입니다. 평소 저장은 완료 기록 때문에 다시 받지 않습니다. 게시일·종류·작성자·파일명·저장일·트윗 본문이 남고 ‘트윗 열기’로 원본을 봅니다. 휴지통 복원이나 원래 자리로 되돌린 파일은 새로고침 때 다시 연결됩니다.
- 부족했던 것:
  1. 사라진 파일이 어떤 그림이었는지 볼 방법이 없었습니다. 트윗이 지워지거나 비공개되면 알 수 없었습니다.
  2. 저장 폴더를 통째로 옮기거나 이름을 바꾸면, 기록 창을 여는 순간 원래 자리에 빈 폴더를 새로 만들고 모든 파일을 ‘사라진 파일’로 표시했습니다(시험: 5개 모두). 되돌리면 복구되지만 그 사이 경고가 없어 ‘다시 받기’를 누르면 수천 개를 10초 간격으로 다시 받게 됩니다.
  3. 외장 드라이브가 빠져 있으면 “폴더 권한을 확인해 주세요”라는 일반 오류만 나왔습니다.
  4. 원래 위치는 기록에 있지만 화면에 없었고, 사라진 때는 기록하지 않았습니다.
  5. 숨기기는 페이지(최대 200개)마다 골라야 했습니다.
  6. 출처·작성자 기록 중에 파일이 사라지면 원래 위치 없이 경로만 지워져, 나중에 복원해도 다시 연결되지 않았습니다.

## 만든 것

### 사라진 파일 미리보기

- 계정마다 이 PC의 앱 데이터에 작은 미리보기(150×112 WebP)를 둡니다. 저장 폴더에는 쓰지 않으므로 동기화 폴더에 올라가지 않습니다.
- 만드는 때: 저장할 때 새로 받은 파일마다, 라이브러리의 갤러리·작성자 사진·파일 미리보기가 그림을 읽을 때, 그리고 **파일 관리 → 작은 미리보기 저장**(이미 있는 파일 전체, 언제든 멈춤 가능).
- 클라우드에만 있는 파일(OneDrive ‘온라인 전용’ 등)은 읽으면 내려받게 되므로 건너뜁니다.
- 크기 측정(Windows 기본 사진 36장): 150×112 WebP 한 장 중앙값 1.1 KB, 최대 3.4 KB. X 그림은 더 복잡할 수 있어 1~4 KB로 안내합니다. 파일 1만 개 약 10~40 MB. 300 MB를 넘으면 오래된 것부터 지웁니다.
- 사진 한 장 만드는 데 약 0.02초, 동영상은 첫 장면을 뽑느라 0.1~0.3초입니다. 저장의 미디어 요청 간격(2초)에 비해 작습니다.
- 파일을 읽지 못하면 갤러리·파일 미리보기도 저장해 둔 미리보기를 보여 줍니다(아래 폴더 사라짐 상태에서 확인).

### 원래 위치·사라진 때·원래 폴더 열기

- 기록에 `missing_since`(사라진 것을 안 때) 열을 더했습니다. 새로고침이 있던 파일을 없음으로 바꿀 때 시각을 남기고, 복원돼 다시 연결되면 지웁니다. 이 버전 전에 사라진 파일은 ‘알 수 없음’입니다.
- ‘사라진 파일’ 오른쪽 카드에 미리보기, 사라진 것을 안 때, 원래 폴더를 보여 주고 **원래 폴더 열기**로 탐색기를 엽니다. 폴더가 없으면 안내만 합니다.
- 출처·작성자 기록 중에 파일이 사라져도 원래 위치와 시각을 남깁니다(6번 수정).

### 전체 선택

- **전체 N개 선택**은 모든 페이지의 사라진 파일을 고릅니다. 페이지를 넘겨도 유지되고, 표를 직접 클릭하면 이 페이지 선택으로 돌아갑니다. 새로고침·‘숨긴 파일도 보기’ 전환 때도 풀립니다.
- ‘다시 받지 않기’·‘숨김 해제’는 개수 제한이 없습니다. ‘다시 받기’는 기존대로 한 번에 2,000개까지이며, 넘으면 안내합니다.

### 저장 폴더 통째로 사라짐

- 기록에 파일이 있는데 저장 폴더가 없으면(옮김·이름 바꿈·드라이브 빠짐) 기록 창은 빈 폴더를 만들지 않고 경고를 보여 줍니다. 파일 재확인을 건너뛰어 사라진 것으로 처리하지 않고, 마지막 기록과 작은 미리보기를 보여 줍니다. 그동안 다시 받기와 출처·작성자 기록·GIF 변환·미리보기 저장은 쉽니다. 기록 사본도 쓰지 않습니다.
- 드라이브 자체가 없으면 “드라이브(E:)가 연결되어 있지 않습니다”로 안내합니다.
- 메인 화면에서 저장을 시작하면 “이 위치에 새 폴더를 만들고 저장할까요?”를 묻습니다(기본값 아니요). 드라이브가 없으면 시작하지 않습니다. 자동 저장은 만들지 않고 건너뛰어 실패로 알립니다.
- 사용자가 저장 폴더를 바꿀 때(기록 이전)는 지금처럼 새 폴더를 만듭니다.

## 검증

- 새 검사 19개(`tests/test_missing_safeguards.py`): 폴더 사라짐(재확인 생략·폴더를 만들지 않음·사본 미기록·드라이브 안내·예약 건너뜀·저장 시작 확인), 사라진 위치·시각과 복원 후 초기화, 출처 기록 중 사라진 파일, 미리보기 왕복·크기·정리·클라우드 전용 미열람·예외 없음, 갤러리·파일 미리보기의 저장·재사용, 저장 worker의 미리보기, 사라진 파일 카드·원래 폴더 열기, 모든 페이지 선택과 해제, 다시 받기 개수 안내, 폴더 사라짐 때 작업 차단, 미리보기 저장 작업.
- 실행 파일 자체 점검에 미리보기 저장·읽기를 더했습니다(WebP가 번들에 들어 있는지 확인).
- 화면 확인: 1366×800·1200×1000에서 ‘사라진 파일’ 카드와 버튼 줄, 폴더 사라짐 경고, 폴더가 없을 때 갤러리가 저장해 둔 미리보기를 보여 주는 것을 캡처로 확인했습니다.
- 사용자의 실제 앱 데이터에 미리보기 폴더가 생기지 않았음을 확인했습니다(검사는 임시 폴더만 씀).
- 처음 전체 회귀에서 미리보기를 ‘이미 저장함’으로 기억하는 표시가 계정 이름만으로 구분돼, 다른 위치의 같은 계정 미리보기를 건너뛰는 문제가 나왔습니다. 실제 미리보기 파일 경로로 구분하도록 고쳤습니다(미리보기 파일을 지운 경우에도 다시 저장됨).
- 수정 전 전체 회귀(2.5.3): **702개 중 699개 통과, 3개 생략**. 수정 후: **721개 중 718개 통과, 3개 생략**(419.4초). 생략은 Windows 링크 생성 권한 검사입니다. `git diff --check` 통과. 로그: `.test-output/v260-full-tests.log`.
- `build.ps1`로 `release/XlikeSaver-2.6.0` 폴더 빌드와 ZIP을 만들었습니다. 배포본 감사: ZIP CRC·SHA256, 소스 113개·앱 2,924개 파일 일치, 개인 설정·DB·쿠키 항목 0개. 한글 경로에 풀어 실행 파일 자체 점검 통과(버전 2.6.0, `frozen=true`, WebP 미리보기 저장·읽기 포함). 로그: `.test-output/v260-build.log`, `.test-output/v260-release-audit.json`, `.test-output/v260-frozen-selftest.json`.

실제 X 계정에 요청하거나 사용자의 인증정보·설정·기록·미디어를 바꾸지 않았습니다.
